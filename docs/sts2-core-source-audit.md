# STS2 规则源码审计索引

本文件记录 `sts2/src` 中与游戏语义有关的源码阅读进度，并把观察映射到 `core-the-spire` / `base-spire` 的实现。`sts2/README-for-browsing.md` 说明该工程由本机数据恢复，不是开发者发布的原始源码。仓库当前有 3,405 个 C# 源文件和 26 个 GDScript 文件；这里按规则域审阅，不把表现层资源计作规则源码。

状态含义：**首轮已读**表示围绕当前切片读过关键实现和调用关系，不表示逐行审计了该域全部文件；**待扩展**表示已定位入口，后续扩展前需要继续追踪调用方、顺序和边界情况。

战斗内容 DSL 的作者模型与当前实现边界见 [`content-dsl.md`](content-dsl.md) 和 [`combat-dsl-design.md`](combat-dsl-design.md)。当前 88 个卡牌声明中有 85 张属于源码中的 87 张 Ironclad 卡池；34 种已注册怪物均由 `.spire` 内容编译。遇敌阵容仍由 JSON 配置。源码审计标出的其余原版怪物与未建模 AI 仍需继续导入和验证，不应以当前 roster 作为全量完成依据。

源码核验确认 Twig Slime Medium 的 `AddBranch(moveState, 2)` 绑定 `maxRepeats` 重载，因此 Pokey 最多连续两次；Sticky 使用 `CannotRepeat`。JSON 与测试现按该语义建模。还发现 Nibbit 的 Butt 伤害漏了 DeadlyEnemies 下 13 点，已补入数据并加测试。Nibbit 源码由 Encounter 明确设置 `IsAlone` / `IsFront`。当前 JSON 原型已改为每个遭遇声明初始动作索引映射；目标 DSL 的 `alone/front/back` 角色将在编译时专门化为该映射，不进入战斗运行态。

`Break`、`Breakthrough`、`Hemokinesis` 和 `Tremble` 的费用、稀有度、目标、基础/升级数值分别核对了 [`Break.cs`](../sts2/src/Core/Models/Cards/Break.cs)、[`Breakthrough.cs`](../sts2/src/Core/Models/Cards/Breakthrough.cs)、[`Hemokinesis.cs`](../sts2/src/Core/Models/Cards/Hemokinesis.cs) 与 [`Tremble.cs`](../sts2/src/Core/Models/Cards/Tremble.cs)。四张牌可由现有攻击、失血、施加 Power、AoE 和消耗原语组合表达；其战斗效果已进入 `ironclad-cards.spire` 并由运行测试验证。Ironclad 卡池现由卡牌 DSL 中的 `pools = [IroncladCardPool]` 明确声明，构建复合规则视图时汇总；稀有度不再决定卡池归属。对照原版 87 张成员名单后移除了误收录的 Clothesline；该名称不在当前恢复的 STS2 卡牌源码和卡池名单中。

下一组复用同一效果代数：[`BloodWall.cs`](../sts2/src/Core/Models/Cards/BloodWall.cs) 先失血再加格挡；[`Brand.cs`](../sts2/src/Core/Models/Cards/Brand.cs) 失血、选一张手牌消耗后获得力量；[`Cinder.cs`](../sts2/src/Core/Models/Cards/Cinder.cs) 攻击后随机消耗一张手牌；[`Taunt.cs`](../sts2/src/Core/Models/Cards/Taunt.cs) 加格挡并施加易伤。[`EvilEye.cs`](../sts2/src/Core/Models/Cards/EvilEye.cs) 与 [`ForgottenRitual.cs`](../sts2/src/Core/Models/Cards/ForgottenRitual.cs) 读取本回合是否消耗过玩家卡牌，[`PactsEnd.cs`](../sts2/src/Core/Models/Cards/PactsEnd.cs) 读取当前消耗堆是否至少有三张牌。效果 DSL 现可写 `if` 与这两种运行时谓词；战斗状态保存最小的本回合消耗摘要。测试核对真假分支、回合切换、选牌暂停与升级数值。

本轮核对 [`AshenStrike.cs`](../sts2/src/Core/Models/Cards/AshenStrike.cs) 与 [`Bully.cs`](../sts2/src/Core/Models/Cards/Bully.cs) 的 `CalculatedDamageVar`：分别是基础值 6 加每张消耗牌 3（升级 4）、基础值 4 加目标每层易伤 2（升级 3）。共享 `scaledAttack` 在结算时读取计数并走普通伤害管线。[`Dismantle.cs`](../sts2/src/Core/Models/Cards/Dismantle.cs) 对易伤目标攻击两次，否则一次；升级单次基础伤害从 8 到 10。[`NotYet.cs`](../sts2/src/Core/Models/Cards/NotYet.cs) 回复 10（升级 13）、消耗自身，声明 `CanBeGeneratedInCombat=false`。卡牌生成 DSL 尚未实现，这一标记目前保存在定义中供后续生成规则使用。

继续跟踪 [`Thrash.cs`](../sts2/src/Core/Models/Cards/Thrash.cs) 后确认，它选择手牌 Attack 时读取 `CalculatedDamage.Calculate(null)`，否则读取 `Damage.BaseValue` 或 `OstyDamage.BaseValue`，然后应用持有者侧的 `Hook.ModifyDamage` 并消耗该牌。因此伤害展示/效果 AST 不能代替源卡牌的规范动态变量：Bully 在 `null` 目标下贡献 4（不是对当前易伤目标重新计算后的值），Ashen Strike 与 Perfected Strike 使用各自的计算动态变量，Body Slam 使用当前格挡，Fiend Fire 使用每击 7/10 的 Damage 基值。DSL 现用 `damageVariable`、`damageValue` 和升级值字段独立描述该投影；Thrash 则通过共享读取逻辑消费它。

本轮继续核对 Ruby Raiders：[`AxeRubyRaider.cs`](../sts2/src/Core/Models/Monsters/AxeRubyRaider.cs)、[`AssassinRubyRaider.cs`](../sts2/src/Core/Models/Monsters/AssassinRubyRaider.cs)、[`BruteRubyRaider.cs`](../sts2/src/Core/Models/Monsters/BruteRubyRaider.cs)、[`CrossbowRubyRaider.cs`](../sts2/src/Core/Models/Monsters/CrossbowRubyRaider.cs) 与 [`TrackerRubyRaider.cs`](../sts2/src/Core/Models/Monsters/TrackerRubyRaider.cs)。五者 HP 与 Deadly/Tough 数值已导入 DSL；攻击、格挡、加力量、上脆弱和多段攻击使用共享效果。Tracker 所需 Frail 作为通用 Power 用 block gain multiplier 表达，倍率只作用于 powered block，时长在敌方回合结束递减。遇敌编队按源码从五者中无重复抽取三者。

[`Pyre.cs`](../sts2/src/Core/Models/Cards/Pyre.cs) 应用 1 层 Pyre Power，升级后 2 层；[`PyrePower.cs`](../sts2/src/Core/Models/Powers/PyrePower.cs) 每层增加 1 点最大能量。Power DSL 的 `maxEnergyPerStack` 提供共享规则，核心在下个玩家回合开始时据当前层数重置能量，战斗观察同时显示最大能量。测试确认出牌当回合不补充当前能量，并覆盖基础与升级版本。

[`Spite.cs`](../sts2/src/Core/Models/Cards/Spite.cs) 根据本回合玩家是否受到正数未格挡伤害选择攻击次数：普通情况攻击 5 点一次，失血后两次，升级后失血分支三次。共享 `playerLostHpThisTurn()` 谓词由玩家 HP 损失事件更新，在下一回合自然失效；战斗测试覆盖普通、失血、升级和回合重置分支。Bloodletting 通过 `CreatureCmd.Damage` 造成不可格挡伤害；该命令在结算后写入 `DamageReceivedEntry`，因此直接失血也满足此条件。

[`Dominate.cs`](../sts2/src/Core/Models/Cards/Dominate.cs) 先给目标 1（升级 2）层易伤，再按目标当前总易伤层数给玩家力量；[`MoltenFist.cs`](../sts2/src/Core/Models/Cards/MoltenFist.cs) 攻击 10（升级 14）并消耗自身，若目标存活且已有易伤则将其当前层数再施加一次。两者由共享 `applyScaledPower` 和现有条件效果表示，测试核对结算顺序及击杀后不再施加 Power。[`Conflagration.cs`](../sts2/src/Core/Models/Cards/Conflagration.cs) 对所有敌人造成 2 点伤害共 4 次（升级 5 次），由 `repeat` 加 AoE 攻击表示；多敌伤害和命中次数已有验证。逐目标的原版多击事件顺序尚需进一步差分。

## 已知实现限制

- 当前战斗内核是用于验证边界的首版切片，未达到原版战斗等价。特定角色遗物、反应式 Hook、多人协作、完整卡牌区域规则、敌人意图选择、Ascension 配置和伤害类型都待实现。
- `base-spire` 中现有状态/效果 primitive 是内核测试语义，不代表可直接无误迁移所有原版机制。
- 目前 `RandomStreams` 复现 RNG 算法与确定性命名流基础，但尚未复现原版全部种子派生、RNG 分类、玩家槽种子和存档计数器语义。
- `Runs.cs` / `ActRoomContent.cs` 提供通用整局流转、可嵌套房间栈、配置驱动的事件/遭遇队列及选择视图；房间进入时会保存随机 enemy slot 结果，`CombatEnvironment.StartCurrentEncounterForRun` 使用已选敌阵容，从 run 牌组及共享 `shuffle` 流构造战斗，`RunEnvironment.CompleteCombat` 将终局生命回写并完成当前战斗房间。RunEffect `enterRunCombat` 可从事件页压入指定 encounter，结束时按定义恢复原事件页面，或结束父事件回到地图；`gainRunRelic` 可将已注册遗物加入运行库存。测试覆盖两种战斗转场、遗物授予和通过整局遭遇选择启动战斗。事件选项和 RunEffect DSL 支持基础资源及最大生命变化、单牌选择升级/移除，并提供注册式 `ICustomRunEffectHandler` 通过受限命令扩展 run 效果；尚未实现原版全量池数据、事件动态条件与完整效果、运行内容可用性筛选、RNG 逐调用差分或完整怪物初始化。
- 当前完整性范围是单人玩法到胜负、快照内全部原版内容默认全解锁；账号级元进度、多人、UI/音画和平台服务排除。
