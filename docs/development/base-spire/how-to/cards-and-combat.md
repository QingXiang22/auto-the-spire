# 开发卡牌与共享战斗机制

文档类型：操作指南（How-to）。适用于卡牌、附着、战斗资源、格挡／伤害／死亡和回合规则。纯 DSL 开发包已有完整单人铁甲战士定义所需的出牌／牌区、显式选敌与手牌选择、X 费、自动出牌、生成、伤害与 Power 修正、永久牌组及战斗副本；准确签名见[铁甲战士共享操作](../../../design/mod-the-spire/ironclad-dsl/shared-operations.md)。原版随机流、获得修正、附着、正常初态和完整 Run 仍需恢复。以下按任务选择现有操作或恢复方法；不存在可直接调用的旧 `card` 声明或 C# Effect API。

先读[准确操作](../reference/operations.md)确认边界，再到 cards/catalog 定位具体源类。需求与判断意图参考[卡牌原语契约](../../../design/mod-the-spire/card-primitives/spec.md)及[主清单的共享机制](../../../review/tofix/README.md#env-t06)，这些旧契约中的接口名不自动成为新 DSL 接口。

## 恢复费用、目标与出牌

1. 在 cards/schema 明确卡定义与卡实例、普通／升级状态、Owner、费用来源、目标域、各牌区和作用域。永久牌组卡与战斗副本使用可追踪映射，不能共用一份可变定义。
2. 在 cards/rules 描述合法动作：实际手牌成员、拥有者、可支付资源、所需目标及禁用状态。公开候选从相同守卫与候选声明产生；AI 或 Host 不另算可打条件。
3. 将支付、快照 X 值、离开手牌／进入打出区、实际效果、history、结果牌区及终局收尾按源顺序实现为完整流程。每张卡只配置费用、目标和效果组合。
4. 对无目标、单目标、多目标／多张选择分别定义类型和取消／空选语义。选择暂停时保存显式局部上下文，续接不重复支付和发钩子；目标死亡后的处理按源裁定。

验收至少能区分：资源不足拒绝无副作用、X 费在支付前捕获、合法候选与真实提交一致、最后一击的剩余效果和出牌收尾仍完成。不能仅让一个减 HP 过程代表完整出牌。

## 定义普通／升级和关键词

将共享字段、变体差异与展开规则写入卡牌契约。新模型需要明确字段继承／整体替换和空块含义；旧 `base/0.0.2 common/normal/upgraded` 是迁移依据，不可直接塞进 core/0.3 冒充已支持语法。升级对实例的费用、变量、附着与已有成长如何保留，分别定义。

状态、诅咒、无色和生成牌按来源组保留身份与资格，不因不进普通池而省略。retain／ethereal／innate／exhaust、自动打出和回合末手牌规则各依赖明确生命周期。普通牌配置优先调用共享模板，特殊牌也不新增 C# 按 ID 分派。

验收普通／升级实际差异及关键词时点，覆盖手动与自动路径的适用差别；同一机制不逐牌重跑整套战斗。自动出牌复用 AutoPlayCard，普通抽牌仍经 DrawOne；Hellraiser 只对实际抽到的 Strike 标签牌触发，不能把任意生成入手都当作抽牌。

## 处理牌区、复制和附着

已迁移定义的 `CardDefinition` 会生成 `<名称>.Obtain` 开发动作与同名过程，例如 `Strike.Obtain`；它调用 `ObtainPermanentCard`，把独立实例放入公开的 `RunDeck` 并发 `CardObtained`。当前只允许存活玩家在房间外、战斗外获得；不生成随机奖励，也不代表原版获得修正已恢复。干净初态也可用 `Ironclad.Initialize` 一次建立源起始牌组和遗物，见[角色初态契约](../../../design/mod-the-spire/character-combat/ironclad-start.md)。

一旦建立永久牌组，后续 `BeginDevelopmentCombat` 调用 `BuildCombatDeck`：清理旧非永久牌，按永久顺序复制到 DrawPile，保留普通／升级及费用等已有字段，隐藏的 `PermanentSource` 指向具体来源实例。不会把战斗升级反写到 RunDeck；临时生成、消耗和 Power 牌不会混入下一场。显式初始化 Ironclad 后，开战追加开发流初始洗牌，回合自动抽五张并处理首回合 Innate；其他机制探针仍用公开 `Draw` 显式抽牌。原版洗牌算法及流未恢复。营火消费者见[房间指南](run-and-rooms.md)，准确边界见[永久牌组与锻造契约](../../../design/mod-the-spire/permanent-deck-smith/spec.md)。

先分别定义移动、获得、生成、复制、变换、升级和移除的完整行为。移动必须维护原集合、目标容量、身份及事件；复制要规定永久 ID、成长、费用修改、附着、临时标记的保留／清除。不能把 `create Card` 当作任意复制操作。

附魔／负面附着与动态关键词放实例层，定义来源、层数、替换和寿命，消费统一选择／升级／变换接缝。验证两张同定义牌不串状态、离场和跨战寿命、复制／升级后的保留及失败不留下悬空引用。Sown 等历史源行为在[实例附着合同](../../../review/tofix/README.md#env-t06)查其原判断点，不恢复旧 C# 装配。

## 恢复资源、伤害与死亡

在 combat/schema 定义权威 HP／最大 HP／Block／Energy 等状态，区分 Run 持久资源与战斗资源。共享获得／支付操作拥有上限、资格、来源和事件；内容不能直接加字段绕过它们。

伤害契约先说明来源、类型、目标、每击计算、加性／乘性修正、格挡吸收、实际失血、Fatal、死亡防止、死亡与胜负判断。多段伤害的每击顺序、批次监听和目标失效不能合并成末端总扣血。当前 GainUnpoweredBlock 只覆盖无加成格挡，不替代普通格挡修正。

验证至少一个带实际 Power／遗物参与者的修正案例、多击中的死亡、最后目标死亡后余效、不可支付及零值边界。返回实际结果供后续效果消费，避免内容再从 HP 差猜测来源。

## 恢复回合与角色资源消费者

将战斗开始、玩家回合开始、抽牌、行动、回合末手牌处理、敌方行动、持续状态衰减和战斗结束写成显式流程。Power、遗物、敌人与卡牌钩子订阅同一事件，不在多个领域重复发出。

星星／Forge／球／宠物／Poison／Doom 等依所属领域建立共享状态和操作，再由卡牌消费。召唤／复活等仍按主清单暂停条件执行，不能因为新增卡牌而自行解除。用至少两个回合／两场战斗区分一次性初始化与逐次触发，长期资源只在约定边界写回一次。

交付时按[机制迁移](migrate-mechanism.md)更新契约、操作参考、消费者与实际见证，再按[验证指南](verify-and-debug.md)检查受影响范围。
