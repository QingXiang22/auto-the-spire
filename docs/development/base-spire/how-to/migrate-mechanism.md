# 迁移一个完整共享机制

文档类型：操作指南（How-to）。用于恢复纯 DSL 尚缺的共享玩法，或发现现有模板不能完整表达某内容。先在[主清单](../../../review/tofix/README.md)确认授权与主要归属，不从旧记录自动恢复暂停项。

## 1. 写清行为而不是先写语法

在对应领域现有 spec 中补充一份机制契约。没有合适位置时才建立领域契约，并从本手册链接。至少明确触发、前置条件、输入／目标、权威状态及寿命、成功状态变化、事件／随机顺序、失败／空集合／取消／重复、公开结果和未支持部分。

以一个能区分错误实现的例子固定顺序。例如重洗机制要求先转移并完成 shuffle，再发 AfterShuffle，所有监听完成后抽下一张；只验证最终加了 6 点抓不住时序错误。规则依据包括匹配源版本／方法和必要旧检查，不以两个复用同一算法的实现相等证明独立等价。

## 2. 检查依赖与语言表达

先查[真实操作参考](../reference/operations.md)和[领域依赖](../reference/domains.md)。可复用的是完整操作，而非相似字段名；例如 GainUnpoweredBlock 不含普通格挡修正，创建 Card 不等于从永久牌组获得或复制牌。

用最小 `.spire` 验证既有类型、控制流、选择、事件与模板能否组合。如果通用 DSL 缺原语，保存最小输入、预期／实际和受阻案例，按核心维护权限补通用能力；游戏效果继续写 DSL。不要将领域效果塞到 Engine、Host 或 C# SDK 组包器。

## 3. 建状态、过程与事件

schema 放实体字段／集合／事件，rules 放过程、模板与订阅，内容来源组只放受限 use。显式传 owner、card、source、target 等上下文，不能依赖全局“当前对象”。

把生命周期作为一个完整操作实现：验证资格、变更权威状态、维护集合／引用、发事件和清理，按契约保持顺序。局内状态保存在 Engine，不在共享定义、C# 字典或脚本全局保存。集合删除、销毁或暂停恢复时，验证引用仍指向正确实例。

## 4. 用真实消费者接线

先交付一个有源依据的内容消费者或明确的教学探针，证明共享机制实际被调用；只存在 DSL 声明不算完成。通过索引加载、公开观察与合法候选接线，同一 scope 不能声称具备尚缺依赖。

恢复正常流程时让实际操作产生状态，不能注入已完成结果、固定随机答案或清场跳过。受控初态可用于边界判别，报告中与正常 Run 分列。

## 5. 按契约验证并维护资料

选择能区分该机制错误的最小案例：顺序、目标／实例隔离、触发次数、零／满／空边界、暂停续接、非法提交无副作用、隐藏信息、随机消费及长期写回。复用同机制已有检查，不按每件内容复制全部组合。

先实际解析／加载／执行，再验证受影响公开路径和必要独立比较。依据[冻结检查清单](../../../review/records/2026-10-18/base-dsl-check-disposition.json)恢复原判断意图，保留原严格 suite 分母与失败门槛。更新共享操作参考与对应指南后交付；首个机制成功不能关闭完整领域。
