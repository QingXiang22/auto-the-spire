# 核心接口与兼容要求

本文规定当前通用内核的职责和行为。工程版本见 [Core.TheSpire.csproj](../../core-the-spire/Core.TheSpire/Core.TheSpire.csproj)，文本版本与语义见[作者参考](../reference/dsl/README.md)。修改语言、执行或投影语义时同步更新标识、消费者与相关检查；历史版本及其检查结果查 Git／PR／CI。

## 1. 固定的结构与接口职责

作者 DSL 和 EnginePackageBuilder 共用类型化 IR、RuleSetBuilder 链接器及唯一 Session 调度器。通用能力包括类型/字段/枚举、实例、集合/关系/作用域、查询、动作及其有限候选、过程、事件/订阅、暂停续接、终局、随机、数值、观察与窄调试。

宿主可使用 EngineDslCompiler.Compile/LoadFiles、EnginePackageBuilder、RuleSetBuilder 及 Session.Start/LegalActions/Submit/Answer/Step/Observe。现有开发者 State/RNG 访问保留；该基线不新增限权 facade，也不新增自动游戏推进器。正式对外标识/协议由 net 处理。

游戏包声明卡牌、角色、资源、回合、伤害、死亡、牌区、胜负和游戏特殊随机策略。core 只执行所声明的程序；例如终局前应执行的游戏余效由游戏包安排，内核不自动补完结算。

## 2. 执行、选择和故障约定

| 能力 | 固定行为 |
| --- | --- |
| 初始化 | 按 RuleSet 链接包顺序、每包启动登记顺序执行；文本 start 列表和模板展开后的收集顺序即登记顺序。一个入口完成后才进入下一个 |
| 初始化暂停 | 同一调度栈保留启动游标；合法回答后完成当前入口再执行剩余入口，不重放已完成程序。同级待执行入口不占嵌套调用深度 |
| 过程与事件 | 过程按声明指令顺序执行；事件监听器按 Priority 升序、再按 DeclarationOrder 执行，监听器完成后继续发出者 |
| 决策 | 请求固定本次实体候选/范围并绑定 StateVersion、RequestId；合法回答从暂停后续接；非法/过期回答被拒绝，不消费待请求 |
| 枚举决策 | 结果槽必须声明具体非空 Enum 类型，参数槽和局部槽都可用。默认范围是 0..成员数-1；显式 min/max 为闭区间，必须完全处于成员域内，可缩小合法范围 |
| 枚举错误 | 不支持 Binding/未定型的枚举结果槽，链接时拒绝；规则给出越界/倒置范围，在发布请求前故障；回答超出请求范围时拒绝并保留请求 |
| 确认 | Confirm 只接受 Flag=true；false 在续接前拒绝，保留原请求、状态和 RNG。Bool 仍允许真假两种回答 |
| 终局 | terminal 指令立即停止 Session，后续程序、监听器和初始化入口均不再执行；不会自动排空游戏余效 |
| 故障 | 一条状态指令按原子单位执行，失败指令的状态写入回退；此前成功指令可保留。Session 进入 Faulted，不自动重试或动作级回滚 |
| 预算 | 超过指令/调用/事件/绑定预算显式失败，不默默截断动作候选或规则执行 |

开发者直接访问 Session 不等于外部协议有回退权限。Start 仍是开发者入口，重复调用不被新权限层限制；正式宿主应每个新 Session 启动一次，重复执行初始化产生的变化由调用者负责。

实体引用选择、多选、整数、布尔、参与者、确认等保持基础语言的现有行为。实体多选检查重复/数量/候选，整数检查闭区间，参与者检查本 Session 成员。请求指定的参与者由 Host 分发；DecisionAnswer.Participant 不用于通用调用者认证。

## 3. 状态、组合与可见性约定

实体类型定义不创建实例；SessionState 持有每局实例、字段、作用域、成员与关系。不同 Session 独立，规则定义可共享。必需引用可在同一构造过程暂缺，稳定命令/暂停/终局/观察/哈希边界前须补齐；销毁与生命周期检查不允许留下非法引用。

集合按每个 Session 中的集合定义 ID 保存一份成员表，不因创建 Scope 自动复制。多持有者通过字段、关系与查询筛选建模；Scope 管生命周期。关系按 owner 实例保存连接。类型/集合查询采用现有确定顺序，Sort 显式定义排序，ForEach 使用入口快照。

模板在编译时展开；名称前缀与库词法绑定隔离各实例声明。参数和声明支持范围查对应语言参考，不能把旧语言的限制用于判断所有文本版本。独立模板实例仍在同一 Session，共享参与者与整局终局；组件的共享状态和游戏组合由包明确声明。

公开观察必须通过声明的 projection 和权限生成。隐藏实例的揭示不自动解除字段权限；已知标识/位置由包维护为当前知识事实。Observe 与 LegalActions 不消费随机数或写游戏状态；预算/求值错误仍可显式报故障。内部 State/RNG/debug 不是公开 AI 输入。

## 4. 确定性、数值与标识

RandomService 管命名流、消耗计数和快照；IRandomProfile 提供版本化算法与映射。整数区间、浮点转换、随机流布局和快照恢复按[随机作者参考](../reference/dsl/0.3/authoring-reference.md#随机流与-binary32)执行，禁止用不同随机实现冒用旧标识。

core 0.9.5 的开发诊断 `RandomCallDetails.SingleRawWord` 只在一次成功 API 调用确实消耗全局及当前流各一个原始随机字时，保留该次生成器实际返回的 UInt64。零消费、多字消费或跨流额外消费时为 null，不把末字当作完整抽样记录。诊断只记录已有抽样，不追加或重放随机；候选、游标、容量与历史快照约束保持，公开参与者投影不包含此字段。

`engine/ir@0.9` 增加通用 `hash64(text)`、`uint64Add(left,right)` 与 `seedStream64`：64 位无符号字以 Int 的有符号位型保存，哈希采用 UTF-8 XxHash64、种子 0，加法按模 2^64 回绕。普通 Int 运算及 `seedStream` 的非负检查保持；只有显式 64 位指令解释完整位型。`startsWith(text,prefix)` 使用 ordinal 比较，`substring(text,start)` 按 UTF-16 下标取到结尾，越界显式失败。这些纯表达式不消费随机，具体游戏派生公式仍属于 DSL。编译器与 SDK 生成相同 IR；操作与参数进入规则标识，公开目录和回放须按新引擎标识重建，wire 值仍使用原有 Int 编码。

规则、编译器、执行语义、包内容及随机配置共同决定兼容性。行为改变后重建包与相关回放，旧包或旧输入不自动续接新版本。数值精度、乘法次序和取整位置属于规则语义，不通过重录预期值掩盖变化。公开协议不提供 rollback／load／fork；开发者调试能力不产生外部回退权限。
