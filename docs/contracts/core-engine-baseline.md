本文定义 2026-10-05 冻结的通用内核范围、执行行为和迁移要求。维护 core 时，先按下表确认语言与运行版本，再核对涉及的契约；下游任务状态见[唯一清单](../review/tofix/README.md)。

用户授权完成通用契约收口后冻结 core，开发重心转向 mod/base、net 与环境工具。本文定义冻结范围、行为与迁移；不承诺支持所有卡牌游戏、不声明完整原版内容或训练环境已经验收。Git 提交范围、独立检出验证与下游验收约束见 [Git 冻结交接](core-git-checkpoint.md)；完整工作区的实施与状态只看 [唯一清单](../review/tofix/README.md)。

## 1. 固定的结构与接口职责

2026-10-18用户授权的DSL-RNG-RESTORE-01已将活动运行身份迁移为engine/ir@0.5、Core.TheSpire 0.5.0；上表保留冻结时点。新增随机DSL接口、显式种子快照及vanilla布尔映射修正见[当前作者参考](../dsl/core/0.3/authoring-reference.md#随机流与-binary32)。旧0.4包及回放需要重建／分身份保存，不能冒名续接；其他冻结职责继续适用。

作者 DSL 和 EnginePackageBuilder 共用类型化 IR、RuleSetBuilder 链接器及唯一 Session 调度器。通用能力包括类型/字段/枚举、实例、集合/关系/作用域、查询、动作及其有限候选、过程、事件/订阅、暂停续接、终局、随机、数值、观察与窄调试。

宿主可使用 EngineDslCompiler.Compile/LoadFiles、EnginePackageBuilder、RuleSetBuilder 及 Session.Start/LegalActions/Submit/Answer/Step/Observe。现有开发者 State/RNG 访问保留；冻结不新增限权 facade，也不新增自动游戏推进器。正式对外身份/协议由 net 处理。

游戏包声明卡牌、角色、资源、回合、伤害、死亡、牌区、胜负和游戏特殊随机策略。core 只执行所声明的程序；例如终局前应执行的游戏余效由游戏包安排，内核不自动补完结算。

## 2. 执行、选择和故障契约

| 能力 | 固定行为 |
| --- | --- |
| 初始化 | 按 RuleSet 链接包顺序、每包启动登记顺序执行；文本 start 列表和模板展开后的收集顺序即登记顺序。一个入口完成后才进入下一个 |
| 初始化暂停 | 同一调度栈保留启动游标；合法回答后完成当前入口再执行剩余入口，不重放已完成程序。同级待执行入口不占嵌套调用深度 |
| 过程与事件 | 过程按声明指令顺序执行；事件监听器按 Priority 升序、再按 DeclarationOrder 执行，监听器完成后继续发出者 |
| 决策 | 请求冻结本次实体候选/范围并绑定 StateVersion、RequestId；合法回答从暂停后续接；非法/过期回答被拒绝，不消费待请求 |
| 枚举决策 | 结果槽必须声明具体非空 Enum 类型，参数槽和局部槽都可用。默认范围是 0..成员数-1；显式 min/max 为闭区间，必须完全处于成员域内，可缩小合法范围 |
| 枚举错误 | 不支持 Binding/未定型的枚举结果槽，链接时拒绝；规则给出越界/倒置范围，在发布请求前故障；回答超出请求范围时拒绝并保留请求 |
| 终局 | terminal 指令立即停止 Session，后续程序、监听器和初始化入口均不再执行；不会自动排空游戏余效 |
| 故障 | 一条状态指令按原子单位执行，失败指令的状态写入回退；此前成功指令可保留。Session 进入 Faulted，不自动重试或动作级回滚 |
| 预算 | 超过指令/调用/事件/绑定预算显式失败，不默默截断动作候选或规则执行 |

开发者直接访问 Session 不等于外部协议有回退权限。Start 仍是开发者入口，重复调用不被新权限层限制；正式宿主应每个新 Session 启动一次，重复执行初始化产生的变化由调用者负责。

实体引用选择、多选、整数、布尔、参与者、确认等保持基础语言的现有行为。实体多选检查重复/数量/候选，整数检查闭区间，参与者检查本 Session 成员。请求指定的参与者由 Host 分发；DecisionAnswer.Participant 不用于通用调用者认证。

## 3. 状态、组合与可见性契约

实体类型定义不创建实例；SessionState 持有每局实例、字段、作用域、成员与关系。不同 Session 独立，规则定义可共享。必需引用可在同一构造过程暂缺，稳定命令/暂停/终局/观察/哈希边界前须补齐；销毁与生命周期检查不允许留下非法引用。

集合按每个 Session 中的集合定义 ID 保存一份成员表，不因创建 Scope 自动复制。多持有者通过字段、关系与查询筛选建模；Scope 管生命周期。关系按 owner 实例保存连接。类型/集合查询采用现有确定顺序，Sort 显式定义排序，ForEach 使用入口快照。

core/0.2 模板在编译时展开；名称前缀与库词法绑定隔离各实例声明。模板参数支持 Int/Bool/String/Fixed/List(Int) 字面量，body 支持核心声明与嵌套 use；不支持类型/字段/行为引用注入和游戏扩展声明模板化。独立模板实例仍在同一 Session，共享参与者与整局终局；组件的共享状态和游戏组合由包明确声明。

公开观察必须通过声明的 projection 和权限生成。隐藏实例的揭示不自动解除字段权限；已知身份/位置由包维护为当前知识事实。Observe 与 LegalActions 不消费随机数或写游戏状态；预算/求值错误仍可显式报故障。内部 State/RNG/debug 不是公开 AI 输入。

## 4. 确定性、数值与身份

RandomService 管命名流、消耗计数和快照；IRandomProfile 提供版本化算法/映射。SampleInt 的范围为 [min,max)，SamplePick 保留查询顺序，不隐式按实例 ID 排序。游戏种子解析、布流与特殊算法归游戏包。

Int 使用 Int64；默认 NumericProfile 为 checked 整数及 decimal 运算后 2 位 ToEven 量化，可由规则包构建指定已支持 Profile。字段 Fixed 的 scale 元数据不独立替换 RuleSet 的算术 Profile；写入按类型/范围检查，不另按字段 scale 量化。溢出、除零明确失败；不隐式使用 binary64。

构建后的声明、IR 子集合、包与链接表按现有冻结规则只读发布。规则身份绑定运行版本、包顺序/内容、编译器/扩展/后端与数值语义；文件路径、源码位置和 debug 配置不改变语义身份。StateHash 仅覆盖状态，State.Clone/Random.Capture 不是完整暂停 Session 的恢复资产。

扩展声明通过 IEngineDslExtension 生成共同 IR，不能替换核心声明或另造调度器。Compile 接受显式依赖/扩展，不读磁盘；LoadFiles 递归处理 core/0.2 相对 imports、循环/缺失/同包冲突检查，当前没有扩展注册参数。

## 5. 从 engine/ir@0.2 迁移

本批启动顺序与枚举域行为变化，因此使用 engine/ir@0.3。IR 节点/公开 C# 签名和 core/0.1、core/0.2 文本写法保留；语言支持不意味着旧执行资产继续等价。

1. 用当前编译器/SDK 重新构建规则包。明确声明 engine/ir@0.2 的旧包被拒绝链接，不直接修改旧包标签冒充新产物。
2. 多 start 按登记顺序重新核对依赖，去掉以旧反序为前提的安排。单个 Setup 内 Call 顺序不变。
3. 枚举决策结果改为具体 Enum 槽位；需要子集时填写域内 min/max。旧 Binding 结果不再接受。
4. 重建规则/会话身份及验证产物。旧快照、轨迹和训练资产留原身份；不自动 resume 或混入新基线。模型迁移/重新评估由 AI 侧另定，不在本次启动训练。

## 6. 冻结后的开发规则

冻结表示明确版本的接口与语义进入维护，不表示禁止修复。内部整理和性能改动应保持公开行为与身份；兼容扩展须保留已有语法/API和行为，并发布能力/身份说明。会改变同规则、配置与种子下的结果、候选、权限、顺序或数值的修改，需要新的语义版本和迁移说明，不能沿用 engine/ir@0.3 身份。

下一阶段默认由 mod/base 编写规则库/内容/整局，net 完成公开接口，tools 负责严格对拍。核心需求须明确通用原语或组合缺口及最小复现，先由负责人判断；不能把具体游戏结算搬进 core，也不能自行启动新的核心架构迭代。

Lua、完整 Session 恢复、动态容器实例、高级模板连接、编辑器插件和完整游戏库不属于本次冻结交付；后续是否开发由独立需求决定，不作为已完成承诺。验收及源码摘要见 [本批关闭报告](../review/archived/core-contract-freeze-2026-10-05.md)。
