## 5. 架构一览（接手需建立的心智模型）

```
作者层    EnginePackageBuilder  ──►  EnginePackage.Freeze（冻结 + 内容哈希）
            │  声明符号（类型/集合/关系/作用域/枚举/事件/终结结果/compute/投影/过程/动作）
            │  IR 构造（表达式/查询/指令），每个声明引用变成"包内引用槽"
            ▼
链接层    RuleSetBuilder.Add(pkg…).Build()
            │  依赖校验 → winner 收集（覆盖/扩展）→ 密集 id → 字段布局
            │  → 两遍类型 id（允许前向引用）→ resolution 表 → IrTypeChecker 定义检查
            │  → 身份哈希（冻结表 + resolution 表 + 后端/数值档位/包版本）
            ▼
运行层    Session(ruleSet, seed, roles)
            │  SessionState（作用域/实例/集合/关系，按指令原子回滚，StateHash）
            │  RandomService（具名流）   Scheduler（激活栈：调用帧 + 事件派发帧）
            │  动作：LegalActions 枚举候选域与 guard 成立的参数元组 → Submit → 校验 → 执行
```

## 6. 关键设计决策与契约变化（**接手必读**）

按影响面排序，前 8 条会直接影响别人写的内容或接口：

1. **限定名声明 = 绝对 ID**。`EntityType("other-package:Thing")` 表示"声明另一个包的声明"；这是 `Overrides` / `Extends` 的唯一表达方式。声明**种类之间是独立命名空间**（同名 `EntityType` 与 `Action` 不冲突）。
2. **动作的 guard / 候选查询 / choices 只能读取"有域"的参数**（有候选查询或有声明 choices）。理由是可用性必须在不依赖宿主参数时可判定。链接期强制。**B-05 的作者前端最容易撞这条。**
3. **动作只能有一个候选域**（`CandidateParameter`/`CandidateQuery` 单数）。多域动作（先选牌再选目标）目前只能把第二个域放进过程体做 `RequestDecision`。这是**待决策缺口 A**。
4. **执行原子性与故障分级**：验证失败（guard 不成立、候选不符、角色不符、过期/重复应答）**不改变状态、不消耗 RNG、不终止会话**；**执行期故障**回滚该指令（若消耗随机则连 RNG 一起回滚）并把会话置为 `Faulted`，此后拒绝任何命令。预算是显式配置，超限是明确故障，不做静默截断。
5. **身份 = 冻结表 + resolution 表 + 后端描述 + 数值档位 + 包版本 + 依赖/覆盖/扩展**（本轮补齐，见审计报告）。`IrDumper` 遇到未登记节点会**抛故障**而不是静默 dump。
6. **随机服务显式声明算法与档位**（`xoshiro256ss/splitmix64@1` + `rejection-uniform@1`），未实现的组合直接拒绝；身份含算法/档位/种子指纹。**不宣称与原版种子等价**，`Engine/` 内没有 `System.Random`。原版有界取整映射需要 B 批带源码证据另行声明。
7. **值类型与槽**：`IrScope.Temp()` 默认是"绑定槽"（`FieldTypeSchema.Any()`），`AnyRef()` 表示"接受任意实体引用"。**所有 `Local()`/`Temp()` 必须在 `Body(...)` 之前调用**（Body 会冻结局部槽表）。
8. **字段可见性三档**：`Public` / `OwnerPrivate`（只有拥有者字段等于观看者的实例可见）/ `Hidden`（只有投影显式开启才可见）。集合的 `IdentityVisible`/`SizeVisible`/`OrderVisible` 独立；**只经"身份不可见"区域可达的实例不进入投影**（防泄露隐藏区域成员与顺序）。
9. 新增/补齐的 IR 原语：`expr.scope`（原有但**签名表漏登记**，任何用 `FrameScopeExpr` 的包以前都链不上）、`expr.entityScope`（实例所在作用域）、`expr.collectionIndex`（绝对位置，非成员返回 -1）。
10. **作用域父类型按"作用域类型"解析**（原先按实体类型解析，任何带 `Parent` 的作用域类型都会失败），父链环检测为 `DependencyCycle`；**数值溢出/除零全部转成结构化故障**（原先泄漏裸 `OverflowException`）。
11. **compute 资产必须声明 `BackendId`/`SourcePath`/`SourceHash`/`Entry`**，输入输出数量不得超过 `ComputeLimits`；没有安装后端时是明确的 `Unsupported` 故障。
12. 决策应答绑定 `StateVersion`，过期即 `StaleDecision` 且不推进；暂停点在指令之后，续接不重放已结算效果。
13. 事件：emit 时**快照**监听表（按 priority、声明序），反应过程的参数按位置从 payload 绑定，`ScopePayloadField` 决定反应的作用域；`Recheck` 在真正运行前求值；事件深度/调用深度超限是明确故障。
14. 规则集构建**两遍分配类型 id**，字段可以引用同包中后声明的类型（互递归类型可声明）。

## 7. 写内容包的要点（给下一个做 base-spire 的人）

**必读**：本文第 6 节 + `mod-the-spire/base-spire/BaseSpire/Composition/CombatSlicePackage.cs`（照抄结构最快）。

**最小骨架**
```csharp
var package = new EnginePackageBuilder("my-package", "1.0.0");
var scope   = package.ScopeType("Battle");                       // 根作用域类型：只能在根作用域创建
var thing   = package.EntityType("Thing");
var size    = thing.AddField("Size", FieldTypeSchema.Int(0, 7)); // 越界写入是运行时故障
var items   = package.Collection("Items", thing); items.Capacity = 2;
var pinged  = package.Event("Pinged"); pinged.AddPayload("Item", FieldTypeSchema.RefTo(thing));
var done    = package.TerminalResult("Done"); done.AddField("Turn", FieldTypeSchema.Int(0, 9999));

var setup = package.Procedure("Setup");
var created = setup.Local("created", FieldTypeSchema.Binding());  // ← 必须在 Body 之前
setup.Body(setup.CreateEntity(thing, new FrameScopeExpr(), created, new[]{ (size, setup.Const(1L)) }, items));
package.OnSessionStart(setup.Symbol);

var act = package.Action("Touch");
var itemParam = act.Parameter("Item", FieldTypeSchema.RefTo(thing));
var body = package.ActionBody(act);
body.Role("player");
body.Candidates("Item", body.Collection(items));                  // ← 唯一的候选域
body.Requires(body.GreaterOrEqual(body.Field(body.Param(itemParam.DeclarationIndex), size), body.Const(1L)));
body.Body(body.SetField(body.Param(itemParam.DeclarationIndex), size, body.Const(0L)));
```
**五个必须知道的约束**：① 局部槽在 `Body()` 前分配完；② 过程/动作互相引用要先声明符号；③ guard/候选/choices 只能读有域参数；④ 一个动作一个候选域；⑤ 运行长度用 `Repeat`（迭代不占调用深度），没有 `while`/`break`。

**包内"已知信息"的写法**：引擎**不推断**玩家知道什么。需要"已知牌及其绝对位置"时，由包维护一个公开事实实体（切片里的 `KnownCard{CardId,Pile,Position}`，位置用 `CollectionIndex(pile, card)` 现算），并在抽牌/洗牌时撤销。

## 11. 方法笔记（给下一个接手的人，省点弯路）

- **验收要按判据反推反例，而不是看测试是否通过。** 本轮 K-01 的"修改相关语义改变身份"就是靠一个**26 维语义突变探针**（每个变体只改一个维度、都要求能链接成功、断言哈希必须变化）才暴露 3 个缺陷的。这个探针留在 `Engine.Tests/EngineChecks.cs` 的 `IdentityFor(...)`，扩语义维度时往 `IdentityMutation` 里加一项即可。
- **写夹具往往会先抓出内核的错。** 本轮 `ForEach` 快照问题、回合开始历史未清空、易伤倍率，都是切片跑起来才暴露的；这也是 K-07"通用性验收"的真实价值。
- **并行构建会互相锁 `obj/bin`。** 同一 solution 的 .NET 工作要串行；纯 Python/文档任务可以并行。
- **委派子任务要切得很小。** 本轮 5 次委派里 3 次因为读大文档耗尽上下文、**没有留下任何产物**（P-01 前两次、base-spire 静态清点）；成功的两次都是"只读一个文件 / 只写两个文件"的窄任务。给子任务写清"快没上下文时优先保证哪个产物完整"。
- **测试场景必须标出来。** 切片里每回合抽 5 张、起始牌组不洗牌、怪物取范围最小生命，都在代码注释与清单里标为测试场景值，不冒充原版行为。
