## 2. 对新评审的决策

| 意见 | 评估与决策 | 归属 |
| --- | --- | --- |
| core 审计 A：一个候选域意味着只能一个动作参数 | 有效限制是只能有一个动态候选查询；现有 Domains/Bindings 还支持多个声明 choices 参数，不应称为只有一个参数。多个动态实体域确实未支持，但首批可以用既有动作加中途选择表达，不是 N-01 的阻塞项。以后出现必须一次提交的牌/目标组合时再立多域任务 | K-04/B-05；N-02 映射合法 Bindings 与 PendingDecision，不自行补规则 |
| core 审计 B：N-03 不确定结果查询/停止需要会话快照 | 不采纳。活跃请求账本、完成响应缓存、uncertain 状态与停止控制即可满足首版；进程丢失按协议处理，不回退重试。种子+动作重放从新局开始，也不要求中途恢复。内部快照是后续独立能力，不作为 N-03/B-07 必需前置，更不成为 NoSL 公开 fork/load | N-03；无需现在扩展 core 快照 |

### 分派顺序与目录协调

1. **先交 R-LEGACY 接管**：只审阅/验证中断前的既有改动，保留其他工作；有不符合约定的部分再局部修正。它不承担 Engine、机器 schema 或 AI/net 实现。
2. **协议 agent：R-P01**。负责共用资产、Python 参考 codec/检查，完成之后才解除 A-01/N-01 前置。AI 端 contracts 可以复用这些代码，不再平行造一份 Python codec。能力内部恢复可以明确 false，不需额外实现快照。
3. **core agent：R-CORE**。与纯 Python 规范工作独立，但 .NET 构建须由用户协调串行。当前不扩多个动态候选查询，不实现 Session 整体快照或 Lua；如专项反例暴露缺陷，限定修复 Engine 内对应通用能力。
4. **AI agent：A-01～A-05；net agent：N-01**。待 R-P01 验收后分别启动，N-01 不等 AI 全部完成。AI 只做确定性当前观察输入层，不安装训练框架；C# contracts 复核同一规范字节/摘要/正反例。
5. **net agent：N-02～N-05**。选既有受控 slice，把运行时的合法 Bindings 展开为当前候选；暂停时只映射 PendingDecision 的合法应答，不把普通动作同时暴露为可执行。公开投影直接消费当前已知位置，不维护第二套历史缓存；没有领域事实就向 base-spire 提具体请求。
6. **联调 agent：J-01**。A-05/N-05就绪后，按开工清单第8节串起随机合法概率、执行与公开轨迹。分别报告规则、投影、编码、请求失败路径证据，不能用一次跑完代替所有检查。
7. **base-spire agent：R-DAMAGE** 在更广规则/内容迁移前做来源差分；与 N/AI 首批可独立规划，不把受控 slice 扩大成完整原版。K-08、完整内容迁移、训练尚不派入首批。

用户负责指定 agent、工作区及编译时段；本规划不自动创建或通知执行 agent。shared schema/fixtures 由协议 agent 维护，其他模块如发现契约分歧给出反例交规划者裁定，不擅自放宽验证或改单方协议。
