## 4. 跨端对照结果

### 4.1 期望值确实来自 Python 参考实现（同源复核，只读）

在写检查体之前，先用 `tools/contract-check` 的**唯一一份**规范实现（**不是**重跑生成器覆盖证据）
独立复算了清单里的每一条期望值：

- 对 222 条 `documents` 条目：用 `check_contracts.resolve_document` + `wire_canonical.canonical_text/digest_bytes`
  重算 `sha256`/`byte_length`/规范文本 → **checked=223、missing=0、mismatch=0**（含 1 条 `raw_documents` 的 `parse_error.rule_id`）。
- 对 golden 向量：`check_contracts.run_golden(golden)` → **51/51 通过**；`cross-end-cases.json` 的
  `golden_case_count=51` 与实际一致。

**结论：清单与 Python 参考实现零漂移，没有需要「以 Python 侧为准」去覆盖的差异**。
（这也意味着 `cross-end-canonical.json` 里的期望值可以被当作 Python 侧的地面真值使用。）

### 4.2 C# 侧复算结果

- **L2 规范字节**：141 个用例的全部 217 个角色文档 + 5 个基文档 = **222 个文档**，
  C# 逐字节复算的规范文本与 `sha256` 与 Python **完全一致**（151 条 ≤2048 字节的文档还额外做了
  规范文本逐字比较，71 条做了 120 字节前缀比较 + 字节长度比较）。
- **L1 结构判定**：141 个用例的 schema 驱动判定与 Python **逐条文本一致**

### 4.3 为使对照不放宽，我在 C# 侧做的一处对齐（记录）

L1 的期望值是**完整诊断文本**（不是 rule id），而 C# `LiteSchema` 原来的消息文本用了

## 7. 残余风险

1. **角色 → `$defs` 映射是镜像的**：`CrossEndChecks.DocRolePointers` 手工镜像
   `check_contracts.py:56 DOC_ROLES`。新增角色会**响亮失败**（`CheckManifest` 断言每个角色都有映射），
   但镜像本身不会自动同步（缓解方案见前置 2）。
2. **L1 检查是对文本敏感的**：它按 Python 的 f-string/`repr` 逐字比较（这是为了不放宽到 rule id）。
   Python 侧消息格式一旦变化，会表现为**检查失败**（响亮，不是静默）。`PythonRepr.String` 只近似了
   Python `repr` 的引号/控制字符规则；`WireEquals` 是类型敏感的，未镜像 Python `==` 的
   `True == 1` 跨类型语义。当前夹具不触发这两点，但属于已知近似。
3. **检查体依赖参考资产在位**：测试在运行时只读 `tools/contract-check/fixtures/**` 与
   `docs/contracts/net/0.1/*.schema.json`（以及本项目 `fixtures/*.json`）。这些路径由
   `AutoTheSpire.sln` 向上定位仓库根后拼出；缺失时报
   `缺少跨端对照资产: <绝对路径>` 并**非零退出**，不会静默跳过。
4. **漂移是响亮的，但有前提**：清单是生成物。若 Python 夹具被改动而清单未重新生成，
   canonical 摘要比较会失败（C# 按新输入算出的摘要 ≠ 陈旧期望值）。
   反之，若有人**手改清单**去迁就 C#，则 §4.1 的同源复核需要重跑才能发现——
   建议把该复核对拍成脚本（前置 6）。
5. **`DocumentComposer` 是镜像实现**：只支持清单里出现过的 6 个叠加操作与 `doc:` 引用。
   Python 侧新增操作符（如 `$merge`）不会被 C# 识别 → 解析出的文档与 Python 不同 →
   canonical 摘要失败（响亮），但错误信息会指向摘要而非「未知操作符」。
6. **L4 seed 检查的用例筛选是手写谓词**（`rule_ids ⊆ {I-66, I-76}`）。若夹具新增
   「能力不支持但 seed 本身合法」之外的 seed 用例并带上新规则号，筛选可能误纳/漏纳。
7. **未提交**：`net-the-spire/` 与 `docs/review/` 在 git 中仍是未跟踪目录，`AutoTheSpire.sln` 的改动
   与其他人的未提交改动混在同一文件里（我的部分是纯追加）。共享 Git 状态由任务负责人协调。
