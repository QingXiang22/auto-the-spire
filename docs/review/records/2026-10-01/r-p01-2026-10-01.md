## 5. `coverage schema` 打印项的性质（任务 3 的回答）

**入口当前打印 `coverage schema: present`，派单中的 `ABSENT` 观测已过期。**

- 该资产**被真实消费、且非空洞**（逐条实测）：
  - 基线覆盖表 `coverage-demo.json` 通过；`status: "made_up"` → 枚举拒绝；删除 required `evidence_ref` → 缺失必需键拒绝；额外顶层键 → `additionalProperties=false` 拒绝。

## 7. 残余风险

1. **`invariants.json` 缺失 + `I-87` 重载**（§6）：影响"带稳定 ID 的跨结构检查清单"这一交付物定义，以及未来 C# 端按 ID 对齐时的歧义。重编号会牵动 fixtures 的 `rule_ids` 期望，须同批修改。
2. **行号漂移**（§4）：`invariants.md` 旧条目出处与当前 protocol.md 不一致，按行号检索会错位约 +2～+10 行。本轮只保证新条目准确。
3. **未覆盖反例**：`I-69`/`I-71`/`I-73` 的跨结构语义（覆盖表引用闭合、结构名与快照一致性）无独立反例；`Limits` 零值许可无用例。
4. **schema 仅覆盖结构、不覆盖数值上界**这一分工已被用例锁定，但同类"模式够宽、语义更窄"的字段（如 `NonEmptyString` 承载的命名空间 ID/`semantic_version` 词法，U-09）仍无校验，属开放项。
5. 本轮**未运行 `dotnet`**（遵守硬性边界），因此 C# 侧、构建、双端一致性均未验证；210/210 只是 Python 参考检查的证据，不是跨端验收。
6. 崩溃用例的成因提示：fixtures 的叠加 DSL（`$set`/`$append`/`$insert`）在路径失效时**抛异常而不是记一条失败**，会把单个用例的错误升级为整个入口失败（正是基线 69/69 假象的来源）。建议后续给 `resolve_document` 加越界诊断（本轮未改，避免扩大范围）。
