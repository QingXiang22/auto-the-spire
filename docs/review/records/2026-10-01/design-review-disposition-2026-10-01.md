## 1. 总体判断

报告对两端协议漂移、规范化摘要、能力结构、请求/会话身份、候选采样和持久化的担忧大体可取。但部分理由把“应写得更明确”扩大为“原设计没有定义”，或者把一种可选设计提升为唯一解。尤其 F-02/F-03/F-09/F-10 的部分结论不能照单采纳。

当前工作区已包含 protocol/encoder 的“修订 2”、[contract-artifacts.md](../../../design/net-the-spire/contract-artifacts.md)、V-15/V-16 及同步追踪表。它们不是本次新写的改动；本次对照它们判断剩余问题。原报告的行号和“7/20 不一致”等结果属于评审时点，不自动适用于当前版本。

公开信息的产生和可知性仍归提供方；AI 只验证结构并编码当前快照。不能因为引入 schema，就要求 AI 判断卡牌规则或重放历史。观察充分性审计检查的是“已知且影响决策的事实有没有丢失”，不是要求不同隐藏状态都能被 AI 区分。

## 2. F-01 至 F-08：契约与首阶段

| 项目 | 原判断的评估 | 当前状态与处理意见 |
| --- | --- | --- |
| F-01 机器规范与双端 codec | 采纳共用规范、摘要/decimal 算法和通用约束；不采纳“独立 fixtures 必然只是自证”或“两端 DTO 必须代码生成”的强推论。人工独立预期及变换反例也是有效验证 | contract-artifacts 第 1/2 节已提出 schema+不变量+正反例，允许生成或对照实现；实际资产和双端验证仍未交付，不应宣称协议冻结 |
| F-02 无序数组与样例 | 采纳提供方排序和身份来源审计；不采纳“C/A/B/D/E 已证明就是内部牌序”。公开示例没有给出内部真值，任意输入顺序本身也不违反旧版消费者规范化契约 | 修订已按公开引用排序。两位置和三位置可以是独立验收案例，不必所有案例共享同一 fixture；不应为统一文案删除对额外离散位置的覆盖 |
| F-03 绝对位置与基数 | 采纳集中列出不变量和 wire→tensor 对应；“原文未说明绝对位置/结构整数”说得过重，旧编码稿已写顶部0、底部 total_count−1，协议已写安全 JSON 整数 | 当前 protocol 第 2 节已明确 `[0,total_count)`、JSON integer 和四条不变量。位置不用 visible_members 长度作边界；这是澄清而不是另选位置语义 |
| F-04 牌堆类型与互斥作用域 | 采纳必须可区分牌堆用途及互斥作用域；独立 pile_types 不是逻辑上的唯一方案，实体种类/具名类别也能承载 | 当前已选择 pile_types→唯一 kind_id，scope 字段用于互斥检查；AI 可使用实体种类编码，无需再增加第二套重复牌堆类别 embedding |
| F-05 需求追踪 | 采纳维护单一映射和补任务追踪；场景子集不对称不全等于行为矛盾，但会给实施者造成分歧 | 当前 20 行已一致，A-01/A-04/A-05/N-05 在矩阵中有归属；原“7行”结论已失效。共同验收是映射权威，spec 是同步视图 |
| F-06 能力、条件及终局原因 | 采纳能力/限制结构和终局声明。消费端不能靠 schema 证明条件值真的可知，也不应实现第二套规则谓词来验证提供方 | 修订加入 terminal_reasons、条件机制检查 ID 和能力结构设计。结构检查与提供方机制证据分开；完整机器 schema 尚未交付 |
| F-07 机制到字段的映射 | 采纳明确产物、状态、责任和进入时序 | 当前 contract-artifacts 第 5 节规定来源清单→N-02补投影证据→N-05闭合；E1 不再要求尚未实现的 net 已经验证。实际所选切片和证据仍开放 |
| F-08 观察充分性 | 采纳 E2 前审计目标切片的公开事实。原文把 V-03 也仅归为“不泄漏”不准确，它还检查已知位置保留/失效；“所有决策相关状态不得合并”必须限定为公开可知事实 | 当前 V-15 补充来源/表示和成对公开差异检查；有限场景不证明完整 Markov 性，也不要求区分玩家无法获知的隐藏状态 |

## 3. F-09 至 F-16：版本、评估和运行

| 项目 | 原判断的评估 | 当前状态与处理意见 |
| --- | --- | --- |
| F-09 整目录身份与模型失效 | 不采纳“每次新增都必须从零重训”和“全部已训模型作废”。旧模型仍可用于冻结的旧 Gym；拒绝新旧身份混用不等于要求丢弃旧权重 | 当前继续 exact identity，登记新内容批次的评估/迁移成本。显式权重迁移或闭包子目录可后续设计；不能只看所需字段没变就证明新增规则/内容无影响 |
| F-10 同种子配对 | 不采纳“随机流逐次对齐才构成配对”。按同一初始场景/seed/重复编号匹配结果可以分析差值，后续轨迹不同不自动取消匹配；只是不保证方差降低 | training-design 已区分初始条件配对、固定动作重放和公共随机数。保留此修正，不为统计方法强制改游戏 RNG；实际实验还需冻结配对单位/种子分布 |
| F-11 会话 ID 域 | 采纳显式唯一域。端点+局部ID也可消歧，不必只有“全局字符串唯一”一条路 | 当前采用 worker 实例标识+局内编号，在客户端可见域不复用；实际生成与重启验证仍待实现 |
| F-12 候选顺序与采样 | 采纳：概率对齐不等于固定 RNG 下采样一致。不需要候选句柄跨快照稳定，需的是公开动作语义键和规范采样 | 当前规范化动作字段，排除 candidate_id 后排序、对齐概率及采样；V-11 增加采样检查。不得将规范行号当模型特征 |
| F-13 快照引用 | 采纳引用格式及保留期；旧文未说引用来自 RequestLedger，不能据此直接认定生命周期冲突 | 当前首版保存完整快照，可选 digest+relative_path 去重并随 episode 保留，不能指向临时账本。存储规模需测量，不预填成本数字 |
| F-14 DTO 依赖边 | 采纳纯 contracts 与活动 client 分离；Python/C# 各有语言对象不等于出现两份规范权威 | 当前 encoding/policy/client/data→contracts，contracts 无活动会话或规则依赖；共用规范约束和正反例 |
| F-15 确定性与恢复能力 | 采纳 seed+动作序列重放的显式承诺；不采纳把复制状态、暂停、序列化或 RNG 内部结构全都变成训练/真实接入的必需能力 | 当前 seed_action_replay 与内部/公开恢复能力分开，公开 restore/fork=false；重放仅在明确声明的后端验收，首版不依赖回退 |
| F-16 字段省略与不适用 | 采纳状态对照和 V-06 断言范围；两种表达不对称本身不是矛盾，不要求增加字段级 not_applicable | 当前省略只表示无声明，不能区分不适用/可选未提供；编码不创建缺失字段值行。absent 是描述，不是新增 knowledge_state 枚举 |

F-10 的方法学依据：[NIST 的配对观测说明](https://www.itl.nist.gov/div898/handbook/prc/section3/prc311.htm)以自然匹配的观测及其差值为分析单位，并没有逐次随机流一致的必要条件。把同一冻结初始条件作为本项目匹配单位是设计推断，不保证差值方差下降，更不意味着可以随意套用 t 检验；置信方法应适配结果类型、种子抽样与重复运行结构。

F-01 中 schema 的作用是固定字段、类型和额外属性规则；例如 [JSON Schema 的 object 规范说明](https://json-schema.org/understanding-json-schema/reference/object)区分 properties、required 和 additionalProperties。解析重复键、跨目录引用及真实可见性仍需在相应层检查，不应声称仅有 schema 就能证明两端或规则正确。

## 5. 对开工结论的修正

原报告第 3 节要求“先闭合 P1 再进 E0”，第 11 节又说“4项文档修订加批准即可开工”，但没有完整 schema/两端原型资产。在未区分讨论、结构资产、编码验证和真实后端之前，不能同时把这两种口径当一致的硬门槛；“半天到一天”也没有执行依据。

我的建议是保留 E0 独立性：A-01 前需要足够明确的单一公开规范及样例；E0 做 Python contracts/编码校验，跨语言 codec 一致性在 N-01/E1 对应关口完成。若维护者另选 C-01 先做两端最小原型，也可行，但这是增加首批前置工作量的工程选择，不是独立编码器技术上必须依赖 C#。

当前实施计划已经选择了“C-01 资产及最小双端原型通过后进入 E0”。本报告记录这一范围变化及替代建议，没有默默取消该前置条件或宣布已批准。实际机器资产和原型还没有交付；预算、奖励与真实后端不能被升级为 E0 前置门。

关于 normalization_tolerance：它属于未来概率推理，不是 A-01 当前观察/字典编码的前置参数。E0 需要的是 EncodingConfig 数值转换/误差策略；两类容差应在各自阶段决定，不因名字相近合并为一项批准条件。
