## 1. 交付内容

`ai_the_spire/data/`：

- `record.py`：`episode-record@1` —— `EpisodeRecord` / `TransitionRecord` / 结束分类 / 结构校验 / 记录摘要。
- `store.py`：`EpisodeStore` —— 落盘（`records/<episode_id>.json` + 追加式 `index.jsonl`）、按 id 读、
  派生索引重建、独立复核（`verify_all`）。

设计要点（逐条对应开工清单的交付与退出证据）：

| 要求 | 实现 |
| --- | --- |
| 版本化 | `record_format_version = "episode-record@1"`；读入时版本不符即拒绝 |
| transition | 每步含 `index`/`request_id`/`observation_id`/候选句柄/语义键/**实际行为概率**/结果分类/下一观测版本/张量摘要 |
| 公开快照存储 | **每条转移保存完整公开快照**（`snapshot`），不只存索引或摘要 |
| 实际行为概率 | 记录的是**真正执行**的那个动作的概率，并同时保存完整候选概率表（便于核对 μ 与 π 的差异） |
| 结束分类 | `terminal_win` / `terminal_loss` / `truncated` / `faulted` / `interrupted` 五类互斥；`outcome` 不是 win/loss 时**按故障记录**，不硬塞进胜负 |
| 身份 | 目录/规则集/后端/Gym/字典/Manifest/编码配置/张量布局/执行器/模型/种子 + `record_digest`；**不含时间戳** |
| 来源 | `provenance{runner, policy, executor_profile_id, entry, source}`：能说明这份数据是谁、用什么策略产生的 |
| 索引 | `index.jsonl` 逐行 `episode_id → path/record_digest/ending_class/steps/confirmed/unknown/identities_digest`；**由记录派生**，可重建比对 |
| 独立重读 + 验摘要/引用 + 重编码 | `EpisodeStore.read`（结构 + 摘要校验）与检查里的 `_reencode()`：只用记录内的目录与配置重建 Manifest 并逐条 `tensorize`，比对张量摘要；同时显式核对 `visible_members`/`known_positions` 的引用闭合 |
| 重复 request 不重复计样本 | `validate_document` 拒绝重复 `request_id`；`episode_id` 由内容派生，同一 id 二次写入被拒绝（不静默覆盖） |
| 未知结果不得补造 | `outcome == "unknown"` 的转移**必须** `next_observation_id == null` 且不得声称执行过候选；非终止类记录不得带 `terminal_result`，终止类必须带 |

产物目录由调用方给（测试用系统临时目录）：**不往源码树写日志或二进制**。D-04 会提供从配置启动的正式入口。

### 2.1 退出证据逐条对照

- **一个记录可独立重读、验摘要/引用并重编码** → `record/offline-reencode-matches`：在**不启动任何宿主**的
  情况下，从记录里重建 Manifest（5 个身份摘要逐字核对）并逐条重编码，张量摘要与记录一致；
  `record/digest-stable-across-read`、`record/index-*`、`record/store-verify-all-clean` 覆盖摘要与索引一致性。
- **重复 request 不重复计样本** → `dedup/duplicate-request-id-rejected`、`dedup/duplicate-episode-id-rejected`。
- **未知结果不会被补造为失败或下一状态** → `ending/unknown-must-not-fabricate-next-state`、
  `ending/unknown-must-not-claim-execution`、`ending/non-terminal-must-not-carry-terminal`、
  `ending/unknown-outcome-not-forced-into-winloss`。

另外覆盖了"记录被改动必须被发现"（`dedup/tampered-record-detected`）与"索引漂移必须被发现"
（`dedup/index-drift-detected`），因为"独立复核"的意义就在于不信任磁盘内容。

## 3. 未覆盖与边界

1. **`unknown` 结果在真实链路上还产生不出来**：同步后端不会返回 uncertain（见
   [h-03](h-03-2026-10-02.md) §1.4），因此"未知转移"目前只被**记录格式**覆盖（构造用例），
   不是真实 episode 的产物。真实产生它需要异步提供方或进程丢失场景。
2. **`interrupted` 分类尚无真实来源**：D-02 的 Collector 才能在进程丢失后产出中断局；D-01 只定义分类并
   拒绝把它混进终止。
3. **没有奖励/收益字段**：D-03 明确要求"原始事实与奖励分开"，奖励向量属训练设计（L-00/16.2 未定），
   本层刻意不发明奖励。
4. **未做数据划分**（训练/调参/最终评估 split）与偏移检查：属 **D-03**。
5. **未做限额与停止**（步数/局数/磁盘/内存/时间）：属 **D-02**。
6. 记录格式与 J-01 的联调轨迹 `j01-trace@1` 是两套东西；本格式**不再是**临时格式，但仍会随 D-03/D-04
   的数据划分与审计需要演进（演进必须升 `record_format_version` 并保留旧记录的读取路径，见 §1 的版本校验）。
