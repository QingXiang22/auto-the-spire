## 1. 来源

```
power RagePower {
  trigger = afterCardPlayed
  whenCardType = attack
  effect = gainBlock(1, perPowerStack=RagePower)
  removeAfterPlayerTurnEnd = true
}
```

卡 `Rage`（:3565）：`cost = 0`、给自己上 **3 层**（升级 **5 层**）。
引擎已有 `inst.destroyEntity`（`PackageBuilder.Destroy`），因此**不需要新原语**。

## 2. 【重要】修掉一个潜伏缺口：玩家侧的能力回合末行为从未执行

实现 `remove` 时发现：`ResolveOwnerTurnEnd` 只在**敌人回合末**被调用（唯一的调用点在 `endEnemyTurn` 里
逐个敌人调用）。也就是说：

- 玩家身上的 **Vulnerable/Weak/Shrink 时长从不递减**（来源要求自己回合末递减）；
- `owner-turn-end = remove`（"本回合有效的触发型能力"，正是 RagePower）**永远不会生效**。

本批在 `EndPlayerTurn` 里补上对**玩家自己**的调用，位置按来源放在**手牌的端末处置之后、敌人回合开始之前**。
这不是"为了一张卡写死"，而是把回合末语义补齐到两侧——因此也顺带让玩家侧时长语义与来源一致。

**回归结果**：切片 25 项既有 + 4 B-05b + 87 B-05c 检查**全部仍然通过**（`SkipNextTick` 的"施加当回合不减"语义
让原本就成立的行为没有位移），net **383/383**、旧后端 190、AI 503 也不回归。

## 3. 退出证据

| 判据 | 检查 |
| --- | --- |
| 语法/编译 | `trigger = after_card_played`、`when-card-type = Attack`、`owner-turn-end = remove` 都被解析；非法值（`AttackAttack`、`vanish`、`before_card_played`）分别以 `invalid_value` 拒绝 |
| 来源对照 | 能力来源行 33、卡来源行 3565、费用 0、两形态层数 3/5、触发效果 `gain-block-per-stack:1` |
| **牌类过滤** | 打出 Rage 自己（Power 类）**不**触发；打出**攻击** +3 格挡；打出**技能**只给技能自身的 5 点格挡（3 + 5 = 8，**没有**额外的触发）；再打一次攻击再 +3 |
| 升级形态 | 5 层 → 每次攻击 **+5** |
| **回合末整体移除** | 打出后 3 层 → 端末后**层数为 0**（不是减 1 层）；随后再打攻击**不再**给格挡 |
| 冻结文本 | 触发点、牌类过滤、回合末形态、两处来源行、两形态层数逐条一致 |
