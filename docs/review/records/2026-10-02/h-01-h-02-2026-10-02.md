## 1. 做了什么

### 1.1 引擎（core）：观看者授权揭示（K-06 契约扩展）

按设计 §8 的 2026-10-02 补充契约实现：包可声明**按观看者授权揭示的实例引用集合**，通用投影据此公开身份隐藏集合中该观看者获授权的成员子集，同时遵守字段权限。

新增声明（`Engine/Schema.cs`）：

```csharp
projection.Type(factType).OwnerField = "Viewer";   // 既有：所有权字段解析
projection.Reveal(factType, revealRelation);       // 新增：授权声明
```

语义与实现要点：

- **授权判据是包声明的 participant 字段**，不是全局布尔；`CollectRevealed` 逐个事实比较「该事实的 viewer 字段 == 本观看者」，其它观看者的事实不授权任何实例。因此不存在"一个全局 `Revealed` 对所有观看者放行"。
- **只放开身份隐藏，不放宽字段权限**：被揭示实例仍按 `Public`/`OwnerPrivate`/`Hidden` 逐字段判定。
- **`ProjectedCollection` 新增 `RevealedMembers`**，与既有 `Members` 分离。这样「完整成员」与「本观看者被授权识别的成员」不会混成同一个列表：`Members` 仍然只在 `IdentityVisible=true` 时非空（原有 V-02 防泄漏断言继续成立），授权子集单独表达。
- **授权子集按实例身份升序**，不沿用隐藏区的内部顺序（隐藏置换不改公开结果）。
- **引用闭合**：引用型字段指向本观看者无法识别的实例时**不发布该字段**；关系边的 owner 或 target 不可识别时**不发布该边**（此前这两处都会原样透传，是真实泄漏路径）。
- **进入规则身份**：`reveal` 声明写入投影的身份文本，改授权即改 identity。
- **链接期拒绝**：授权类型不在投影内 / 授权类型没有观看者字段 / 观看者字段不是 participant / 揭示目标类型不在投影内。

### 1.2 切片（base-spire）

- `KnownCard` 从「定义 ID 型事实」改为**真实实例引用 + 观看者 + 包维护的绝对位置**：
  `KnownCard{ Viewer(participant, owner-private), Card(ref→Card, owner-private), Pile(string, owner-private), Position(int, owner-private) }` + 关系 `KnownReveal(fact → card)`；不再有任何"从内容定义 ID 造实例"的路径。
- 清除/撤销事实时**同时清除授权边**（`ClearRelation`），避免留下指向已不可识别实例的引用。
- `RecordKnownTop` 增加 `Viewer` 参数（由出牌者实例的 `Owner` 字段取得），由包声明谁被授权。
- 每个牌区声明独立实体种类（`HandPile`/`DrawPileEntity`/`DiscardPileEntity`/`ExhaustPileEntity`/`InPlayPileEntity`），供协议 `pile_ref` 唯一匹配（protocol.md:83）；这些实体不承载玩法状态，`core` 未新增任何 STS 概念。

### 1.3 net 映射

- `PublishedPile` 从「固定 `pile_ref` 字面量」改为「`PileKindId` → 在本快照里解析唯一实体」；`kind_id` 即 `pile_type.kind_id`，与协议一一对应（同一 `kind_id` 声明两次直接 `I-07` 拒绝）。新增 `PositionSchema`。
- `visible_members` = 完整成员（身份可见时）∪ **授权揭示成员**，排序后去重；`members_complete` 仍严格等于引擎的 `IdentityVisible`。
- `known_positions` 由**包声明的事实实体**填入：`card_ref` 取真实实例、`position` 取包维护的位置；逐条校验 `I-27`（`0 ≤ position < total_count`）与 `I-29`（`card_ref ∈ visible_members`、每牌一个位置、每位置一张牌）。找不到事实字段、牌堆标记未声明对应 pile_type 时**拒绝**，不跳过、不补默认值。
- `KnownReveal` 关系**显式不发布**（授权边不是游戏事实，其公开表达就是 `known_positions`；发布成 relation 会把同一成员事实重复表达，违反 protocol.md:94）。
- 目录：`pile_types` 由 profile 导出（5 条，`kind_id` 唯一、成员种类非空）；`entity_ref` 的 `target_kind_ids` 与动作/终局字段的 required/optional 来自**显式声明**（`PlayCard.Card` 进 `required_fields`）。
- 旧具名缺口 `TODO-N02-PILE-ENTITY` / `TODO-N02-KNOWN-POSITION` / `TODO-N03-CATALOG-PILES` **已真正关闭**，检查由"TODO 存在"改为"TODO 不存在且行为成立"。

## 4. 实际行为范围（能声称什么）

- **引擎层（通用，不含 STS）**：观看者授权揭示、字段权限不放宽、隐藏置换不变、撤销失效、引用/关系边闭合、声明进入身份、4 条链接期拒绝 —— 由 13 条可判别检查覆盖（含两观看者、重复同定义实例、多个离散位置、撤销、隐藏置换反例）。
- **切片层**：头槌置顶后的**第一份**观察即可给出真实卡牌实例 + `Pile=draw` + `Position=0`，且该实例同时是 `entities` 成员与 `DrawPile.RevealedMembers` 成员；隐藏牌区其余成员与顺序不外泄；抽牌/洗牌/撤销三条路径各有检查。
- **net 层**：`pile_ref` 解析到实体且 `kind_id` 唯一匹配已声明 `pile_type`；`known_positions` 满足 I-27/I-29；`pile_types`/`target_kind_ids`/required 字段来自显式声明。
- **口径**：以上是**夹具/单元层**证据。**不声称 V-15 已成立**，也不声称真实模拟证据；逐场景证据类别标注属 N-05。

## 5. 未覆盖与残余风险

1. **公开实例 ID 使用内部创建计数器**（`PublicInstanceId = "e" + InstanceId.Value`）：`design.md:61` 要求内部 ID 的创建顺序若泄漏隐藏排列/预生成内容则须改用"公开出现顺序或另一可审计机制映射"。本切片下初始牌序是公开的固定起始卡组，影响有限；但**一般情形**下 id 会暴露会话内创建次序。**已登记为待裁定项**（`net-the-spire/coverage-n-02.md` §2/§3.6），本轮**未**擅自改动（改它会同时改变所有既有快照与 AI 侧夹具身份）。
2. **pile 的 `exclusive_group_id` 未声明**：引擎内部有成员互斥组，但协议要求互斥组带 `membership_scope_field_id`（牌堆实体上引用作用域实体的字段），而战斗作用域不是实体。已声明为能力边界，**不把内部互斥组冒充协议互斥组**。
3. **`H-01/H-02` 的 net 检查只覆盖本切片配置**：其它包/其它 profile 的同类映射未验证。
4. **未做变异测试**：H-01 的 13 条引擎检查未做"注入错误后必须失败"的变异探针（反例本身的判别力由构造方式保证：内部顺序≠身份顺序、Black 事实不得授权 White、撤销前后对比）。
5. **引擎未强制"公开字段不得指向不可识别实例"以外的引用一致性**：列表型引用字段（`FieldTypeKind.List`）未纳入 `IsIdentifiable` 检查（当前切片无列表字段）。缺口已记录。
6. **`PlayedThisTurn` / `Monsters` / `Known` / `KnownReveal` 仍为显式跳过**：属已登记的能力边界（无公开有序流程语义、无 group owner 实体、事实已逐个发布、授权边不作公开关系），**不作为 V-15 成立**。
