## 1. 选卡方式：先看来源能不能表达

`Entrench`（:1752）的来源只有一句 `play = { gainBlockFromCurrentBlock = { } }`，外加**两形态费用不同**（2 → 1）：

| 来源事实 | 本批新增的能力 |
| --- | --- |
| `gainBlockFromCurrentBlock` = 获得"当前格挡"那么多的格挡 | **`amount-source = block-count`**（与既有 `hand-count`/`discard-count`/`draw-count` 同形；降级为读玩家 `Block` 字段） |
| 普通 `cost = 2`、升级 `cost = 1` | **变体键 `cost`**：变体块里的 `cost` 覆盖卡牌级 `cost`，范围 0..9，越界不截断 |

**冻结数据一字未改**：`SliceCard` 的升级费用做成**可空属性**（`int? UpgradedCost` + `EffectiveUpgradedCost`），
所以切片那 4 张卡的构造调用不需要改；只有作者路径会显式带上不同的升级费用。

## 3. 本轮修正的缺陷（都在我自己的实现/检查里）

1. **记录的字段顺序与调用实参顺序被我改乱**：`AuthorCard` 里我把 `NormalCost/UpgradedCost` 插在 `Cost` 之后，
   而调用点把实参插在 `unplayable` 附近 ⇒ 编译器报"参数 5 无法从 bool 转换为 int"等一串类型错。
   按声明顺序对齐后解决。
2. **属性块插错了记录**：`SliceCard` 与 `SlicePower` 的结尾签名相同（`string SourcePath, int SourceLine);`），
   我的插入命中了 `SlicePower`（那里没有 `Cost`）⇒ `CS0103: 不存在名称 Cost`。改为只改 `SliceCard`。
3. **检查里假设存在"升级动作"**：切片**没有** `UpgradeCard` 动作（升级是 `upgrade_hand` 过程/旧 Upgrader 的职责），
   我原本按不存在的动作写检查 ⇒ `Sequence contains no matching element`。改为走**真实存在**的
   `upgrade_hand`（用药水触发）——这也让"升级改写费用"这条断言更有说服力。

## 6. 仍未迁的关键项与原因

- **`BodySlam`（:1786）**：`attackUsingBlock` 在恢复得到的 `sts2/` 里**没有实现**，
  "这次攻击是否算 powered"无法确认 ⇒ **未声明**（待来源或裁定）；它还需要本批刚补的每变体费用（1 → 0）。
- **自我施加能力**（`DarkEmbrace`/`Tank`/`Inflame` 一类）：需要 `apply_power` 的**自身目标**形式，
  且这些能力的**触发语义**（如"消耗时抽牌"）切片尚未实现 ⇒ 声明它们会出现"牌在、效果不在"，因此不做。
- **能量获取**（`ExpectAFight` 的 `modifyEnergy` + `NoEnergyGainPower`）、**条件**（`Clash`）、
  **按名字计数**（`PerfectedStrike`）、需要交互的抽牌（`Pillage`/`BurningPact`）等，逐条待补原语。
