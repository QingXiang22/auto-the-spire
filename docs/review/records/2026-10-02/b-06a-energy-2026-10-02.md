## 1. 来源

```
power NoEnergyGainPower { preventEnergyGain = true  removeAfterOwnerTurnEnd = true }   // ironclad-powers.spire:19
card ExpectAFight {
    cost = 2                                       // 升级 1
    play = { modifyEnergy { amount = scaled { base = 0  perCount = 1
                              count = { pileCount { pile = hand  type = attack } } } }
             applyPower { power = NoEnergyGainPower  stacks = 1  target = context.owner } } }
```

## 2. 三件新东西（都是"先补能力，再声明内容"）

| 能力 | 说明 |
| --- | --- |
| `gain_energy` 步骤 | 给玩家加"这张牌的 `Amount`"点能量（数量可由 `amount-source` 决定） |
| `hand-count:<Kind>` 数值来源 | 手牌里**该类**牌的数量（来源 `pileCount { pile = hand  type = ... }`；`Kind` 只接受 Attack/Skill/Power/Status） |
| `prevent-energy-gain` 能力标志 | 持有该能力时**不能获得能量**；判定是**声明驱动**的（没声明的能力不进判定链），因此不引入隐式默认 |

**顺序**按来源：先 `gain_energy`（此时还没有门控）再 `apply_power_self`（挂上门控）——
所以这张牌**自己**拿到的能量是有效的，此后本回合再想获得能量才会被挡。

| **回合末移除** | 端末后该能力**整体移除**（不是减层）；下一回合再打同一张（升级、费用 1）→ **花 1 得 3**（门控确实解除了） |
| 冻结文本 | 能力来源行/标志/回合末形态、卡来源行/两形态费用/两形态来源逐条一致 |

## 4. 本轮修正的缺陷（都在检查/夹具侧，但都是真问题）

1. **夹具的"合成升级"不写费用**：`PutInHand(..., upgraded: true)` 只写 `Upgraded/Amount/PowerStacks`，
   于是升级形态仍按**普通费用**跑——表现是"花 1 得 3"却算出差 1 点能量。
   修法：给夹具加**显式** `upgradedCost` 参数（不猜、不回落），并在注释里写明它曾经导致过差 1 的假失败。
   （这正好与批 7 引入的"每变体费用"呼应：**任何升级路径都必须改写费用**，夹具也是升级路径之一。）
2. **我自己的检查期望值写错**：第二张牌被门控挡住时净变化应为 `-2`（只扣费用），我却按"未挡住"的公式算。
   改为 `-2` 并把"反向对照"交给下一项检查（回合末解除门控后**确实会**加能量）——
   这样两条检查合起来才证明"门控真的起作用"，而不是各自自说自话。
3. 场景卡组只放了一张 `expect-a-fight` 却要用两次（检查报 `no 'expect-a-fight' card in the source area`）——
   改为两张。
