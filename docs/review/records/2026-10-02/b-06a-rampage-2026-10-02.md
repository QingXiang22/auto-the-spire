## 1. 来源语义与本批的编码决定

`Rampage` 的来源由三段组成：

```
variables { variable { name = ExtraDamage  default = 0  preserveOnDowngrade = true } }
play = { scaledAttack { base = 9  perCount = 1  count = { cardVariable ExtraDamage } }
         modifyCardVariable { variable = ExtraDamage  amount = 5 } }     // 升级形态 amount = 9
```

已有的实例变量机制里 `grow = <name>` 只表示"每次 +1"，而来源是 **+5 / +9**，因此本批新增：

- **`grow-amount = <n>`**（默认 1，范围 0..999；**必须**与 `grow` 同时出现，否则 `missing_prerequisite`）；
  它对应的正是来源的 `modifyCardVariable { amount = N }`。

**编码决定（写下来，不藏着）**：把来源的 `base = 9` 落到变量的**初值**（`variable { extra-damage = 9 }`）。
"9 + 1×计数（每次 +5）"与"初值 9、每次 +5"在可观察行为上等价；差别只在内部表示。
来源的 **`preserveOnDowngrade = true` 在切片里没有降级路径，因此未建模**——这不是"支持了"，
而是"当前无法观察"。

## 6. 本次**没有**迁的内容与具体原因（不编造规则）

- **`BodySlam`（:1786，"以格挡为伤害"）**：来源用 `play = { attackUsingBlock = … }` +
  `damageValue = scaled{ base = 0 perCount = 1 count = block(owner) }`。
  在恢复得到的 `sts2/` 源码里 **搜不到 `attackUsingBlock` 也没有 BodySlam 的实现**，
  因此**这次攻击是否算 powered（是否受 Strength/易伤影响）无法确认**——我**不**按切片的默认行为
  替它猜，也不因此把它算进覆盖。等取得来源（或由规划者裁定）后再声明。
  另外它还有 **每变体不同的费用**（普通 1、升级 0），当前作者模型只有单一 `cost`，也需要先补。
- 其余未迁项（按名字计数、条件、能量获取、需要交互的抽牌、3+ 敌场景）同上，逐条留待补原语。
