## 1. 本批交付（已可用）

- **作者声明**：切片作者文本新增

  ```
  run {
    hp = 80
    max-hp = 80
    gold = 99
  }
  ```

  解析进模型（`AuthorRun`），键集合固定 `hp/max-hp/gold`，未知键按既有纪律**显式拒绝**。
- **整局实体**：只有作者文本声明了 `run` 时（`hasRun`）才创建 `Run` 实体与字段
  `Hp`/`MaxHp`/`Gold`/**`BattleSettled`**，取值来自声明；程序化路径（`author is null`）**不创建**，
  因此冻结包形状与 net/公开投影**不受影响**（383/383、J-01 150/150、client 50/50 均不回归）。
- **写回过程**：`SettleBattle` —— 守卫是 `BattleSettled`，语义是"把战斗玩家的 HP 写回整局，**恰好一次**"：

  ```
  If(Not(Run.BattleSettled), [Run.Hp = Player.Hp; Run.BattleSettled = true])
  ```

## 2. 为什么"恰好一次"的守卫长这样

B-07a 的验收里有两条："房间结算**写回一次**"与"结束/故障**不重复奖励**"。这两条都要求写回是**幂等**的，
因此在整局实体上放一个 `BattleSettled` 布尔而不是依赖调用方"只调用一次"——
重复调用会走空操作（第二次进不去 `If` 的 then 分支）。

## 3. 【未接通】自动写回在运行期取不到 Run 实例（下一轮的第一件事）

把 `SettleBattle` 接到"胜利/失败"两条终局路径上后，运行期报：

```
TypeError: field 'BattleSettled' target must be an instance reference but is None
```

即 `SettleBattle` 里的 `First(Type(runEntity, battleScope))` **查不到 Run 实例**。
已核对：Run 实体确实在 `SetupBattle` 里用与玩家/敌人**相同的写法**创建
（`setup.CreateEntity(runEntity, setup.LocalRef(battleLocal), createdLocal, [...])`），
且创建发生在 `StartPlayerTurn` 之前。因此下一步要查的是"**从另一个（非 setup 的）过程里按类型查作用域成员**"
这条路径（例如作用域成员索引是否需要显式 add，或查询目标应为 `EntityScope`）。
**在那之前不做别的接线**：宁可让写回暂时不生效并把症状写清楚，也不接一条"看起来能跑、实际上写不进去"的调用。

本批因此**保留过程定义与实体**，把自动接线撤下（源码里有注释指向本节），保证既有 186 项检查全绿。

## 3b. 【第二小批】三个实验与结论（症状被收窄到"创建/可见性"）

| 实验 | 做法 | 结果 | 结论 |
| --- | --- | --- | --- |
| ① 只在**胜利**路径接线 | `DamageMonster` 尾部 `Concat(SettleTail(...))` | `TypeError: field 'BattleSettled' target must be an instance reference but is None` | 复现稳定（该检查会打赢一场战斗） |
| ② **在 setup 末尾**紧接着创建后调用 | `setupSteps.Add(setup.Call(settleBattle.Symbol))` | **同样的错误** | 问题**不在调用上下文**，而在"实体创建/可见性" |
| ③ 查法换成集合 | `First(Collection(runStates))` 取代 `First(Type(runEntity, battleScope))` | **仍然 None** | 两种查法都取不到 ⇒ 更像是"创建指令没有生效/实例不在集合里" |

另外一个**失败并被放弃**的实验（不作为证据）：把 Run 单例改成"首次出牌时懒创建"时，
我在动作体里**再次**调用了 `playBody.Body(...)` ⇒ `DuplicateDeclaration: … 'PlayCard$program' more than once`。
该实验已完全撤下；下一轮做同类实验时要**把创建指令追加进既有的 Body 序列**，而不是再调一次 `Body`。

**下一轮的第一个实验**（据此设计）：在既有的 `playBody.Body(...)` 序列里**追加**一段
"若 `RunStates` 为空则创建"的指令，再看结算过程能否取到——这样可以在不改动调用上下文的前提下，
判定"setup 里创建的实体是否可见"与"创建指令本身是否执行"这两件事。
