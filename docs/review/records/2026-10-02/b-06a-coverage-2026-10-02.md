## 1. 为什么要有这个检查

B-06a 的前 16 小批报告里，"分母 / 已迁"是**手写**的（"22/96"）。手写的数字会漂：
换一次口径、漏一张状态牌、把多人内容算进单人范围，报告就会和实际不符。按 §14 的要求
（"不可达或多人内容显式分组，不能静默删掉难项使分母变小"），本批把它做成**机械核算**：

```powershell
python tools/coverage-check/check_slice_coverage.py --json tools/coverage-check/slice-coverage-2026-10-02.json
```

三个数据源都不手写：

1. `tools/content-manifest/manifest-2026-10-02.json`（B-05a 冻结清单）→ **分母**；
2. `Authoring/Examples/slice-content.author` → 作者文本里**真的声明**了什么（正则读 `card … {` / `power … {`）；
3. `BaseSpire.Slice.Tests/Shared/SliceFixtures.cs` 的 `AuthoredBeyondSlice` / `AuthoredPowersBeyondSlice` → 测试侧登记的已迁清单。

检查的不变量（任一不成立即退出码 1）：已迁清单不能有作者文本里不存在的条目（清单过期）、
不能有不在分母里的条目（命名漂移/超范围）、作者文本里声明的卡必须"在分母里或显式列为夹具卡"（不静默计入）。

## 2. 【修正】分母口径：以前写的 96 是"注册总数"，不是迁移分母

检查第一次运行就抓到 `base-spire:entrench` **不在** `ironclad_single_player_cards` 里——
它属于 `cards_without_pool`（来源 `rarity = event`）。顺着这条把口径定清楚：

| 口径 | 值 | 说明 |
| --- | --- | --- |
| 注册总数 | **96** | B-05a 清单的 `cards_registered`（对照用） |
| 多人专属（**显式分组、不计入**） | **2** | `base-spire:demonic-shield`、`base-spire:tank` |
| **迁移分母** | **94** | （Ironclad 单人卡池 85 + 无卡池卡 11）− 多人专属 2 |
| 已迁入并可运行 | **22** | 分母内 18 张新迁 + 切片自有 4 张（Strike/Defend/Bash/Headbutt） |
| 剩余（仍在分母内） | **72** | 94 − 22 |

> 此前报告的"22/96"里的分子分母都各有一处不精确（未含状态牌口径、且把 2 张多人专属算进了范围）。
> 本表以后者为准，并且**可复算**——改口径只需改清单或清单里的分组，检查会立刻反映。
