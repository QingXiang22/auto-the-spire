# 敌人格挡、Frail 与三只新敌人交付记录

日期：2026-10-18。任务：**CORE-AUTHOR-05／DSL-ENEMY-BATCH-03**；当前认领、状态与恢复顺序只维护在[主清单](../../tofix/README.md#当前交付)。本记录接在[敌方阶段规格](../../../design/mod-the-spire/enemy-turn/spec.md)之后，是实施与自查记录，不是独立评审，也没有独立原版对拍。

## 交付与范围

- 新增 `GainEnemyBlock`：敌方用自身 `Block` 承伤（`DamageEnemyPowered` 已经按格挡→生命的顺序结算）。
- 卡牌格挡链加入 **Frail**（源 `FrailPower.ModifyBlockMultiplicative` 的 ×0.75，整数向下取整）：`GainBlock` 先算 `amount + Dexterity`，再乘 0.75，最后截到 999。
- 复刻源 `PowerCmd.Apply` 的**首次减层豁免**：施加到玩家身上的 debuff 带 `Power.SkipTick`，第一次回合末减层被跳过（`SkipNextDurationTick`），否则敌方回合内施加的 Frail 1 会在同一回合末立刻消失。
- debuff 减层的角色集合加入 `block-dealt-multiplier`。

三个新的敌人模板与内容：

| 内容 | 模板 | 源行为 |
| --- | --- | --- |
| BowlbugEgg | AttackDefendEnemy | A0 HP 21..22（开发用 21），`BITE_MOVE` 7 伤害＋7 格挡，单招循环 |
| BruteRubyRaider | AttackBuffEnemy | A0 HP 30..33（开发用 30），`BEAT_MOVE` 7 伤害与 `ROAR_MOVE` +3 强度交替 |
| Stabbot | AttackDebuffEnemy | A0 HP 18..23（开发用 18），`STAB_MOVE` 11 伤害＋1 Frail，单招循环 |

包版本升到 `0.5.0-dsl.16`，敌人定义 6 只（源分母 121）。

不迁移：敌方格挡修正参与者、Frail 之外的减益（如 Artifact 抵挡）、其余 115 个敌人、遭遇编队、意图伤害数值、死亡钩子与 Run 结算。

## 来源依据

三只敌人的源 hash 均由已安装 skill 的定位助手从安装路径核对为 `source_hash_status: matches`，资格 `singleplayer`。关键数值来自各自文件的 `MinInitialHp`／`MaxInitialHp`、`BiteDamage`／`ProtectBlock`、`BeatDamage`＋`_roarStrength`、`StabDamage` 与 `FrailPower` 施加量；Frail 的 ×0.75 与减层时机来自 `FrailPower.cs`，首次减层豁免来自 `PowerCmd.cs` 的 `SkipNextDurationTick` 设置。

## 实际验证

Windows／PowerShell，.NET SDK 9.0.306；Debug 配置。

| 命令 | 实际结果 |
| --- | --- |
| `dotnet build AutoTheSpire.sln -v minimal` | 通过，0 警告／0 错误 |
| `dotnet run --project tools/base-spire-dev -- validate` | 退出 0；包 `0.5.0-dsl.16`；enemy 目录 121 源／6 个 DSL definition；card 29、relic 8 |
| `dotnet run --project tools/base-spire-dev -- check --report .artifacts/base-dsl/behavior` | 103 项全部通过 |
| `python -X utf8 tools/ci/check_relic_coverage.py .artifacts/base-dsl/behavior/package-behavior.json` | 退出 0：8 件遗物行为见证；源 297；未实现 288；`independent_verified=false` |
| `dotnet run --project net-the-spire/Net.TheSpire.Tests` | 362 项通过／0 失败（敌方格挡清空后复跑） |

新增判别覆盖（103 项）：BowlbugEgg 攻击后获得 7 格挡，玩家下一次 Strike 只把它打到 1 点格挡而生命不变；敌人每个回合开始时先清空自己的格挡（对应源 `Creature.AfterTurnStart`，玩家的首回合例外不适用于敌人），所以连续两回合后仍是 7 点格挡；BruteRubyRaider 先打 7、再强化 +3、再打 10（80→73→73→63）；Stabbot 打 11 并施加 1 Frail，玩家下一次 Defend 的 5 点格挡变成 3（5×0.75 向下取整），且 Frail 因首次减层豁免没有在施加当回合消失。

过程中修了两处自身错误：CP73／CP75 先授予卡牌再结束回合，手牌在回合末被弃掉导致取不到候选（改为下一回合授予）；CP74 的期望值一开始写成 66（应为 63）。两处都只改检查、未改生产语义。

## 未验证与未支持

- 未运行独立原版对拍、完整 Engine 套件（留给 Actions）、正常 Run、完整游戏矩阵与性能套件；`independent_verified` 保持 false。
- 敌人只覆盖 6/121；没有遭遇编队、意图伤害、开场条件、死亡钩子与移除；初始 HP 用最小值。
- 敌方格挡没有修正参与者；Artifact、减益免疫与其它减益仍未迁移。
- 减层只绑定到三类 debuff 角色；其它带时长的能力（如姿态、蓄力）没有对应语义。
