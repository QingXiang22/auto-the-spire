## 2. 关键决策与新旧行为

1. 首批 M1 是通用运行时经非 STS 夹具验证后，运行 base-spire 的受控战斗切片，经 net 生成公开观察/执行动作，由 Python AI 编码并输出均匀合法候选概率，记录实际转移。随机基线验证管道，不宣称训练有效。只包装旧 CombatEnvironment 不满足通用引擎交付。
2. 保留并验收已有 Engine 六份 Schema/IR 等初始源码；旧 STS 后端作为迁移对照，不重写或删除其他工作。真实构建、规则检查、内容加载范围在 K-00 建立基线。
3. 旧 C-01 要求 E0 前有最小双端原型；现在 P-01 先交付统一机器资产与 Python 参考检查，AI 独立编码可以开始，N-01 再交付 C# contracts 和双端复核。协议冻结/接口联通的跨端要求保留；两端不得另建互不一致的协议。
4. 当前公开事实和已知牌位置由游戏包/提供方投影；AI 不补历史缓存、不读取隐藏完整状态。未知真实顺序与已知绝对位置分开验收。
5. Lua 适配、完整作者前端与剩余 STS 领域迁移在后续批次；训练需要明确目标、偏好和资源配置。没有把未定奖励权重或预算擅自填为编码要求。
