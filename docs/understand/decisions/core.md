# core 架构决定

文档类型：解释（Explanation）。本文解释通用内核的长期边界。当前 API、语言和兼容性以 [活动约定](../../specs/core-engine-baseline.md)、[语言参考](../../reference/dsl/README.md)和实现为准；版本及验证结果由工程文件与 CI 给出。

## 通用内核与游戏规则分离

core 提供类型化状态、过程、事件、集合／关系、选择续接、随机和观察原语。卡牌、回合、伤害、死亡、地图、奖励及原版初始化由 base DSL 定义。其他游戏通过相同原语组包，不让游戏 ID 或玩法条件进入 Session。

## 同一 IR 与执行路径

文本 DSL 和 C# 构建器编译为同一种 IR，经同一链接检查器和 Session 执行。普通规则作者直接编辑文本；C# 服务宿主、扩展和检查。ANTLR grammar 与生成代码纳入源码，正常构建不依赖 Java。语法接受、绑定成功、启动成功和行为正确分别验证。

Session 按职责分文件，共用唯一执行栈和调度器。调试、公开适配和独立比较工具消费它的接口，不替换执行语义。

## 规则不可变与实例状态独立

Build 后规则及作者对象图固定，不能因后续集合或 Symbol 修改改变已构建规则。RuleSet 可供多个 Session 共享；局内状态属于各自 Session，内容私有状态仍使用 Engine 类型化存储。

## 随机顺序由调用者定义

取样保留候选序列，核心不擅自按实例或展示顺序排序。游戏需要排序时显式表达。随机算法、Profile、流状态和计数可核对；原版 seed 派生、候选构造和调用顺序由游戏规则／配置负责。

## 开发者 API 与公开接口分层

Session 保留开发者能力，不为训练接口另造一个内核运行时。公开 Host 按投影约定发布允许的信息和当前合法候选；隐藏状态、内部随机及诊断信息不得流入 AI 输入。稳定公开句柄、可见性和幂等控制由各自约定定义。

## 故障和暂停语义明确

当前故障以 [Session 约定](../../areas/core/reference/session-api.md)为准，已完成指令的作用不能被文档写成完整动作回滚。选择在原执行路径暂停并继续，重发不能重放已完成的前缀。新的暂停位置或原子性要求先明确可区分的行为，再扩通用能力。

## 有界诊断

现有调试选项默认关闭，轨迹有界且只读，不改变随机、候选或规则语义。调试记录供当前排障使用，按临时产物清理；可重复的缺陷转为自动回归。

## 内容自有规则与公共操作

具体内容拥有自身正文、数值、监听和私有状态，调用稳定领域操作；公共生命周期只发布真正共用的站点。通用 dispatch、模板和纯提供者不包含游戏 ID 特例。第二个复用者应能通过内容模块接入，无需再修改公共调度。

## 维护决定

通用缺口使用最小语法／SDK 复现确认，必要时修改内核并迁移真实消费者。Lua、完整恢复／搜索、编辑器及多人能力按明确需求安排；当前可用性以约定为准。重要新决定在本页维护背景、决定和后果，普通改动通过 PR／Git 查询。
