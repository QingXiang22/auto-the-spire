# 项目规格

文档类型：参考（Reference）。本项目为 AI 提供可复现、可观察、可控且可扩展的《杀戮尖塔 2》环境。目标是按[锁定的 sts2-sim](../../reference/baselines/sts2-sim.json)实现五角色完整单人游戏；Ironclad 和局部开发场景是中间交付。规则依据为该提交的源码与顺序随机执行，本地 `sts2/` 不再作为当前规则裁决依据。锁定模拟器同时提供比较后端；结果一致证明 DSL 与该实现一致，不单独证明真实客户端保真。现有 DSL 与旧固定向量仍须按新基线迁移，不能只更换版本标识。

## 模块与规则归属

| 模块 | 职责 | 规格 |
| --- | --- | --- |
| core-the-spire | 通用类型化状态、DSL 编译、唯一执行器、选择续接、随机与观察原语 | [core 规格](core/game-model.md)、[活动约定](core-engine-baseline.md) |
| mod-the-spire/base-spire | 用 DSL 定义原版玩法、内容、生命周期与 Run | [base 规格](../areas/base/spec/overview.md)、[当前架构](../understand/base-architecture.md) |
| net-the-spire | 加载相同规则包，透传公开观察及合法候选，维护协议与幂等控制 | [net 规格](../areas/net/spec/overview.md)、[协议](../areas/net/reference/protocol.md) |
| ai-the-spire | 消费公开协议，采样、训练及评价；不读取隐藏状态 | [AI 规格](../areas/ai/spec/overview.md)、[策略约定](../areas/ai/spec/policy-contract.md) |
| tools | 构建、CI、定向检查、独立参考适配和来源核对 | [工程工具](../../tools/README.md) |

普通规则作者使用 core/0.3 文本包；C# 构建器服务引擎扩展与宿主集成，两者编译为相同 IR。游戏内容和可变游戏状态分别由 base DSL 与 Engine 承接。规则包构建后不可变，Session 状态彼此独立。活动生产工程不回退旧 C# 玩法或另建结算器。

## 当前可用性与交付目标

可运行范围以 [base manifest](../../mod-the-spire/base-spire/package.json)及所审提交为准。当前开发 scope 提供部分战斗和内容机制，正常地图／Run、完整来源和独立比较尚待恢复。声明、加载、行为测试、独立比较和公开可用分别确认；实现数和测试数不能代替完整游戏能力。

当前任务和暂停条件见 [GitHub 任务清单](https://github.com/QingXiang22/auto-the-spire/issues/28)。环境完整行为要求与最终矩阵集中在 [环境验收规格](environment.md)，不在交接报告中维护。

## 全项目要求

### W-01

正式规则包通过同一 Host 完成 describe→catalog→start→出牌／用药→终局及离线重编码。药水定义、目标、容量、可用状态和长期牌组应正确发布。当前有效的损血、耗尽、成长变量等公开事实由提供方输出；AI 不从历史补齐缺失的当前事实。不同 Profile 的适用范围和标识须明确。

### W-02

相同定义的不同实例在关系、位置可区分时正确表达；隐藏增删与重排不泄露，合法公开事实完整。跨会话一致换名后，结构、引用、编码、概率和默认选择应等价；适用扩展场景执行 V-15。未经对应验证的场景不进入真实学习。

### W-03

采样分布包含真实资源、目标和牌区知识差异。每个模型标识的 train／validation／final 划分隔离且非空，绑定场景来源、故障、截断、资源上限及采样成本。环境阶段先建立完整来源、可执行 suite 和 Release 成本；学习分布另行确定。

### W-04

学习工程包括模型、自动微分、Adam／PPO、版本化奖励、真实轨迹学习、同 seed 配对评价与区间、模型精确标识、参数量／内存／延迟／吞吐、保存加载及 resume。Trainer 标识刷新与新增路径失效须明确处理。后续框架优先 PyTorch；共享 Transformer 与正式实验当前暂缓，既有 NumPy 工程保留。框架替换本身不证明学习效果。

### W-05

战斗终止与整局终止分离；结算幂等并完成最后击杀余效。HP、MaxHp、金币、药水、遗物和永久牌组跨房间正确保留，同定义实例来源明确，临时变化隔离。地图、遭遇、奖励、商店、营火、宝箱、先古之民、事件战斗返回、幕转换与终局均属于完整 Run。

Run 阶段、敌人招式图、奖励来源上下文及规则历史按 [base 共享领域模型](../areas/base/spec/overview.md#共享领域模型)及其领域规格实现；共享状态由同一 Engine Session 持有，Host 不另建玩法推进循环。

### W-06

玩法以 DSL 为单一可执行来源。高级声明、普通／升级、条件、X 费、目标、hook 与文本库组合语义可核对；未支持范围明确拒绝。五角色和全部原版单人可达内容均在目标范围，缺来源不能默默删减内容，也不回退旧语言或旧后端。

### W-07

先完成 ENV-00～06 环境候选，明确参考偏离及真实客户端取证边界。验收后重新确定 AI 分布、目标／奖励、学习与部署预算、晋升条件及收益偏好，旧实验 seed 和预算不自动沿用。

### W-08

接口不变量、行为检查与性能要求绑定实际源、规则、内容、随机 Profile、模型及提交。首个差异和故障可复现，覆盖、确定性和部署成本有自动结果。局部缺陷修复只关闭对应范围；发布及完整环境仍按各自完成条件验证。

## 开发与变更

遵循 [开发与文档约定](../../CONTRIBUTING.md)。规格维护行为承诺，PR 维护变更讨论，CI 执行检查。历史实现和已替代的方案通过 Git 查询；日常开发不要求恢复旧报告或本地产物。
