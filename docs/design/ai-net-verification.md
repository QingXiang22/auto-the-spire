# AI 与接口的验证和验收计划

本文供实现者和验收者查询验证场景、判定依据及需求追踪。表中的场景是验收定义；实际执行结果、当前任务与关闭结论以[GitHub 任务清单](https://github.com/QingXiang22/auto-the-spire/issues/28)为准。

编码第 9 节细化确定性编码场景，不能代替提供方行为验证。[运行约束](ai-net-operations.md)规定部署停止与恢复。任务、依赖和排期只在 GitHub Issues 维护。

## 1. 判定依据与验证记录层级

类型/引用/顺序由公开约定判定；可见性由游戏机制与观察者当前可知信息判定；规则结算以仓库恢复源码和可复现规则检查为依据；模型效果以事先固定的任务/种子/偏好与基线为依据。不能用 AI 的预测检查游戏规则，或用 JSON 解析成功证明没有泄漏。

E0 用公开 fixture 的预期结构；E1 用真实模拟会话，构造不同隐藏顺序但相同公开事实；E2 加模型输出/训练/资源实验；E3 按内容覆盖扩大规则检查；E4 对真实后端抽样差分。分别保存配置、输入、命令、实际输出、判定、失败及范围。

## 2. 质量目标与验收条件

| 驱动 | 刺激、响应和度量 | 验收条件/决定者 |
| --- | --- | --- |
| 可见性 | 隐藏牌序/RNG/未揭示内容变化，公开输入仍等价 | 所有适用场景零泄漏；完整范围列清单 |
| 执行安全 | stale/重发/并发/断开，只有一次符合版本的推进 | 对受支持生命周期无重复或过期执行；跨崩溃不假承诺 |
| 编码可扩展 | 新声明/新实例/批长变化，不改记录格式 | 已声明结构无静默遗漏、无错引用；新语义需新版本 |
| 概率正确 | 候选/实体重排与补齐变化，按引用对齐结果等价 | 精确集合匹配；浮点容差由批准的推理配置给出 |
| 学习效果 | 保留分布下候选优于基线且可复核 | 主指标、改善幅度、样本与置信验收条件由维护者在 E2 前声明 |
| 部署成本 | 目标 CPU 上按典型/极端规模测完整链路 | 延迟分位数、峰值内存、参数/权重阈值在 E2 前批准 |

没有批准阈值时允许报告测量，不允许写“达标”。不得预设 5 秒、8 GB 或固定 200 局作为要求。

## 3. 验收场景目录

| 场景 ID | 初始条件与刺激 | 预期响应、事实及禁止结果 | 检查方法/阶段 |
| --- | --- | --- |
| V-01 | 同一公开目录以不同注册顺序给 C#/Python，构建和保存字典；随后用另一目录/能力标识启动 | 原字典映射持久化一致；目录值两端 round-trip 一致；错标识在推进前拒绝 | Python fixture 逐项比对 E0；双端复核 N-01；真实 describe/start E1 |
| V-02 | 模拟局保持同一公开成员、位置、ID 和候选，改变未知内部牌序、RNG 游标/未揭示内容；获取公开快照 | 除诊断隔离资料外，公开特征按引用对齐相同；数组顺序、ID 与候选也不能暗带隐藏信息 | 净化后的 wire 和 AI 特征比较，审查投影来源 E1；不是只对 fixtures 编码 |
| V-03 | 第一次输入为置顶后快照，五张中 C 位置0、D位置3；随后抽牌/洗牌；切到另一会话再编码 | 有效位置正确保留/变化/失效；无 known_top、历史缓存或跨会话残留；成员不重复计数 | E0 样例与独立调用比较；E1 实际机制核对 |
| V-04 | 对观察7提交候选；并发另一个控制请求；完成后以新 request_id 重用观察7；另测后端自行变化 | 并发 busy 或已声明单写者拒绝；旧请求 stale，无额外推进；没有半结算快照；当前候选与版本一致 | 注入调度屏障，读取推进计数与请求账本 E1 |
| V-05 | 同名牌实例不同升级/费用，候选引用其中一张；一致重命名 ID、重排实体/成员/候选 | 引用动作仍指向正确实例；多张不被合一；编码按映射等价，模型概率按句柄对齐等价 | fixture 映射 E0、真实动作 E1、网络 E2 |
| V-06 | 输入已知0、unknown、unavailable、字段省略、无内容空槽及 padding；另输入悬空引用/重复键/非法十进制和牌堆四条不变量的反例 | 协议明确声明的状态可区分；省略不推断具体适用性；位置按 total_count 绝对边界检查；失败代码和路径明确，无部分编码或游戏推进 | 类型/数组/mask 及每条不变量的正反例断言 E0/E1 |
| V-07 | 请求被接受后丢失应答并原样重发；同 ID 换载荷；真实执行确认丢失；提供方崩溃 | 活跃进程原样重发仅一次执行；换载荷 conflict；未知结果停止/查询；崩溃后 not_found 不导致自动点击重试 | 注入断开/故障；检查后端调用数、状态和禁止请求 E1/E4 |
| V-08 | 旧 Gym/模型包有效；增加内容建新目录和字典；混批不同 Manifest 或加载错标识包 | 旧文件可照常加载；新输入配旧模型、混批和维度错配拒绝；不自动扩 embedding | 保存/加载 E0；模型包 E2 |
| V-09 | 声明 seed_action_replay=public_trace 的模拟后端，相同 identity/配置/种子/动作语义序列启动两次，额外插入只读查询；另测部署 NoSL 和错误后重选 | 公开事实与候选语义按公开引用对齐一致，排除会话/句柄字符串差异；查询不写状态/RNG；无公开 rollback/load/fork，unknown 不重试；新局标识不复用。未声明重放的后端仅检查能力诚实与适用 NoSL 项 | 会话记录、能力与操作白名单；纯读另用提供方状态哈希/RNG 游标断言 E1/E4 |
| V-10 | 实际行为含温度/探索或并列采样；普通终止、窗口截断与技术中断各发生一次；奖励改版 | μ 与真正采样一致；原始事实/奖励/偏好分开；完整转移去重；中断不当失败或凭空反事实 | 轨迹重算与采样分布核对 E1/E2 |
| V-11 | 内部 tensor 混合有效/补齐项，单候选、终止空集合；候选排序/句柄改名后用相同执行 RNG 采样；输入非有限 logits、重复/遗漏概率项 | 内部 padding 概率零；外部 choices 精确覆盖候选且没有 padding，总和为1；相同语义输入采样相同语义动作；终止不softmax；非法输出停止；可选 Q 语义完整 | 输出约定、规范采样与 masked 计算检查 E2，mock 可提前检查协议 |
| V-12 | 训练/调参/最终种子隔离；在固定任务分布比较随机合法/规则/模型，恢复学习 checkpoint | 数据/目标版本可追踪，无评估样本训练泄漏；报告样本数与不确定性；恢复不要求游戏回退 | 实验配置审计和保留分布报告 E2/E3 |
| V-13 | 指定目标机器，典型与极端实体/字段/候选规模，暖机/冷加载和不同 batch | 报参数/权重/全链路分阶段延迟及分位数/峰值内存；超过已批准预算不发布、不截断 | 重复 CPU 基准、输入规模/机器/线程/精度记录 E2/E4 |
| V-14 | 超出实体/候选/帧/磁盘上限，非法概率，用户停止，结算超时 | 明确超限/中断，不丢字段后继续；不使用旧快照，不伪造终止结果；能说明残留状态与恢复方式 | 故障注入、日志及禁止动作核对 E0/E1/E2 |
| V-15 | 所选开发场景逐机制给出来源/公开事实/更新/字段/验证验证记录；构造决策相关公开事实不同的成对状态 | 目录及覆盖表中的引用均有效；事实差异在 wire 和编码中保留，不因聚合丢失；未支持约束阻止该训练配置。有限反例不证明完整 Markov 性 | 覆盖表审计、提供方机制与编码对照；E2 前完成，E3/E4 扩展时重做 |
| V-16 | 将已评估模型量化/蒸馏、改变推理精度或导出格式 | 新摘要/model_id；在相同固定任务与资源配置下重新检查概率、学习指标/决策行为和 CPU 成本，通过验收条件后才发布 | ModelBundle 标识、V-11/V-12/V-13 适用项重评 E2/E4 |

上述都是期望，不是“已有测试通过”。同一场景的 fixture/模拟/真实验证记录各自独立标注。不可见内部数值只允许在提供方测试的判定工具中读取，不暴露给训练输入。

## 5. 执行与报告

纯文档运行 `python tools/ci/check.py docs`。实现按影响执行协议、模拟集成、规则、学习或资源检查，入口见[CI 说明](../../tools/ci/README.md)。阶段代码用于区分验证层级，不能作为旧派单表的依据。

交付通过 PR 和 CI 确认，说明实际改动、受影响场景、检查结果及限制；失败给出最小复现。接口变化在同一 PR 更新规格，流程见[开发约定](../../CONTRIBUTING.md)。
