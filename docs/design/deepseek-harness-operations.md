# 委派远端开发任务

适用于已授权的 DeepSeek Harness 任务。开发、文档及交付统一遵循 [CONTRIBUTING](../../CONTRIBUTING.md)；远端任务同样提交分支／PR，由 CI 和代码评审确认结果。

## 派发

1. 从[任务入口](../roadmap.md#近期队列)选择一个 ready 执行工单，在 Issue 写明实际执行者，核对依赖、输入提交、修改边界及验收条件。不要直接把父任务或一段旧聊天作为派单。
2. 为远端任务准备独立 worktree／分支，将分支写入工单，确认 Harness 实际能访问该目录。派发内容以工单链接和必要 skill／文件入口为主；执行者不能访问 GitHub 时提供该工单的当前正文，不另存派单文档。
3. 使用已配置的服务地址和登录凭据连接。凭据从 `DSH-USERNAME`／`DSH-PASSWORD` 读取，不写入提示词、仓库或命令输出。
4. 派发成功后将工单改为 doing，保存任务／会话 ID 供本次查询；`accepted` 只表示已受理。每个执行者同时一个执行单，避免重复派发或其他会话同时修改相同文件。

base 内容作者可显式读取 [项目开发 skill](../../.agents/skills/base-spire-development/SKILL.md)，按其路由阅读现行手册；是否自动发现 skill 以实际环境为准。

## 复核与接续

- 运行中查询同一任务的状态，避免另一会话修改它的工作区。
- 提交关联工单的 PR 后改为 review；读取实际提交／差异及检查结果，按工单完成条件评审。只有调度响应或执行者一句“完成”不足以判断实现正确。
- 失败时保留当前任务所需的最小复现，修复后由 CI 重新运行；阻塞时改为 blocked，在 Issue 写明依赖及恢复条件。
- 结果摘要直接放任务／PR，包含改动、检查及限制。无需另建交接 Markdown、会话台账或归档目录。
- 已授权的定时复核跟踪当前任务，仅在完成、失败、阻塞变化或需要用户操作时通知；无变化保持安静。

取消请求受理后核对任务确已停止，再处理其工作区或接续任务。未完成的工作通过分支与 PR 保留。

## SSH 工作区

需要 SSH 时按所安装插件的 README 核对工具与版本，先用 `rw_info` 确认机器及目录，再连接和选择工作区。任务 cwd 应位于实际返回的镜像目录；浏览器登录与 SSH 连接分别确认。不要在普通项目文档中固化个人机器路径、服务 IP 或某次部署的版本结论。
