## 1. 验收原则

先完成环境与保真验收，再开展正式 AI 学习。小开发场景只能验证局部机制和学习管线；完整环境要求全部单人可达内容有来源、可加载、可运行，关键机制、组合及整局有独立比较结果。比较后端独立执行；因规则移植和比较共享 sts2-sim 来源，输出一致仍不能排除来源错误或移植中的共同错误，也不能据此宣称客户端保真。

游戏玩法在 base DSL 中实现。通用能力不足时附最小复现协调 core 维护，不将完整通用桌游引擎、Lua 后端或任意 mod 能力作为原版内容前置。按可运行阶段交付，新规则与差异测试同批完成；短场景不能替代正常开局到真实胜负。真实客户端取证及指定 mod 分别验收，不扩展当前原版实现范围。

模块、状态与生命周期要求见[实现约束](environment-implementation-constraints.md)，协作流程见[开发约定](../../CONTRIBUTING.md)。正式 Host 固定角色／进阶，每次 start 接游戏字符串 seed，遵循[协议 0.2](../areas/net/reference/protocol.md#7-env正式环境的02扩展)，旧协议版本明确拒绝，消费者同步迁移。

## 2. 实现与来源入口

- 当前支持范围以 [base manifest](../../mod-the-spire/base-spire/package.json)、[开发手册](../areas/base/README.md)及所审提交的[检查结果](../../tools/ci/README.md)为准，局部行为检查不代表完整 Run。
- 独立比较入口见[差异测试工具](../../tools/differential/README.md)，参考提交见[锁定清单](../../reference/baselines/sts2-sim.json)。原 suite 和失败条件继续有效，未支持或零执行不得计通过。
- 源码核对绑定 sts2-sim 的提交、tree 与实际文件摘要；每次更新先取最新上游再锁定 SHA，不在测试运行时追踪浮动 main。现有旧源码向量只证明其原来源回归，不作为新版符合性测试结果。模拟器已知缺口及与客户端的差异单独报告，不能为关闭阶段而修改完成条件。
- 五标准角色为 Ironclad、Silent、Regent、Necrobinder、Defect。额外类型是否纳入取决于单人正常可达性；不得按 C# 类总数推断完整内容范围，也不得无依据排除可达内容。

## 3. 固定范围与AI开训验收条件

以锁定 sts2-sim 的单人、全解锁顺序玩法为目标：五标准角色；基线支持的全部进阶等级（参考声明0～10，ENV-00核对源码）；全部可达卡牌普通/升级及其他合法变体、Power、遗物、药水、附魔/负面附加、敌人/招式/遭遇、角色资源、古代人/事件、地图、商店/营火/宝箱、奖励/选牌、四幕及最终终局。来源的全部内容类别进入总表，当前Ironclad94张等旧子集不能作全项目的来源条目总数。

排除UI/音频/平台、账号解锁/成就追踪、多人专属/同时私密选择和源码证明单人正常不可达的测试/废弃内容。排除必须登记对象、源码定位和理由；来源缺失的必要内容继续计未完成。游戏规则需要的历史摘要、状态验收条件及选牌/敌人记忆不得因“没有UI”省略。真实客户端驱动适配与任意mod自动移植不纳入本次编码任务。

ENV-03完整Ironclad整局只是中间里程碑，**不自动恢复正式AI实验**。主验收条件为ENV-00～06验收：完整来源范围无未实现/未加载/静默fallback，机制及整局差异有结论，公开出口覆盖完整，机器成本有测量，负责人审查固定环境候选。若尚缺某角色/事件或真实客户端抽样，明确剩余范围，不把“已能跑”改写为“环境已完整”。

## 4. 架构及实现约束

| 落点 | 允许工作 | 禁止越界 |
| --- | --- | --- |
| core/Engine | 通用类型/数值、状态与作用域、查询/集合、调用帧/局部变量、事件排序/暂停续接、随机后端/显式种子配置、诊断与预算 | 不加Card/Power/地图/伤害等STS分支；不以复制参考核心作为新Engine |
| base-spire | STS领域Schema/程序/事件/观察政策、正式DSL编译及原版内容、算法资产、完整Run | 不另建绕过调度器的战斗引擎，不直接写Core内部状态，不长期维护正式`.spire`和生产`.author`两套内容 |
| tools/differential | 两后端适配、标准动作/诊断快照、逐步比较/首个差异、有限生成与最小复现 | 不是生产后端；不替base执行规则，不给AI提供内部数据/正确动作 |
| reference/sts2-sim | 默认只读固定参照；必要时薄诊断钩子，行为无变化并独立验证 | 不先修遍参考，不修改参考规则使结果对齐，不以引用该项目运行base冒充完成 |
| net | 完整流程的公开观察/动作、当前知识、目录/Profile/版本标识及资源限额 | 不定义STS规则，不为AI设计奖励；诊断内部快照不能进入公开协议 |
| AI | 既有工程回归、必要Manifest/公开编码兼容；环境通过后再排学习 | 本轮不加预测头、不跑D3/D4/PPO、自监督正式实验，不用策略效果掩盖规则缺口 |

base 先用固定能力按机制纵向交付：用正式DSL描述→运行Engine→同批差异测试；确有通用表达缺口再附最小复现交负责人，不自动进入核心开发。复杂地图等计算放在base可追踪算法/受控计算资产，不把可选Lua工程变成全量内容前置。

公共约定变化须说明语法、AST/编译IR、执行语义、兼容/迁移以及受影响Profile。游戏作者入口为[base 开发手册](../areas/base/README.md)，通用语言入口为[core DSL](../reference/dsl/README.md)。领域玩法使用纯 DSL 和必要静态 JSON，不按卡牌 ID 增加专用指令，不回退旧 C# 玩法。

## 5. ENV-00：版本、完整来源范围及差异测试骨架

差异测试复用`tools/differential/`及既有来源清单和检查工具，恢复独立 DSL 适配并补齐原版源码的内容范围统计。参考依赖只存在于工具／工具测试，不进入生产core/base/net。语义规范留在`docs/`，工具目录只放用法／实现。

环境验收要求的用户命令如下（包含已实现入口与目标入口，当前可用范围见代码块后说明；内部项目命名可自行决定，但保留这些语义和稳定命令）：

```powershell
dotnet run --project tools/differential -- inventory --output .artifacts/environment/inventory
dotnet run --project tools/differential -- compare --suite fixtures-v1 --output .artifacts/environment/fixtures
pwsh -File tools/differential/test-env.ps1 -Suite regression
dotnet run --project tools/differential -- test --suite regression --output .artifacts/environment/tests/regression
dotnet run --project tools/differential -- test --suite ironclad-run --output .artifacts/environment/tests/ironclad
dotnet run --project tools/differential -- test --suite full-singleplayer --output .artifacts/environment/tests/full
dotnet run --project tools/differential -- run --character Ironclad --ascension 0 --seed ENV-IRONCLAD-001 --output .artifacts/environment/run
dotnet run --project tools/differential -- verify --manifest .artifacts/environment/candidate/environment-manifest.json --output .artifacts/environment/verify
```

以上为稳定语义约定。当前已实现 `test --suite` 入口，原 11 份 suite 定义保留在 `tools/differential/suites/`，包括有 17 个必测 ID 的 `regression`、`ironclad-act1` 和 9 份 `normal-*`。`regression` 的两个原用例已有双侧适配，其余用例及其他原 suite 仍明确报告 `unsupported`，完整测试集不能视为通过。实际命令、比较范围和结果含义见[差异测试工具](../../tools/differential/README.md)。

`test-env.ps1`、通用 `inventory`／`compare`／`run`／`verify` 入口以及目标 `ironclad-run`、`full-singleplayer` suite 定义尚待实现；已有 `normal-compare` 等专项命令按各自范围报告，不替代这里的完整环境验收。探索性诊断的返回码不能证明环境测试通过。后续 `test` 扩展须复用已有适配器、Comparator、记录及差异定位自检；禁止重建规则实现或先搭建独立大型测试平台。

`inventory`绑定source/reference/built Engine/base内容/DSL前端/适用运行配置的文件摘要；未提交目录不用父Git HEAD冒充版本。生成每内容类别完整ID和状态表：来源确认、解析/编译、Engine加载、能区分正确与错误实现的行为验证、差分结果、适用Host公开可用。旧Legacy状态另列，不计入新 Engine 的已实现数量。未迁移内容明确unsupported且给位置/原因，不因差异测试工具暂不支持而从完整来源范围删除。

输出机器可读完整表、机制依赖图及简短下一批列表。批次依据通用机制依赖/真实规则路径排序，不按卡名无限逐个修原语。已有已迁卡/Power优先纳入正式构建和差异测试；不重写已正确实现的内容。

首批测试场景：StrikeIronclad/DefendIronclad/Bash的普通/升级、Headbutt中途选择/置顶、伤害/死亡后续结算、Power生命周期。未具备兼容RNG时先用无随机受控状态比较；随机路径必须报`unsupported_rng_profile`，不能标原版同种子通过。差异定位工具需用刻意设置错误的测试数据证明会报字段差异/缺动作/漏事件，不能直接污染生产代码。

## 6. 差异测试协议与裁决

### 6.1 输入、标识与决策

每case版本基线、角色/进阶、初始配置或有来源的受控状态、种子及完整动作脚本。原版生成整局与受控机制测试场景分别标记；手工设定状态不能算正常开局胜利验证记录。两个后端接受**同一个语义决策序列**，不各自用默认策略跑到终局再比HP。

标准动作覆盖play/target/end-turn/potion、单选/多选/确认/跳过、地图、事件/古代人、奖励、商店、营火、进入/离开房间。描述使用内容ID、明确实例/目标角色、字段/选择参数及当前决策阶段。通过各后端自己的合法性API映射；合法动作集合、候选数量/参数/约束本身也比较。无法唯一映射就显式失败，禁止挑“效果差不多”的另一张牌。

实例跨后端映射从初始牌组/遭遇槽和已发生生成/复制来源建立稳定对应；相同定义的两张牌不可合并。生命周期/牌区移动不重绑，生成/销毁保留可追踪来源。只忽略后端分配的不透明原生地址/句柄，保留语义实例标识/顺序。不以动作执行后的HP等结果重新匹配以消除差异。

### 6.2 两类快照与比较点

**内部诊断**可以包含完整牌区顺序、实例变量/修饰、执行帧/待选阶段、敌人状态机、永久状态、RNG流状态/调用计数。只在测试工具访问，不能加入AI训练输入/公开协议。这是环境差异测试，与NoSL部署无回退并不冲突；每个脚本仍顺序执行，不用回退替代不一致分支。

**公开观察**另比较真实玩家此时可见的资源、意图、牌区知识、已知卡牌/位置、公开摘要、行动约束；当前公开信息必须足够，不要求公开完整内部状态。完整模拟器存在隐藏变量不等于投影应泄漏它们。

在共同逻辑边界比较：开局/进入房间、产生决策点、每个外部动作结算、暂停/选择续接、回合结束/开始、死亡及战斗结束后余效、奖励、房间返回、幕和Run终局。不同后端函数/调度微步不机械一一对应；游戏有影响的事件、hook/修正阶段顺序单独规范化核对。整数/布尔/枚举/顺序精确比，decimal按来源数值及舍入语义精确比；不靠全局容差掩盖中途舍入，时间戳/UI展示等排除项须显式版本化。

内部状态不逐个私有实现字段硬比，比较有规则含义的可追踪状态和各自不变量。参考RunRecorder可供可读展示，但其大小/内容ID快照不能代替以上完整差异测试抽取。优先通过现有公共API和RngDiagnostics读取；确需补参考薄诊断，保持原规则/随机调用不变、更新固定摘要，并跑针对性回归证明诊断开关不影响结果。

### 6.3 首差与参考错误

每case输出passed/diverged/unsupported/invalid_fixture/reference_deviation/source_gap/timeout/fault；只有passed计通过，reference_deviation另以原版来源验证结果统计，不隐式合入参考通过率。未实现/缺来源/超时不会变成skip通过。

首个差异报告至少有case/版本/seed、动作前缀、第一次不同的路径/值、最后一致边界、事件顺序和随机调用前缀、两侧完整诊断位置、原版源定位及复现命令。缩短复现只能在独立诊断case中保持首因，不换种子、不补抽/删抽、不重新排序候选池。先确定首因再修下游。

差异裁决以`sts2/`为准：本项目错误→修core/base；参考错误→保留最小复现与基于源码的针对性检查，登记reference_deviation，不照抄错误；版本错→修基线输入；来源不足→保持开放，仅阻塞相关内容。既有参考README/历史报告需重新核对，不把已修项重复派单。默认不修改参考规则；确需独立修参考时留单独差异及验证记录，不用双方同时改golden自证正确。

### 6.4 差异测试作为必过测试

严格test接收版本化suite定义，定义必测case ID、适用内容/变体/机制、生产构建与配置、比较维度、预期终点及固定seed/语义动作。运行清单必须来自定义，不能从“本次成功导出的记录”反推。新增正式内容默认绑定到regression；允许相关机制共享参数化测试用例，禁止每张卡复制运行时或再写一份模拟规则。

必测case只有实际执行且满足全部断言才通过。缺case/缺两侧记录/参考未加载/零案例、unsupported、invalid_fixture、source_gap、异常、首个差异、超时、错误终点或应比较字段没有实现抽取，均使test返回非零。作用于实现覆盖的case不能被执行者移出suite、标optional、缩短到首个差异前、改seed或仅减少比较字段来变绿。明确尚未实现的未来内容保留在最终suite/完整来源范围；日常regression可分范围执行，但结果必须标明范围，不能用定向子集关闭整体任务。

reference_deviation本身不是通过理由。确有参考错误/版本差异的窄case，必须固定两侧标识、源定位和最小复现，执行本项目的source-backed预期断言，并断言参考仍只出现登记的具体差异及范围；意外新增差异、登记过期、来源不足都失败。结果单列source_adjudicated，不记双侧passed；阶段关闭仍由负责人核对。不能把一个“种子派生不同”的登记扩展为忽略所有随机或整局差异。参考完全缺能力时记blocked_compare并继续不受影响的实现，该项仍未取得差异测试验收。

每个case从两侧实际执行取得结果，不把base输出复制成reference，不自动更新golden。固定reference记录仅作为绑定源码/构建摘要的回归缓存；标识变化或新case须重新执行参考。原有比较器故障记录自检直接复用，并确保严格入口能拒绝缺记录、未支持和零执行，避免只检查“比较器会找差异”。

base侧工具和Host使用同一正式生产RuleSet/开局构造。机制fixture可在明示的受控初始化阶段构造边界状态，动作阶段仍执行真实规则；正常整局case全程禁止改HP、牌组/奖励池、RNG状态或直接跳房。参考需要选牌/事件决策注入时，只补薄测试桥接/诊断，不改游戏规则或随机调用，并用相同输入证明诊断开关不影响结果。

提供`tools/differential/test-env.ps1`统一运行入口，默认Suite为regression：一次构建后执行现有Engine/Slice/net检查和对应严格差异测试suite，任何步骤失败传递非零退出码。这成为默认环境测试命令，并接入已有CI（如有），无需新增测试框架。开发者可直接执行定向test减少反馈成本，但交付不能只交旧本地检查全绿。生产core/base/net不新增参考依赖。严格入口运行后输出必测/执行/双侧passed/source_adjudicated/失败/阻塞数量、缺失维度、来源和首个差异。统计按实际受检效果/分支记录，仅在状态中出现的卡/敌人ID不算效果验证。

### 6.5 开发顺序与验证成本

第一步复用现有七个受控案例打通严格入口及正式源构建，然后立即在同一条线上补初始洗牌、弃牌重洗、回合/敌人行动、头槌中途选牌、死亡余效、Feed永久成长跨房间等必测case。后五个旧unsupported不得永久作为“非必测”绕开；它们是待补适配/随机接入的明确缺口。每个新增机制族在本批加入可区分正确/空实现/关键错误的两侧case，普通/升级及适用随机/hook分支用参数化输入覆盖。

有明确语义输入时先登记case并确认因目标缺口失败，再实现至通过；旧能力迁入严格入口可以直接复用已有case。开发红状态允许存在，但不能宣称已交付。每批选择能解除一组实际内容/整局路径阻塞的机制族，连续补到正式入口和相关差异测试通过，不将“只增加解析字段/测试/报告”当成一批产品交付。

修改时跑受影响case、共用机制相关case和必要既有回归；机制族交付时跑完整regression。ironclad-run在整局路径变更/阶段交付时执行，full-singleplayer在整局共享机制重大变更及最终候选时执行，不每张牌重跑120局。构建和根AGENTS要求的规则检查按相应改动执行一次；已有结果无新改动/失败/风险不重复刷新。默认只保留摘要，失败保存两侧轨迹与首个差异；完整胜利/死亡交付轨迹单独保留。

## 7. ENV-01：原版兼容随机数与数值

core提供通用、显式可选择的随机算法/有界映射/流初始化能力，保留原默认Profile以免破坏既有测试场景。base提供STS字符串seed转换、Run/Player/内容随机流布局、池/洗牌算法及调用顺序；标识绑定算法/映射/派生配置，不把所有STS派生规则硬编码进core。

对照`sts2/`及参考MegaRandom/Rng/RunRngSet/PlayerRngSet：初始化、整数/浮点/加权抽样、边界、洗牌、派生流、不同流不干扰、计数推进、观察不消费随机数。记录每个调用的流、操作、参数、消费计数及值，工具只读。使用参考普通顺序模式；禁止CreateKeyedForLabels/CloneReseeded、额外随机抽取或换seed把差异抹平。内部精确快照可用于测试，不开放net回退。

同步验证数值：来源decimal中间结果、各种修正阶段、负数、截断/取整、乘加顺序、溢出/边界。Engine已有Fixed能力应复用；不能认为默认FixedScale=2必然满足所有规则，按源精度声明并覆盖中间舍入反例。通过后随机战斗/地图/奖励才进入严格同种子差异测试。

交付兼容Profile、源定位/已知向量、真实原版调用序列对照和双模式回归；不只验证“各自可复现”。

## 8. ENV-02：正式DSL与完整战斗规则

复用当前纯 DSL 包和共享机制，按实际依赖补齐内容并接入独立比较。规则放在各领域模块，不恢复 CombatSlicePackage 或 C# 玩法工厂。正式 source 按精确文件／内容摘要加载，缺依赖显式失败；不为拆分文件重写已验证的规则。

覆盖费用/X/资源与条件，所有目标/选择，牌区/抽洗/已知位置，生成/复制/变牌/升级/附魔，手动/自动/重复出牌共同生命周期，Power/药水/遗物触发与数值修正，敌人动作图/意图/召唤/阶段，死亡/最后击杀后余效/胜负结算。确认单实例变量、公开历史摘要、临时与永久归属、跨实例监听器顺序。

enemy/potion/relic/encounter/角色等正式内容走base前端/受控算法，新增语法按模块约定声明。不将所有领域算法塞到core，也不将每种复杂效果留成永久C#专用旁路；规则库可有可追踪领域算法实现，但最终经同一类型化状态/调度/决策执行。

每批以“一个完整机制族+实际内容+Engine加载+能区分正确与错误实现的普通/升级检查+差异测试”为交付，复用现有回归及原检查的判断意图，不把同逻辑实现两遍算独立验证。包含两种修正同时作用、选择中断后触发、同定义不同实例、末敌死亡后继续效果等真实组合；不追求组合穷尽。

## 9. ENV-03：Ironclad完整整局，中间可见交付

正式运行从角色/seed/进阶开局，经原版地图生成、遭遇池、所有房间/古代人、奖励/选牌、商店/营火/宝箱、事件战斗嵌套/返回、幕转换、最终事件与真实胜负结算。控制台能一路展示并按脚本/合法公开规则策略推进；两房间人为场景不抵此交付。

永久状态写回须覆盖 Feed 成长后的 Run.MaxHp、HP/金币/牌组实例与升级/遗物/药水槽/附魔及相应整局计数。修复与验收进度只看[行为要求](environment-completion-and-differential-v1.md#env-t02)，不将旧版“MaxHp 未写回”的发现持续当作当前状态。战斗复制、临时生成牌、卡牌变量及房间/事件局部状态按原版生命周期隔离，事件里的战斗后回到同一事件，最终房间击杀奖励完整结算再终止。

用参考普通顺序模式记录可复现整局决策，base按同脚本逐步执行，比较地图/候选池/奖励/商店/房间及永久状态，不只比最终胜负。关卡上限/故障/超时单列，不能作为死亡或胜利。Ironclad正常开局至少有真实死亡及跨全程胜利的可复现脚本；胜利脚本可来自既有参考/原版记录，不需要训练新AI，不以加血/无敌制造正常开局验证记录。难以取得时记录未完成，不能降低验收。

ironclad-run是自动测试suite，固定进阶0的8个seed=`ENV-IRONCLAD-{i:02}`（i=0～7），预先登记配置和只读公开决策策略/脚本，以同一语义选择逐决策比较至真实终局。全部8个case必须运行并满足严格约定。该矩阵之外还必须固定至少一条完整四幕胜利及一条真实死亡脚本并加入suite；胜利脚本先通过参考普通顺序运行获得或来自原版记录，再固定给本项目回放，不能仅靠8次早死交付。所有地图/战斗/奖励/房间/幕转换以及最后击杀余效进入比较；每种必需房间及非平凡长期状态另用定向两侧case补覆盖。罕见房间的测试场景不抵正常胜利。

该阶段同时提供公开Host的正常开局至完整胜负轨迹，规则/内容/Profile标识与差异测试base侧一致；公开合法选择和所需观察缺失也不能验收。内部测试与公开烟测共享正式构建，不能分别交两个行为不同的“完成版本”。当前长任务持续推进到ENV-04～06，不在Ironclad阶段自行宣布整个项目完成。

## 10. ENV-04：五角色与全量单人可达内容

沿ENV-00来源范围扩Silent/Regent/Necrobinder/Defect及跨角色/通用内容。覆盖中毒/弃牌等角色机制、星星与锻造、召唤物/两阶段失血、充能球/集中等各角色实际机制，具体以源清单为准，不能只加角色起始数值。共享机制进base规则库，core只补可复用能力。

所有进阶变化及原版四幕/遭遇/事件/古代人进入生产构建，不能只有单独测试能手工注册。每个内容至少有能区分空实现/关键错误的行为case与源定位；每个适用普通/升级分支、随机规则或非平凡hook有覆盖。来源是空实现也需注明，UI空方法不能推断玩法全空。

每个角色正常开局都需完整多幕胜利及死亡验证记录；单独设置状态的测试场景补罕见房间/机制覆盖但不抵正常整局。参考缺内容时按原版实现并保留以源码为依据的检查，不把缺内容继承到本项目。保留完整清单，任何一类缺失则完整环境未关闭。

## 11. ENV-05：完整公开接口和正式出口

学习暂缓不代表net可以永久只有开发场景出口。复用Host/client/共享约定，通过命名生产构建`base-spire-singleplayer-v1`公布完整环境标识和功能；配置角色/进阶/seed，不能继续沿用默认开发场景或作者Profile标识。具体CLI/Profile参数由执行者在ENV-00时登记并保持一致，不再把开发开关排列当完整场景配置。

公开状态覆盖角色资源、敌人/Power、待选牌/选项、场景/地图/奖励/商店/营火/事件/古代人、长期资产、当前公开摘要和牌区知识。候选由规则包当前决策生成，避免net另写一套合法性规则。保持持久不透明句柄及不可见创建不泄漏、隐藏顺序不能影响公开编号；头槌直接通过当前抽牌堆已知卡牌与位置表达，不由AI记历史。

全流程真实stdio→客户端→合法动作→终局→公开轨迹离线校验/重编码；对一致换名及隐藏扰动核对投影。新增类别字段在现有L0可表达时复用，不无必要改协议；声明变化更新适用目录/Profile/容量，必要wire变更写兼容迁移。AI只补当前公开编码的约定兼容/回归，不跑学习。生产目录不得导入tools或参考实现。

## 12. ENV-06：候选版本验收、性能与真实性验证记录

以ENV-00完整来源范围作最终coverage：各项有来源/编译/加载/行为/差分或源依据裁决/Host可用，没有遗漏、无静默fallback、无未解决的本项目规则差异。单纯几百个测试绿色不能关闭此阶段。结果导出`environment-manifest.json`及`coverage.json`，绑定所有源/规则/编译器/Profile/工具版本。

最终整局种子预先固定：角色按ModelDb五角色顺序，进阶0/5/10，各8个字符串seed=`ENV-FINAL-{Character}-{Ascension}-{i:02}`（i=0～7），共120对。语义选择由唯一公开合法决策源在一侧产生脚本，另一侧回放同动作，遇首个差异立即停该case并保存；不得一侧看未来选行动，另一侧补选。死亡也可差异测试，但不能代替每角色正常全程胜利/其余进阶规则的定向验证记录；上限截断不算终局通过。

最终120对进入full-singleplayer自动测试suite，使用第6.4节严格失败约定和预先固定矩阵。先运行regression及ironclad-run，再执行一次该矩阵；每批修复只跑受影响case及必要回归，不每个原语重复全项目构建/全量120局。最终组用于环境缺陷修复并保留所有首个差异和修复历史，它不是AI保留测试集；后续AI实验重新固定独立划分。不得删失败seed使矩阵变绿。120对都早死也不能代替每角色完整四幕胜利与必要房间/机制覆盖。

每case有120秒/20000外部决策/100层保护，超限显式timeout/truncated而非规则结论；最终120对上限14400活动秒，超过保存部分结果/未完成项，不因长期目标跑无界循环。数值限制是执行保护，源规则不受强行裁切。完整coverage可以分批按内容族结算，不把所有原版变体放进每次单元检查。

性能单列measurements：Release版本、机器/.NET/配置、Engine纯结算/内容加载、投影/序列化、Host往返与完整局吞吐、最大候选/对象数、进程树RSS及长局资源趋势；观察/候选重复查询不改状态和RNG。保真差异测试与性能测量分开，参考快慢只作参照，不靠删候选/关闭hook/变随机算法取得性能。性能首次测量作为后续采样预算依据，本轮不凭空规定跨机器加速比。

真实客户端验证记录优先复用已有同版本原版轨迹，抽查随机/洗牌、复杂伤害/触发、中途选牌、末击杀余效、跨房永久成长、地图/奖励和终局。模拟器差异测试不能替代客户端；目前未找到的轨迹记为真实抽样未完成，不伪造、不擅自启动/部署游戏适配服务。可以交完整源码/参考一致的**候选环境**，但实际游戏抽样缺口须留给负责人，不能宣称已与真实游戏全量一致。是否足以进入下一AI实验由负责人评审候选及未完成项，不由执行者自动解禁。
