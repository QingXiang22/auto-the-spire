# 规则、会话与宿主的关系

文档类型：解释（Explanation）。

core 把游戏规则与驱动游戏的程序分开。一份 `.spire` 文件可以由控制台、界面或 AI 宿主运行；换一个操作来源，不需要把加分、回合或胜负规则重新写进宿主。本文说明这些部分为什么分开，以及它们如何协作。实际接入步骤见[宿主教程](../../start/first-host.md)。

## 规则定义可能发生的事，会话保存已经发生的事

`RuleSet` 包含实体类型、动作、程序、投影和规则标识。它描述一种游戏如何运行，可以供多局使用。`Session` 保存其中一局的实体实例、当前字段值、随机服务和执行进度。两局使用同一规则，不会因此共享分数或实体。

以计分小游戏为例，`Counter` 是类型，`Score` 是类型中的字段。开局程序创建出的计分器才是一局中的实例。修改这个实例的分数，改变的是会话状态；修改目标分数并重新加载规则，改变的是规则。

程序的参数和局部变量属于执行帧，用来保存“这次调用正在处理哪个实例、运行到了哪里”。它们与持久实体状态不同。动作等待回答时，执行帧保留，因此可以在同一位置继续处理。

## 动作开始一次操作，决策续接已经开始的操作

`LegalActions` 和 `Submit` 表达玩家准备做什么。动作参数是在操作开始前提供的，例如先选定要打出的牌及其目标。

规则运行到 `decide` 时，这次操作已经开始。它可能已经完成前面的效果，又需要玩家提供下一步信息。会话暂停并提供 `PendingDecision`；`Answer` 将回答写回执行帧，从暂停位置继续。

两种交互分开后，宿主可以知道是在发起新操作，还是回答旧操作中的问题。等待决策时不能再次提交普通动作，否则会把尚未完成的操作与新操作交错起来。

## 玩家观察是规则发布的事实

内部会话状态包含游戏运行所需的全部事实，玩家未必能看见它们。例如牌堆中可能有隐藏的顺序。投影规定某个角色可以观察哪些类型、字段、集合和关系，`Observe` 按这份规则生成视图。

因此换成 AI 宿主时，观察仍来自参与者视图。知道内核中存了什么，不意味着玩家应当知道什么。读取视图也不会推进游戏或改变随机结果。

## 规则库复用行为，配置选择参数

底层声明把状态、动作和效果写清楚，`procedure` 复用运行时执行的程序，`template` 复用编译时生成的一组声明。`use` 用具名参数实例化模板；导入的规则库也是 DSL 文件。

计分规则中的合法条件和结束条件都需要目标分数。把它们封装在同一模板里后，使用者只填写一次 `target`，减少条件修改不同步的问题。重复实例化会产生各自带前缀的声明；独立实例本身不会自动组成轮流行动或共享胜负，多玩家组合仍需明确规则。

使用已有库的作者主要维护 `imports`、`use` 和参数；库作者维护模板及底层规则；宿主开发者维护加载、操作来源、观察显示和接入层。需要新通用原语或扩展时才涉及内核能力。

## core 与游戏内容包的边界

core 提供通用状态和执行工具，不预设卡牌、伤害、回合或原版胜负。base 和其他 mod 使用内容接口描述这些玩法。core DSL 的计分器例子与 base 的卡牌 DSL 不是同一种声明形式。

模板的可表达范围仍受语言与扩展接口约束，不能把一个计分模板的成功运行推广为完整原版内容已支持。具体语法查[基础语言参考](../../dsl/core/0.3/language-reference.md)与[规则库指南](../../dsl/core/0.3/authoring-guide.md)；原版卡牌作者使用[内容 DSL 作者约定](../../areas/base/README.md)。

## 同一种操作可以连接模拟环境与真实游戏

规则包中的 Action 定义操作入口，具名过程负责内部执行。定义一个过程不会自动增加外部操作。

宿主通过三组接口与玩家交互：`LegalActions` 和 `Submit` 处理玩家主动操作，`PendingDecision` 和 `Answer` 处理结算中的选择，`Observe` 提供玩家所知事实。这些定义应当随规则包进入内核。

net-the-spire 的职责目标是让 AI 和其他操作者通过同一种协议操作模拟环境与真实杀戮尖塔。模拟侧的游戏语义来自上述内核输出；真实侧由本体适配器形成同样的公开事实与操作含义。

net 负责协议编码、传输，以及会话、候选句柄、重发和版本管理。按照这个目标增加可公开的新动作时，内容作者只维护规则包，net 无需逐项增加游戏专用注册。下文说明当前实现与该目标的差距。

“原样暴露”指保持公开语义，不意味着发送完整内部状态或直接序列化C#对象。公开引用可以转换成句柄，数值可以转换成规范字符串；这些表示变化应当能对应回原来的值与操作。可见性、合法条件和当前已知位置仍由规则提供方决定。

模拟 Host 已从 DSL 包声明派生公开 Profile；具体字段、决策种类与限制查[net 架构](../net-the-spire/design.md#7-公开声明与适配边界)和协议。通用内核能力与可公开的协议类型仍需分别核对。
