# net-the-spire 规格

net 向操作者提供当前公开观察与合法候选，负责协议、引用、版本、重发和会话控制。模拟语义来自规则包与 core，真实后端对齐同一协议。支持范围见[公开运行指南](../../areas/net/how-to/run-public-game.md)，具体字段见[协议](../../areas/net/reference/protocol.md)，验收场景见[共同验收](../ai-net-verification.md)。

新增内容的公开语义从规则声明派生，不要求在 net 重写玩法与合法条件。无法表示的字段或决策须显式拒绝并扩展对应协议能力；派生 Profile 不等于所有 mod 和选择类型都已支持。

## 1. 使用流程与边界

模拟训练时，调用者取得后端能力与公开目录，选择已声明的规则集和场景，启动新会话。在每个决策点，后端完成自动结算并一次性返回当前观察和合法候选。提交一个候选后推进到下一个决策点或终止结果；效果中途选牌也是独立决策点。调用者不能直接发送内部结算命令。

真实游玩时，调用者附着到适配器明确允许控制的现有单人会话，使用同一观察和动作语义。实际游玩不允许回退、读档重试；后端不能因协议支持模拟新开局就虚假承诺真实重置、种子或状态复制能力。首版真实控制不是模拟接口的前置条件。

后端忙于结算、数据不足、连接中断或动作结果不明时必须明确表示该状态。没有有效决策快照时，AI 不选动作；不能用空候选伪装一个仍在运行的决策点。断开连接、关闭外部会话和游戏结束是不同事实。

## 2. 规范要求

| 需求 ID | 触发与可观察要求 | 对应验收 |
| --- | --- | --- |
| NET-01 | 获取观察时仅返回观察者可知的事实，包括此前公开且当前仍有效的变量与位置；隐藏牌序、未揭示事件、RNG 及内部命令不得进入训练协议 | V-02、V-03、V-15 |
| NET-02 | 返回决策点时，字段、关系、候选和动作绑定表属于同一个会话及观察版本；执行时核对版本，过期请求不推进游戏 | V-04 |
| NET-03 | 使用稳定的会话内实例引用区分同名卡牌及实体；候选使用快照内不透明句柄，后端索引不成为消费端执行参数 | V-05 |
| NET-04 | 获取结构化能力时明确场景、字段、动作、控制操作、重放范围及无法观测的字段；未知与不可提供分别表示，不以零或隐藏值代替 | V-01、V-06、V-15 |
| NET-05 | 同一动作请求重发只产生一次动作提交；结果不明时可查询请求状态，不能自动重复真实游戏操作 | V-07 |
| NET-06 | 执行期间串行化同一会话的控制；成功响应意味着已取得下一稳定决策快照或终止快照，不仅是已收到请求 | V-04、V-07 |
| NET-07 | 新会话固定规则集、公开目录及后端语义配置；不兼容的目录或能力变化拒绝继续，不能中途改变训练 Gym 的含义 | V-01、V-08 |
| NET-08 | 模拟会话可按已支持的种子和场景重开；真实后端按能力附着；NoSL 执行器禁止回退和失败重试结果 | V-09 |
| NET-09 | 对无效类型、悬空引用、非法候选、超限、结算失败和不确定执行分别返回可分类错误；不静默删减候选或观察 | V-06、V-07、V-14 |
| NET-10 | 后端结果与公开事实可用于轨迹记录；记录不自动定义训练奖励，不向 AI 提供未采取动作的真实收益 | V-10 |

观察提供方负责当前事实的形成与更新。头槌置顶后，快照直接给出该卡牌的已知位置 0；抽牌、洗牌或重排后给出新的有效位置。AI 不额外记录历史或重放事件来补齐。第一阶段支持确定的离散位置，不推断概率位置分布；遇到必须表达但尚不支持的公开结构，声明限制并禁止将该配置标为完整支持。

场景列同步自[共同验收第4节](../ai-net-verification.md#4-需求与交付追踪)，该表是唯一维护源。固定前规范资产与逐机制覆盖交付见[约定资产](contract-artifacts.md)，不从设计文档存在推导 codec 或投影已实现。

扩展声明必须带命名空间、值类型、适用实体/动作和语义版本。敌人、Power、卡牌、场景、选项及玩家可见 mod 变量使用通用结构；接入新的规则集可以建立新目录，不承诺旧模型理解新内容。未适配的内容或机制应使会话启动失败，或进入明确标记的独立受限配置，不能在完整配置中静默省略。

模拟侧目录中的类型、字段形状、枚举和动作参数从所选规则集及投影派生，当前事实与候选分别来自`Observe`、`LegalActions`和`PendingDecision`。内容标识、位置单位、集合用途及终局含义等无法从通用声明推导的信息，由规则提供方补充一次，只读发布并纳入构建标识；net不得按STS名字猜测，也不得把这些补充变成另一份完整声明清单。结构无法编码属于公开约定缺口，不能通过省略已有公开事实解决。

## 3. 可见性与实现依赖

活动内核的[参与者投影](../../../core-the-spire/Core.TheSpire/Engine/Projection.cs)已经按规则包定义处理字段权限、集合标识/数量/顺序及揭示授权。模拟出口消费`ParticipantView`，net不再执行第二套游戏可见性规则。旧Legacy的完整牌堆观察不是活动公开出口依据；内部State、RNG及调试对象也不是透传对象。

公开实例 ID 也不能由隐藏排列、内部数组下标或 RNG 派生。对未获知标识的隐藏牌，不创建可区分的虚构卡牌实体。实例标识的生成、公开生命周期和可跨区域跟踪的条件必须由提供方明确，不能仅依赖 AI 不把 ID 当特征来防泄漏。

在真实接入前，应逐机制核对适配器能否获得玩家当前已知信息。某字段暂不可提供是后端能力问题，不要求 AI 通过历史缓存修复。独立编码器可使用标注为样例的公开 fixtures 开发，不受真实提供方完成度阻塞。

## 4. 范围与阶段

首版协议覆盖本机单消费端、单人会话、模拟后端及通用的公开数据结构；不要求远程服务、多租户、任意存档恢复或真实 UI 自动控制。多个独立模拟会话可以并行，同一会话内只有一个控制所有者。

先固定协议和样例，再接入已验证的模拟开发场景；完整整局和真实后端依据已验证内容逐步扩大支持范围。规则缺失报告回 core/mod，协议投影与执行问题由 net 修复，AI 表示和训练问题由 AI 修复。所有阶段分别报告“设计”“实现”“约定检查”“实际后端验证”，不以 solution 构建代替运行结果。

未定项：真实后端机制覆盖、动作完成判定方式、部署的超时/帧大小/资源阈值，以及完整原版覆盖验收条件。负责人均为项目维护者，在相应阶段启动前确定；不会把猜测写为默认承诺。

真实适配的工程参考与动作确认方案在实施工单中确定，后端边界见[架构](design.md#7-公开声明与适配边界)。参考工具不代表已实现或已验证真实后端。
