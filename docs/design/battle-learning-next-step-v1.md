预算口径：D1的max_train_actions约束训练采样的实际确认动作；validation/evaluate另列动作数，但训练命令内validation时间仍计入训练累计墙钟。修复后的恢复仍要保持正常smoke连续两轮与停下恢复的最终权重、Adam及训练位置一致；只比较训练状态，不要求实际资源消耗相等。原产物不可覆盖；没有累计账目的旧run可以查看/评估，resume应明确拒绝而不是猜剩余预算。新字段用现有版本/兼容机制，不重做模型包格式。

增加能区分故障路径和恢复预算的有限检查：一次确认后中断并核对磁盘；未提交轮次消耗跨resume保留；剩余动作不足时不超额采样；已耗尽累计时间时不启动Host/新局。允许测试中注入时钟/受控故障，不为等待超限真的跑900秒。旧D1验收192项通过不构成这些新增场景已覆盖的证据。

## 3. D2：先交可见的学习诊断

新增根目录入口，完成后在AI README提供可复制命令：

```powershell
python ai-the-spire/run.py diagnose --run artifacts/d1/train --output artifacts/d2/diagnose
```

`--run`指向已有D1训练产物，复用其配置/Manifest/模型身份校验；只诊断，不调用Trainer更新、不读取final种子、不改原run。不兼容或缺产物时退出码2。交付以下四项，打印摘要并生成`diagnosis.md`、`diagnosis.json`与可读参考对局。

1. **四策略同条件对照**：均匀、原初始模型、原候选模型、明确版本化的公开信息规则策略。固定诊断环境seed40000～40007、执行器seed=环境seed+1000000；这些seed已被负责人用于探查，不称最终保留集。规则优先出可打攻击牌，再出其他可打牌，最后结束回合；攻击牌优先公开Amount较高者，敌人目标优先公开HP较低者；其余选择与所有并列按canonical语义键排序取第一项。按当前决策合法候选返回归一化概率，决定目标也只在已发布选项中选择。记录完整规则版本/优先级，不能调用规则内核估算隐藏收益。结果若与负责人8/8胜不同，先报告实际差异，不为追求8/8改种子或规则。
2. **同局面概率探针**：按train的episodes/index.jsonl次序选最早8局，重放其中全部有合法候选的公开快照，记录初始/候选模型身份、平均/最大总变差距离`TV=0.5*sum(abs(p_new-p_old))`；对存在对应候选的局面统计结束回合概率及带剩余能量的结束回合选择。保留逐候选概率与局面定位，不能比较两条不同轨迹后称概率变化。不要把softmax概率命名为Q值或通关概率。
3. **学习信号与更新检查**：从已有公开记录、action-samples与metrics复核π/μ、G/A/V的范围和每轮分布、胜负及HP损失分量、参数分组变化、更新前后概率变化与现有梯度/裁剪数据；列明验证/采样/更新耗时占比。若这些数据不足以区分某个假设，明确“未测”，不要猜测优化器有错。没有必要为诊断重新跑32局训练或为每个内部函数写新测试。
4. **一个接续实验建议**：用可定位证据区分“任务不可完成”“表示遗漏”“学习信号不能区分行为”“采样/执行概率错配”“更新幅度或裁剪影响”等假设，注明哪些被排除、哪些仍未判定；只建议一个最小可区分实验，写出唯一自变量、固定条件、最大采样量、评价与停止条件，交负责人决定。不得把全败同回报直接判成PPO实现错误，也不得由规则基线获胜推断模型必然能在32局内学会。

D2诊断预算：最多4策略×8局=32局；每局最多128个确认动作/60秒、请求10秒；整个diagnose最多180秒、4096个确认动作、输出512MiB。命令总限额优先于每局上限。任一技术故障/未知执行保留已有事实及失败行、非零退出，不替代种子、不继续补局；使用D1.1的停止/资源处理。参考策略复用同一执行器，one-hot使选择确定，不增加特权。至少保存第一局参考策略的`episode.md`及公开EpisodeRecord，用户能直接查看怎么赢。

本阶段允许上述有限模拟评估，不新增训练实验。已存在的D1曲线/模型足够作为诊断输入，其他输入run须记录同样身份与范围。未来最终保留seed50000～50007预留，本任务不得访问；旧30000～30007已经评估，不伪称再次使用后仍是未见数据。
