## 组织与执行顺序

1. 在 `docs/development/base-spire/` 建人类手册：README 导航、两篇受控教程、按任务组织的领域操作指南、准确共享操作参考和机制解释。旧开发指南改为入口，原历史教程保留迁移说明。示例 DSL 和真实 stdio 驱动放 `docs/examples/base-dsl/`，不进入正式 base 包。
2. 先试跑人类教程。若现有 DSL 无法表达示例，缩小学习案例或回写本约定，不能用 C# 效果回调绕过。教程副本放 `.audit/`，保留正式源池与内容；报告落 `.artifacts/`。
3. 从文档生成项目 skill 与有限定位助手，再通过代表任务演练路由：已有遗物配置、未迁移 Power、房间／Run、源文件不匹配。skill 不依赖用户机器绝对路径或 DSH 凭据；业务规则仍以文档／DSL 与匹配版本的源为准。
4. 检查全部文档、skill 元信息与引用、示例阶段的真实结果；记录命令／版本／范围，完成后提交 PR。不运行与本轮无关的玩法全套或独立对拍，不宣称本轮恢复了完整游戏。

## 风险与准备度

正式`check`验证已接入的本包行为，包含TheAbacus固定6点等预期；它不是任意内容的通用验证器，不能把教程副本改成8后原样套用正式断言。教程使用已有通用Python协议客户端，在真实Host上提交合法候选并检查可见格挡；不解释或替代玩法。新内容需自己的实际判别；调试使用已存在的名称前缀，批次收尾再生成完整报告。

全部领域文档的覆盖指开发职责和恢复方法，不表示已提供全部可执行内容教程。机制尚缺时，操作指南明确先补共享 DSL 契约与行为，不把旧 C# 公共方法写成新 DSL 调用。定位缓存以 catalog 的来源／hash 为索引，状态与支持范围仍读取实际包，不在 skill 固化测试数或每批支持名单。
