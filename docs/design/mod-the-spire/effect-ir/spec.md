# 逐效果语义与职责边界规格

本特性服务内容作者与规则维护者：组合已有机制时，每条效果的参数、执行位置和条件必须保持原意，修改不应扩散到无关的组包和生命周期逻辑。用户于 2026-10-09 指定由 Codex 亲自完成；工程认领只维护[ENV-T06](../../../review/tofix/README.md#env-t06)。

## 用户场景与验收

### US1：组合效果保持各自含义

作者声明攻击 3 后攻击 7，普通形态实际伤害为 10；升级形态使用自身的两组参数。先获得资源再按当前资源计算效果，后一步必须读取前一步完成后的值。固定步骤与条件分支施加不同能力时，各自的能力、目标和层数均正确。

### US2：按顺序组合条件与重复效果

作者可以在已有支持的效果之间插入条件，条件后继续执行后续效果；可以嵌套条件和重复效果。已绑定的所选目标在同一次出牌内保持一致，随机目标仍在各次执行时抽取。正常/升级版本、钩子与选择暂停分别保留自己的语义。

### US3：维护一个职责明确的机制

效果编译只生成当前效果及其子块的结算。完整动作在其效果、钩子及牌区收尾结束后才判胜负和提交永久状态。组合已有效果时，仅需修改内容与验收案例，不增加共享卡级参数槽或组包器特判。诊断旧内容入口继续兼容。

## 功能要求

- FR-01：每个效果保留独立的类型、参数、目标、重复/条件结构与来源；禁止将两条独立数值折叠为一个卡级参数。
- FR-02：效果及条件按源码顺序执行，重复包含整个被重复块；保留空块和零次重复的含义。
- FR-03：动态数值在该效果规定的执行位置读取；目标绑定、随机消费和暂停续接不发生隐式重放。
- FR-04：固定与条件效果的能力引用独立链接，缺失引用有来源可定位的错误，不能用空效果替代。
- FR-05：普通、升级和钩子效果有独立程序；升级和长期/战斗副本复制不丢失实例变量。
- FR-06：效果与完整动作结算边界分离，最后击杀不得截断后续效果、钩子、结果区和永久状态写回。
- FR-07：当前诊断入口与已支持规则保持兼容；尚未迁移的形状必须显式标识，不把兼容转换误报为新增原版覆盖。
- FR-08：正式玩法继续使用同一个权威状态与随机服务。此次改变不得要求内容作者更换现有语法。

## 范围与假设

此次完成中间表示、效果编译与动作结算边界及必要的纵向接线/检查；不批量重写卡牌文件，不补齐所有未支持原语，不优化地图生成，不恢复训练。原版源规则及冻结契约继续有效。现有卡级显示数值、元数据可为兼容保留，但不能决定独立效果的参数。

## 成功标准

- SC-01：`3+7`、`3+3`、单次10对照分别产生10、6、10；普通/升级参数可区分。
- SC-02：固定与条件能力组合、条件位于中间、条件嵌套及重复执行均有可区分的实际行为证据。
- SC-03：动态数值读取时序、目标选择暂停、末杀后的钩子与永久提交均有验收案例。
- SC-04：组合一个已支持的新内容不增加组包器分支或共享卡级字段；职责由代码接口和检查共同约束。
- SC-05：构建、既有规则检查、实际内容加载及受影响公开出口检查通过；新增能力与未验证原版范围分别报告。
