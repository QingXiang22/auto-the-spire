# 降低规则修改的阅读与验证成本

文档类型：实施设计（Explanation）。本设计扩展[逐效果职责边界](plan.md)，任务状态只在[行为要求](../../environment-completion-and-differential-v1.md#env-t06)。

## 判断成本是否降低

用三种修改检验边界：组合已有效果、增加一个已有状态的查询、新增需要新状态的机制。记录要改哪些生产文件、是否进入规则包构建器、能否脱离全地图门槛获得有区分力的反馈。文件越少并非总是越好：语法、领域语义和运行时仍需要一致；目标是减少不相关职责和隐含前提。

逐效果程序已经使已有效果组合只需内容和行为案例，不必逐牌改规则包构建器或公开注册。动态数值/条件由`CardEffectExpressions`生成，状态绑定在`Cards/Compilation/CardCompilation.EffectState`，外部卡文件可通过作者工具验证。公共编译也已按领域拆分，准确入口见[编译模块参考](../package-compilation-reference.md)。旧步骤兼容、新字段的寿命与跨模块程序依赖仍需要明确处理；文件拆分本身不证明完整玩法或开发成本已量化改善。

## 可行方案与取舍

| 方案 | 收益与成本 | 决定 |
| --- | --- | --- |
| 提取数值/条件到 `CardEffectExpressions`，显式绑定现有字段与集合 | 保持同一权威状态；新查询不再读整份规则包构建器；不需要改变Engine或IR | 实施；保留查询构造顺序，默认规则身份必须不变 |
| 从文件读取卡牌并通过生产前端、链接器与Session做受控验证 | 修改 `.spire` 后无需重编译内容程序集；能定位解析/引用/IR/行为阶段 | 实施独立开发工具；报告控制范围，原版加载缺口仍保留 |
| 全部玩法改为通用插件注册系统 | 要迁移动作/生命周期/旧机制；增加动态注册、冲突和接口阅读成本 | 本包不实施；有真实机制需要时再设计其扩展点 |
| 一次迁移所有 `.author`、敌人/Power及奖励机制 | 多条职责同时变化，难以定位回归 | 本包不实施；按现有任务包逐族收敛 |

## 实施与验收

`CardEffectStateBindings` 只持有声明符号，`CardEffectExpressions` 只生成IR表达式。动态读数在每个效果的位置构造；不提前读取Session、不缓存状态值、不改变随机或局部槽分配。`CardCompilation`提供符号和效果能力绑定，付款与目标上下文由共享出牌模块拥有。已绑定字段支持的新查询修改前端/领域模型/表达式编译及测试用例；新状态按[现行 DSL 开发手册](../../../development/base-spire/README.md)修改声明、分组、寿命和消费者，新依赖组才调整根组装。

`tools/base-spire-dev` 接受独立卡牌文件，链接实际加载的base能力，将新增定义与base卡牌定义合并；ID冲突明确失败。测试牌组只含输入卡，不接真实地图/奖励工厂。声明、解析、降级和运行实例分别报告；未支持、引用缺失、非卡声明及执行故障返回非零。`upgraded`经升级起始牌组创建完整升级实例，采用升级费用、变量初值和适用hook；这是受控出牌验证，不代表营火等永久升级流程已验证。准确工具契约见[作者工具参考](../../../../tools/base-spire-dev/README.md)。

验收包括：示例普通扣血10/格挡2、升级扣血13/格挡3；外部文件改第二击为11后无需重编译且扣血14；缺能力引用/未支持效果/ID冲突明确失败；默认身份不变，Engine和受影响Slice全通过。完整地图失败仍如实执行并登记；不把局部工具当作完整环境、独立源对拍或性能测试。实际命令、时间和结果进入日期记录。
