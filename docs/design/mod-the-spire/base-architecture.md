# base-spire 的 DSL 规则组织

文档类型：解释（Explanation）。base 是 Engine 执行的规则包，目录按游戏领域与具体内容组织。它没有 C# 工厂、效果解释器或独立执行后端。包版本以 manifest 为准；行为要求见[内容行为约定](content-behavior-migration.md)，修改内容见[开发手册](../../areas/base/README.md)。

Engine 负责类型、状态、事件、随机、编译与唯一 IR 执行。共享游戏机制和具体内容均由 DSL 描述。简单内容使用模板配置；复杂内容可在所属模块声明独有过程、监听和私有状态。卡牌、Power 和遗物各有领域目录；实体模型在 `schema.spire`，真正共享的过程与模板在 `rules/`，具名内容按来源组一项一文件。

```mermaid
flowchart LR
    Manifest[package.json 包标识和支持范围] --> Load[Engine 通用包加载]
    Root[base.spire 与领域 index] --> Load
    Rules[DSL schema / rules / template] --> Load
    Content[具体内容：模板配置或完整 DSL 模块] --> Load
    Load --> IR[同一 RuleSet / IR]
    IR --> Session[Engine Session]
    Meta[静态公开元数据] --> Host[通用 net Host]
    Host --> Session
```

`base.spire` 显式包含各领域索引并持有唯一启动顺序。同包片段先合并声明再绑定，保留文件定位；跨包库通过 imports 组合。catalog 的 definition 已允许完整 DSL 内容模块，根入口仍独占 start／imports／包版本等顶层配置。完整模块准入不表示可以绕过显式装配、同包命名空间、纯 JSON 或未引用文件检查。

生产 `catalog.json` 只保存已加载内容的 id 与 definition 映射，不维护未实现条目、来源哈希或开发进度。完整来源标识、哈希、池成员和源排除事实由工具固定数据保存，覆盖检查将其与实际定义及行为结果分别核对。公开 `get_catalog` 仍由规则声明与 public 元数据生成；来源目录不属于公开协议目录。包加载拒绝执行型 JSON、未知字段、包外引用和未声明文件。

当前已有统一出牌、牌区、永久牌／战斗副本、Power 定义生命周期和实例修正等可复用 DSL。准确入口与限制见[当前控制流程](control-flow-modules.md)和[操作参考](../../areas/base/reference/operations.md)。卡牌正文与纯基础伤害由所属模块的唯一分派绑定表达，攻击与结果各有独立标识，费用与附魔采用独立状态及复制通知。精确边界见[行为迁移约定](content-behavior-migration.md)。

包 manifest 目前只开放开发 scope；显式 Ironclad 初态与开发战斗不代表包含 Neow、地图、事件往返和跨幕的正常 Run。旧 C# 与检查只在[迁移对照](../../../tools/base-migration-baseline/README.md)保存，生产与默认 Host 不回退。后续恢复与认领按[GitHub 任务清单](https://github.com/QingXiang22/auto-the-spire/issues/28)执行。

## 包边界与兼容要求

本表保留包迁移后继续适用的 DB-R01～DB-R13 要求。首链、首批等用语表示最小验证场景，不缩小完整环境验收范围。

| ID | 要求 | 可观察的完成条件 |
| --- | --- | --- |
| DB-R01 | base包只包含DSL与必要JSON | 文件检查仅允许`.spire`和`.json`；文档、测试、C#与项目文件在包外；加载图无脚本后门 |
| DB-R02 | 用游戏领域和具体内容定位文件 | 从根入口能到power／relic目录及具名文件；一个具体内容一个主文件；共享机制有唯一归属 |
| DB-R03 | 玩法规则由DSL维护 | 类型、字段、规则、事件发出／订阅、动作守卫、效果和流程可追溯到DSL；无C#玩法switch或回调 |
| DB-R04 | JSON只存静态数据和元信息 | 可存源目录、池顺序、包标识、支持范围和公开元数据；不能存效果指令、条件、hook或待宿主解释的DSL字符串 |
| DB-R05 | 子集与完整DSL共用语义 | 首批内容能用DSL库／模板表示；越出已声明作者限制时明确拒绝；没有第二个效果解释器 |
| DB-R06 | 正式路径只加载DSL | 默认生产启动、显式范围、开发工具与公开Host不引用或调用旧C#组包器；即使本地存在旧DLL也不回退 |
| DB-R07 | 未迁移能力在产生副作用前拒绝 | 启动前拒绝未支持场景／范围；已有会话的未支持请求返回`unsupported_capability`且不改变状态、随机游标或账本中的执行事实 |
| DB-R08 | 源范围和支持范围分列 | 工具固定数据保留完整源标识、来源和池顺序；生产目录只列已加载定义，支持行为由执行结果证明；旧C#声明／测试数量不算新DSL支持数量 |
| DB-R09 | 文件组合保持可维护性和确定性 | 同包跨文件引用可用；顺序有唯一声明来源；重复引用不重复声明／启动，循环、缺文件、重复符号、外来命名空间具名失败 |
| DB-R10 | 调试定位和标识可信 | 错误定位到实际DSL文件；相同源码语义／配置的标识稳定，语义变化改变标识；新产物不冒用旧构建标识 |
| DB-R11 | 首链具有真实状态行为 | 实际重洗后、下一张抽取前触发TheAbacus；每个有效实例增加6点无加成格挡；不洗牌、不持有或移除后不触发 |
| DB-R12 | 回退与测试变更可审计 | 逐组登记旧检查／入口的保留、迁移或退出生产范围原因；原差异测试未执行或不支持时保持非零，不包装成全通过 |
| DB-R13 | 每次实现可追溯 | 任务注明要求、修改边界、依赖、预期结果和失败处置；实际记录命令、版本、结果、验证记录和剩余问题 |

新增机制应明确输入、目标、执行顺序、状态、暂停点及结束条件。复用过程和模板；实例状态留在 Engine，调用局部值留在执行帧。出牌历史按执行记录，不能用唯一牌实例集合代替次数。只组合已有能力时不扩展 Host 或共享卡牌字段；通用语言缺口先提交最小复现。
