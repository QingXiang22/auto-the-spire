# 当前 Ironclad 卡牌整批补齐规格与实施边界

本工作包供 A 完成当前 base 内容资源中的单人卡牌。规格与职责决策由 Codex 负责人制定，执行者按下列边界连续实施。任务状态、排期、当前机制与认领只在[主清单 ENV-T05](../../review/tofix/README.md#env-t05)维护；本文定义完成条件，不能作为第二份进度表。

## 1. 范围与可验结果

用户 2026-10-09 要求一次接下全部卡牌补齐。这里的全部是当前 Ironclad 阶段已声明的卡资源，包含 `ironclad-cards.spire`、`status-cards.spire` 的单人适用卡及其必需 Power、普通/升级与有效 hook。池外 Toxic、WellLaidPlans、Beckon 同样需要对账；不能只清奖励池名单。先核对版本与原版角色/牌池归属，遗留在 Ironclad 文件里的其他角色内容保持源身份，不能移进 Ironclad 奖励池。

开工生成覆盖矩阵：源资源/声明名/正式 ID/原版 file:line/单人适用性/池成员/普通与升级/依赖能力/已有行为证据/缺口。原版池单人 85 项全保留，多人专用项按源依据明确排除；不扩展其余四角色、多人运行环境或未声明内容。原来可加载的牌也要核对完整效果、变体和 hook，复用已有验证证据，修正矩阵发现的偏差。

交付必须同时满足：

1. 当前适用卡声明、解析、领域程序、正式注册逐层对账，没有空效果或静默删 hook。确属无 play 效果的牌以原版语义说明，不用占位分支伪装支持。
2. 正式 Ironclad 单人奖励池 85 项均链接到可执行定义，缺卡为零；名单、rarity、类型与原版一致。保持 `RewardWiring.BuildPool` 的严格门槛。
3. 每张适用卡的普通/升级及必要生命周期有实际行为证据。可复用已有源受控检查；新共享机制同时覆盖零/多实例、适用分支、目标/费用/随机抽数、终局余效和临时/长期隔离。
4. 源一致性审计和本地行为验证分列；独立双侧和完整 Host 轨迹仍由 B/C 按清单接续，缺失不能称全原版验收。

本批次只完成卡牌前置能力，不关闭 T05/M01、完整 Ironclad 或五角色父项。真实药水/奖励/长期写回/地图返回仍按 T05 原合同完成。

## 2. 负责人确定的职责边界

复用[逐效果表示](effect-ir/spec.md)、[维护原则](maintainable-rule-sets.md)与[base 开发指南](base-development-guide.md)。源码读取、领域表示、IR 生成和动作生命周期分别承担以下职责，不把新卡规则散回规则包构建工厂。

| 层 | 允许扩展 | 保持的边界 |
| --- | --- | --- |
| 正式 `.spire` | 同版本原文偏差修正；完整普通/升级/具名效果 | 先对照 `sts2`；不改内容以迎合运行时，不删效果让卡变绿 |
| `SpireCardSource` / `SpirePowerSource` | 读取准确形状、类型化绑定与带源位置诊断 | 不调 Session，不在解析期缓存运行时牌区/历史 |
| `Slice/Effects` | 下列有限类型化节点、表达式和编译能力 | 不持有可变游戏状态，不处理终局/房间/长期提交，不新增含糊字符串协议 |
| `Slice/Compilation` / `Slice/Orchestration` | `CombatSchema`声明状态，`CardCompilation`绑定效果，`CardPlayPipeline`编排出牌，`SettlementCompilation`生成动作结算尾；入口查[模块参考](package-compilation-reference.md) | 效果叶不拥有付款/出牌/终局；不堆逐卡 ID 的特殊运行分支，不新增 C# 调度器 |
| 正式工厂 / SinglePlayer | 原有正式模型注册与描述派生，必要窄接入 | 不另造工厂、不开放完整 scope、不承担效果语义；身份变化交负责人核对 |

核心 engine/ir@0.3 冻结；所有新增运行态必须在 Engine 类型化实体、集合或字段中。跨模块生产修改、核心语义升级及上述范围外架构设计交负责人裁决，继续其他已独立就绪卡，不把一个受阻机制当作整批停止理由。

## 3. 有限机制扩展契约

这些是负责人作出的实现方向，执行者据同版本源细化字段名称和代码，不自行引入另一套解释器。新增字段默认隐藏；只有原版应观察的事实走现有投影。扩展前在综合交接写明源操作形状、拟用节点/共享过程及首个测试用例，然后直接实施，不为每张卡等待再派单。

### 3.1 计数、重复与牌区处理

- 保留当前 `CardEffectAmount` 的执行位置读取。新增动态重复节点持有类型化次数表达式及子程序，编译为 Engine `Repeat`；在进入循环时捕获次数，循环体仍逐效果读取活状态。X 消费使用付款边界已经保存的 PaidX，不能重新读剩余能量。
- `withCount` 新增具名词法绑定节点：在该节点执行时取计数快照，只对其子程序可见。引用需在前端校验；嵌套允许遮蔽但不能泄漏到下一张牌/下一次出牌。
- `forEachCard` 新增类型化牌区/过滤器/实例绑定/子程序节点。必须按对应原版操作确定稳定顺序及遍历快照语义；用 Engine 查询/实例状态表达。遍历时移动或消耗牌不能漏牌、重复处理或修改正在枚举的 C# 容器。
- 标签/类型/牌区计数用受限枚举与具名过滤器，归属 `CardEffectExpressions` 的运行时读取；不再向工厂增加数值/条件字符串分支。
- 选中牌与所选敌人是不同绑定；牌区处理需显式传当前迭代/选择实例，不能误用正在出牌的 cardRef。

### 3.2 复制、生成与抽牌

- Anger 的已有独立克隆过程复用。多张/其他目的牌区的复制为类型化复制节点，不用把新形状塞进现有 `clone_card_to_discard` 字符串。复制当前变体/变量/适用临时状态、保存 CloneOf、长期来源留空；新定义生成与长期复制分开。
- `generateCards` 使用源真实生成池、过滤与源随机流，实例由共享建卡过程产生；池未齐时明确受阻，不缩池或塞空卡。费用修正的范围/失效按源确定。
- `drawUntil` 复用共享抽牌、重洗及抽牌 hook，维护 Engine 局部终止条件；覆盖空牌区、无法命中、手牌容量和重洗，不绕过随机/抽牌事件。
- innate、临时费用、消耗/虚无等关键字在原有入战、抽牌、出牌/回合边界接入，内容只声明意图。

### 3.3 出牌历史与自动出牌

`PlayedThisTurn` 是实例集合，不能用它表示有重复的出牌历史。核心集合唯一性正确，禁止放宽核心约束。

为 base 新增 Engine 出牌事件实体/有序记录：至少记录源实例、出牌序号、牌类型、自动/手动方式和对应时点。每次真实出牌产生独立事件，同一实例两次出牌有两条记录。已有“本回合打过的实例集合”保留时只幂等加入；计数/筛选按原版读取事件，不用 `!= 当前卡` 排除同实例此前事件。回合/战斗重置边界按源，before/after 事件的可见性由源案例确定。

自动出牌复用共享出牌过程：接收实例、目标策略、付款模式、结果牌区策略和原因，手动动作也调用同一过程。共同过程拥有合法前置、源要求的费用/目标、before/after hook、InPlay/消耗/结果区和出牌记录。选敌策略与随机出牌机制按原版分别绑定；不默认自动出牌等于普通收费出牌，也不默认全部免费。

效果编译器只请求“执行此牌”的具名能力，不拥有 Session、不在 C# 递归 Submit。外层动作/生命周期过程在完整父效果与嵌套出牌、hook、结果区处理之后统一调用 BattleEndTail。覆盖同实例重放、X/免费模式、致命子攻击后父余效、不重复付款/触发和无可选目标；避免嵌套过程提前设置终局。

### 3.4 hook、能力与自伤

新 hook 明确事件主体、拥有者、触发卡、选中卡、时点与普通/升级程序。按实际事件边界发布，不能依靠轮询每张牌模拟触发。Power 依赖必须带同版本真实行为，不能只声明空 Power 让名字链接成功。

伤害自己的 attack 与 loseHp 分列：前者按对应源攻击/格挡/力量/脆弱/事件管线执行，后者是源明确的失去生命。Owner 和 Enemy 状态类型不同，效果编译能力显式区分自伤与对敌伤害，不把 Owner 传给仅支持 Monster 字段的过程。

十进制变量与伤害倍率按既有数值 Profile 及源舍入时点处理，禁止转整型消除诊断；如果冻结核心确实不能表达，提供最小复现给负责人，相关卡保留阻塞，继续其他族。

## 4. 连续实施顺序与成本控制

整批只开一条 A 线，同时实现一个机制；下一机制不需要用户唤起。按依赖顺序先清稳定前置，再做复杂族：

1. 正式矩阵与已有行为对账；Anger 复用。
2. 动态 repeat / PaidX、标签计数：Whirlwind、TearAsunder、PerfectedStrike。
3. withCount / forEachCard / 实例写入：PrimalForce、Stoke、FiendFire、SecondWind。
4. 抽牌/生成：Pillage、InfernalBlade；生成池若依赖未齐则留精确检查点，继续已就绪族。
5. 卡牌必要 Power、innate、变量/费用、事件 hook：Juggling、Aggression、Rupture、DarkEmbrace、CrimsonMantle、Inferno、Thrash、Stomp，以及源受控依赖。
6. 出牌事件与共用出牌过程，自动出牌/重放：Cascade、Havoc、OneTwoPunch、Hellraiser、Stampede、DrumOfBattle、HowlFromBeyond。
7. 池外卡/状态牌及完整变体审计：Toxic、WellLaidPlans、Beckon；回收此前受阻但现在依赖已齐的卡，最后对账 85 项奖励池。

必要时依实际依赖调整局部顺序，不扩展范围。每机制交付一组能区分正确与错误实现的行为和一个简短检查点到同一综合交接，长日志放本任务 audit；主清单只保留当前机制与下一成果。不要每张卡新增报告、重读全历史、重复模型大调用或每次编辑跑全量套件。

局部开发优先受影响机制检查与 base-dev 工具；每个共享机制稳定后串行跑非地图回归。整批末尾串行 build、Engine、完整 Slice、net、刷新工具后作者工作流、doc-check 与 diff-check，保留真实首个差异。身份 golden 不能由执行者迎合结果；若新增状态导致身份变化，记录新旧值与变化依据，继续独立局部检查，最终交负责人一次性复核迁移。

## 5. 交接与受阻处理

综合交接路径由派发记录固定。覆盖矩阵和每机制源/案例/日志存 audit，交接只链接。交付声明用 `ready_for_review`，不是负责人验收。给出构建、Profile、seed、变化目录/契约、所有门槛实际返回码/执行数量、覆盖分母、池对账结果、首个差异及未验证。

遇到真实核心缺口或未授权边界时，只阻塞对应族，注明依赖/最小复现/受阻卡/可继续卡。全体就绪族完成且只剩需负责人裁决的范围时可以交部分结果，不能写“全部卡完成”。没有这类阻断时继续完整批次，不在第一张卡/第一族完成后自动收尾。
