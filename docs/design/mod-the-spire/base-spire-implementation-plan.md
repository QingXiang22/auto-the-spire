本文供 base 实现者查询 BASE-01/02/03 的批次、依赖和交付方法。认领、当前状态和关闭只维护[唯一清单](../../review/tofix/README.md#当前任务)。

开始本包前，按[分工约定](../post-core-agent-assignments.md)确认跨模块责任，并按[ENV任务包](../environment-completion-and-differential-v1.md)及[实现约束](../environment-implementation-constraints.md)核对范围与门槛。活动core使用当前工程及[核心契约](../../contracts/core-engine-baseline.md)的修订；`92ccd34`／`engine/ir@0.3`是历史锚点。发现通用缺口时，按[冻结契约](../../contracts/core-engine-baseline.md)提交最小复现，由负责人决定维护。

## 3. 工作包方法与依赖

按主清单任务ID取一个已就绪工作包；目标、先后与当前认领以主清单为准。每包一个主责，一体交前端/IR/运行时/针对性检查/文档，不按同一机制文件并行。必要依赖可提前准备，但不先清全部长尾unsupported。

本节提供实现方法，不复制当前状态或派单。按任务 ID 直达对应包；算法细节查第 4 节，实际文件范围与验证查第 5 节。

### ENV-T01

**工作包**：ENV-T01：源加权随机与描述。

**开始位置**：核对已交付的描述与内容侧权重检查，接续源算法与消费者证据；是否仍需实现及当前认领以主清单为准。

**实现与可验边界**：当前均匀随机及流布局复用`run/random.spire`；完整加权分支先建立源向量与实际DSL消费者，再判断现有表达是否足够。旧SampleInt／纯Compute探针只作算法依据，不是可直接移入base的C#实现。保留源NextDouble→float、LINQ Sum的double累加后转float、声明顺序逐项减法及小于等于0命中，不能把0.4／0.6改成整数比后声称等价。真实分数权重／多候选／门槛／连续转换与流计数须有独立比较，算法及数值身份进入构建；若文本无法表达，附最小通用复现交core维护者，不在Host或工具中代算玩法。

**接续登记与验收**：回到[主清单对应任务](../../review/tofix/README.md#env-t01)核对主责、依赖、当前成果及原完成条件；实施后只更新本包状态与证据。

### ENV-T02

**工作包**：ENV-T02：结算尾与长期状态。

**开始位置**：从主清单核对已有结算尾与长期来源交付，先核对DSL的PlayDepth／AttackDepth／DamageDepth收尾与永久来源，再恢复正常房间消费者及独立双侧证据；旧CommitPermanent过程不能直接作为当前入口。

**实现与可验边界**：结算必须在完整父动作结束后提交 Hp/MaxHp 等永久变化；最后击杀不能在 Feed 余效、出牌钩子和结果区处理前进入终局。旧复核反例及后续修复自报见主清单；接续时复用已报修复，核对实际边界，不只给早提交多拷字段或取消幂等守卫。建立长期牌→战斗副本稳定来源与字段写回矩阵，区别重复定义的实例和临时克隆；验收Feed跨房、最终击杀余效及适用永久资源

**接续登记与验收**：回到[主清单对应任务](../../review/tofix/README.md#env-t02)核对主责、依赖、当前成果及原完成条件；实施后只更新本包状态与证据。

### ENV-T05

**工作包**：ENV-T05：真实地图/房间/奖励纵向闭环。

**开始位置**：从现有DSL的`run/`、`encounters/`、`rewards/`和根启动过程核对声明；地图域尚需建立，当前正常地图／Run未迁移。先设计访问阶段／父子上下文及源初始化切片，再接真实地图战斗奖励闭环，不调用旧SinglePlayer工厂。

**实现与可验边界**：子包依次为地图和房间阶段/父子上下文→战斗结束与真实奖励/选牌/跳过/容量→长期提交与合法地图后继；占位UpgradeReward退出该正式路径。每子包可从同工厂进入，不注入改血/强制清场。B/C同步登记case和公开实际选择；若内容阻塞，先补实际必需机制，不重写已正确状态机/普通队列

**接续登记与验收**：回到[主清单对应任务](../../review/tofix/README.md#env-t05)核对主责、依赖、当前成果及原完成条件；实施后只更新本包状态与证据。

### ENV-T06

**工作包**：ENV-T06：正确反伤及条件/生命周期族。

## 4. 必须按源码校准的算法细节

以下是本次规划直接核对源码发现的交接修正，执行以实际源算法为准，不能照旧 RESUME HERE 原样实现：

| 要点 | 实施约束与源码位置 |
| --- | --- |
| 普通遭遇队列长度 | `ActModel.GenerateRooms` 从弱遭遇数开始补到 `GetNumberOfRooms(false)`；Overgrowth为总计15条，其中前3条弱遭遇，不能算3+15=18。精英队列另有15条；队列库存长度也不等于玩家真实访问的房间数。见 `sts2/src/Core/Models/ActModel.cs:261,349,361,373`、`Acts/Overgrowth.cs:45,47` |
| 相邻遭遇回避 | 谓词同时检查“不共享标签”及“不是上一遭遇”，不能只预计算标签相交表。无合格项时，带谓词抓取先返回空，调用方再无约束抓取；重抽/移除/补袋与消费次数分别核对。见 `ActModel.cs:419-430`、`sts2/src/Core/Helpers/GrabBag.cs:96-124` |
| 敌人首动随机 | 初始状态已经是Move且未执行过时不转换；初始为随机分支时仍执行源转换。不能把“首动不抽数”写成所有敌人的规则；一次随机分支一抽不等于任意图遍历总共一抽。见 `sts2/src/Core/MonsterMoves/MonsterMoveStateMachine/MonsterMoveStateMachine.cs:54-80` |
| 出生生命流与开局顺序 | 工厂已传 `Niche`，不能再按过期描述当作 `MonsterAi` 或范围下限。遭遇派生、出生、意图与整幕前置消费按源调用点核对，局部独立复算不证明整局流位置一致 |
| 数值中间值 | 先核对冻结NumericProfile及源decimal反例，再实现需要的权重/乘法/修正阶段；不能用默认两位量化或double近似宣称等价。现有Profile无法表达时附最小复现交负责人，不在base绕开RandomService或调度器 |
