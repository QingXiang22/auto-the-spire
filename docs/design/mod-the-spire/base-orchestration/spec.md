# Base 规则集核心编排重构规格

归属 [ENV-T06](../../../review/tofix/README.md#env-t06)，关联T05卡牌依赖。用户2026-10-10授权Codex亲自实施，可替换base内部实现，参考sim分工降低开发上下文；core engine/ir@0.3继续冻结，参考侧保持独立。阶段、认领和验收只维护主清单。

## 成功条件

1. 词法计数由效果编译环境负责，进入/退出块、同名遮蔽及分支隔离正确，块外引用带源位置拒绝。
2. 牌区共享模块拥有创建、长期副本、克隆、移动、消耗和真实变形；变形创建独立替代实例、保留位置和入战语义，不污染长期来源。
3. 统一出牌编排拥有资源快照、目标策略、before/start/body/finish/after、结果区及次数；手动/自动复用，效果模块不拥有终局/房间提交。
4. 出牌历史记录执行事件，同实例再次出牌不冲突，次数查询按事件；回合/战斗数据有统一重置边界。掉血计数跨战斗清零。
5. 组装按能力提供类型化符号和过程，模块不依赖整份组包闭包或Session；原正式工厂/公开动作继续使用新编排。
6. 保留有效内容普通/升级、选择暂停、随机流/抽数与完整末杀余效；新增生成/抽牌/自动出牌机制提供真实DSL例子和检查；生成先支持显式完整池，不冒充完整角色池。未支持内容仍明确拒绝，不缩奖励池。
7. 局部及回归实际运行、身份迁移有依据，文档/作者路径跟随实现；完整原版双侧/正常Run未验证范围明示。

## 范围

重构base的卡牌与战斗核心流程，复用现有敌人/Power/房间内容与源数据；不重写冻结core；net只调整旧SlicePublicProfile的新增字段/内部历史处置，不改协议或玩法。不引用sim运行时，不启训练或新角色。核心能力先就绪，再接续剩余卡牌，不把本轮范围扩大为五角色全部玩法。内部类型/过程可调整，外部内容ID、动作和正确游戏语义保留。

## 反例

既有负责人探针复现：嵌套withCount读0而非外层1、块外引用接受；掉血计数换房仍1而非0；PrimalForce保留旧InstanceId。重放同实例触发MembershipConflict。上述反例必须由新模块判别修复，不能改检查去接受旧错误。

## 作者契约修复范围

### 下一回合能量

注册规则 `rules = { energyAfterResetOnce = true }` 在拥有者能量重置完成后、BeforeHandDraw之前按当前Power层数获得能量，再移除该Power实例；卡牌仅施加Power，不立即获得能量，不修改MaxEnergy。叠加累积到同一注册定义；自定义命名空间可以复用规则。被禁止获得能量时沿相同GainEnergy门控，仍移除一次性Power。战斗结束/新战斗沿既有Power清理，不保存为隐藏C#字段。第一张正式卡Outmaneuver来自EventCardPool而非SilentCardPool，普通2/升级3，均cost1。

机制与卡内容并发实施，但公共文件单一主责。Codex与DSH分别使用独立.NET artifacts-path；项目默认输出、身份golden、公开夹具与全量验收由负责人在集成窗口统一处理。此机制的局部检查使用显式牌组，不因DSH新增其他卡而依赖全包数量。

### 下一回合抽牌

注册规则 `rules = { handDrawNextTurnOnce = true }` 对齐DrawCardsNextTurnPower：回合开始、任何Power钩子前，将拥有者Power层数保存在Engine隐藏字段AmountOnTurnStart；ModifyHandDraw只允许开始时已存在且层数为正的实例参与，收益取修改时的当前层数。修正基础手牌抽取数量，再沿正常Draw过程处理NoDraw、手牌上限与洗牌；回合开始抽牌及钩子完成后移除已参与的Power实例。开始期间新创建的实例留到下一回合，不能立即生效或被提前移除。快照字段沿现有Power.Stacks的有符号范围，不能让负力量等无关能力导致回合故障。

卡牌仅施加已注册Power。Predator以普通15/升级20攻击后施加2层DrawCardsNextTurnPower接入，费用2、SilentCardPool。自定义命名空间可注册同一规则。所有层数、快照与消费状态在Engine实体中，不新增C#状态缓存或具体Power ID分支。

### 通用选牌与恢复执行

`chooseCard`编译为不可变`SelectCardsEffect`：来源、数量、资格、提示和自动选择策略与onSelected子程序分开。移动短写展开为选中牌移动，子程序还可组合升级/复制/控制流；不把每个组合编码成新AuthorStep。运行时由独立选牌模块发出已有Engine决策IR，回答后执行子程序并继续原效果程序；付款、出牌历史和结果区仅由原编排处理一次。新原版卡明确写 `autoSelect = true`，候选不足或恰好够时按原生CardSelectCmd自动选全部，零候选不提问；未写时保留旧DSL手动确认行为。数量在进入选择时读取一次并限制为现有候选数，多选使用一次引用列表决策，不重复单选。手牌上限取回失败时保持原弃牌堆归属。进一步组合与特殊范围见[原语契约](../card-primitives/spec.md)。

本包实际接入Acrobatics、Prepared、Hologram。手动弃牌触发所弃实例的 `onDiscard`，普通出牌结果与回合末移动不触发；跨实例Power监听、弃牌历史计数、Sly自动出牌、保留选择和可选数量区间仍需后续专属机制，不以本包冒充全部弃牌能力。直接检查暂停前抽牌/付款、回答后移动/继续、精确多选、空与不足候选、过滤、消耗钩子及取回上限；重复全量回归和原版独立对拍按用户本轮指令延后。

### 跨卡族公共边界

复核补充：Stampede式回合末自动出牌，每次迭代先确认战斗仍活跃且候选非空，再随机选牌。空手、不可打攻击牌或上一迭代已用尽候选，不调用Engine空集合采样、不重复出牌。牌数断言采用显式受控正式牌组，不依赖全包新增内容数量。

Power正常出牌的默认结果为None，优先于自身Exhaust或自动出牌的forceExhaust；统一结果模块移除战斗牌区归属，不销毁历史仍引用的实例，也不触发消耗钩子。非Power仍依消耗规则进入Exhaust或Discard。依据原生CardModel.GetResultPileTypeForCardPlay与CardPileCmd.AutoPlayFromDrawPile。

正式DSL允许 `target = { selectNone = {} }` 与真实空 `play = {}`；仍付款、记录出牌、执行钩子及结果区规则。无目标牌不得隐式读取所选目标，嵌套效果和条件也必须拒绝；显式owner/全体敌人效果可以无目标执行。诊断作者包和SinglePlayer共用Power声明资源枚举，跨文件链接以实际注册的Power为准，不能重复声明Dexterity或回退到名称白名单。

用户本轮追加要求：Power保留内容注册和实际语义校验，移除可复用模式对具体ID的依赖，新包保留自己的命名空间；卡牌可引用实际注册的跨文件Power。onExhaust不要求牌自身带exhaust关键词，外部消耗也经统一事件站点。参考sim的OnUpgrade增量方式：已有变量保留成长并加升级初值差，费用加定义差额，变体关键词迁移，重复升级不重复应用；新建升级实例仍使用升级初值。作者工具的升级模式必须走同一配方，并可检查注册的新Power及其行为，拒绝未实现语义不造空效果。
