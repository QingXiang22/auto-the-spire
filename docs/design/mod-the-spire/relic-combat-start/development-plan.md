# 按共享机制开发遗物

本计划用于把遗物开发拆成可验证的机制包，减少逐件重复实现。关联CORE-AUTHOR-05；当前任务、优先级、认领和下一成果只维护[主清单的遗物分组](../../../review/tofix/README.md#遗物分组任务)。本页维护拆分方法、依赖和实施门槛，行为以[生命周期契约](content-lifecycle.md)及各领域契约为准。

## 分组依据

2026-10-18基于`7ff95ca`／PR #23，对catalog中257个未迁移且未排除的遗物提取源override方法和领域命令；扫描产物在`.artifacts/relic-group-plan/source-hook-inventory.json`。这是源码入口初查，不是257件完整语义复核或支持证明。来源297项、1项Deprecated排除及原ENV/W保留；分组中的名字是候选例子，不构成新的内容分母。

一个遗物选主要归属，其他效果记依赖。判断能否同批开发时，依次比较：

1. **触发和顺序**：拾取、开战、资源重置、抽牌前、出牌前后、房间进入和奖励生成分别处理。只因都调用Upgrade就放在同批，会漏掉奖励展示或回合重置。
2. **被修改的对象**：永久牌、战斗副本、奖励候选、库存实例不能混作同一生命周期。获得或复制的完整操作由原领域拥有。
3. **状态与寿命**：无状态修正、每回合／每战／整局计数、一次消耗及移除清理分别约定；能力私有状态不堆进公共Relic。
4. **随机与决策**：完整StableShuffle后Take与逐次samplePick并不等价；原生选牌及取消不伪装为随机选择。需要玩家决策的内容另保留暂停续接验收。
5. **可运行的依赖**：同组只有参数差异时共享模板；触发顺序或外部能力不同则拆成子包。后排只保留方向，接手时再细化，不预先建立所有未来模板。

## G04：回合开始资源

按同一个AfterSideTurnStarted站点分成三个子包：Candelabra／Chandelier／VeryHotCocoa配置指定回合回能模板，Cocoa保留源<=1条件；FakeHappyFlower配置跨战模5计数；Sai新增每回合无加成格挡模板。复用GainEnergy／GainUnpoweredBlock，不改主流程、core或Host。先明确源条件与计数寿命，再注册五份use配置、公开身份和实际行为见证。

复用原回合检查中的移除／熔化及持有者隔离，用表驱动覆盖新增数值，机制判别补NoEnergyGain抑制但计数仍归零、跨战计数与重新获得重置、同定义不同实例、Sai与Anchor／HornCleat以及敏捷／脆弱的组合。公开stdio连续执行实际回合并跨战观察；定向检查后集成一次最终包行为与受影响公开检查，记录来源hash及包身份。新增共享入口的准确参数见[生命周期契约](content-lifecycle.md#回合开始资源dsl-relic-content-06relic-g04)。

## 依赖和验收策略

主清单中P1优先消化已有监听／资源／升级能力能独立交付的组；P2接新跨域接口和正常来源；P3保留依赖较多或仍暂停的域。同为P1时，G01先验证随机永久选择，随后G19复用简单拾取能力，再按G04→G05→G06补已有战斗监听消费者；若源复核揭示新依赖就拆子包并调整主清单。表中同组不表示一次实现所有候选，每批只认领一个完整可运行子包。尚未就绪的组不阻止其他已就绪组。尚未确定主要机制的剩余条目归G20复核，不混入角色／召唤暂停组，也不从完整来源中删去。

Egg组必须同时说明奖励生成后展示、商店创建、加入永久牌组前修正及NoHookUpgrades；不能只监听CardObtained便算完成。伤害组区分基础加法、乘法、最终失血及防止死亡；房间组需要真实房间上下文；角色、召唤和复活保持既有暂停，当前规划不授权恢复。

每批共用机制判别，参数差异用表驱动；每个正式definition仍要有实际执行见证。独立固定源向量可证明局部随机顺序，不代替双方正常Run；公开stdio证明真实投影和决策，不能代替原版双侧。来源、定义、行为、独立比较和正常可达始终分列。

出现以下证据时重排：源方法比预期多出一个效果阶段；需要未支持的Power／附着／资格；随机流或稳定排序不符；共享状态无法按实例或调用隔离；公开候选无法表达决策。只退回受影响子包补契约，继续其他就绪工作。每批最终记录实际接口、版本、命令、结果、未验证和下一动作，状态只回写主清单。

## 规划自查

本次由Codex `/root`自查，没有派出独立agent。发现并处理三处风险：随机升级与选牌升级拆开；Egg的三处消费者单独成组；拾取洗牌明确消费完整候选的n−1次随机，即使最终只升级两张。G01依赖均已有实现入口，未发现需用户决定的新业务规则；其他组仍需逐批核对完整源方法，不把方法名聚类当成设计完成。
