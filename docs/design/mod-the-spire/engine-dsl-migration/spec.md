# 纯 DSL base 包规格

关联任务：**CORE-AUTHOR-05**。规格版本：0.1，2026-10-18。本文定义需求与验收；[设计](plan.md)定义目录和接口，[路线图](../../../roadmap.md)连接实现与检查。状态、认领及下一项工作只维护在[路线图](../../../roadmap.md#近期队列)。

## 目标与决定来源

用户要求降低内容查找、维护和更新成本，并在本次对话中明确以下边界：

| 决定 | 来源与确定程度 | 对本次交付的约束 |
| --- | --- | --- |
| Engine为主体，几乎所有游戏规则由完整DSL实现 | 2026-10-18用户明确指令 | C#生成IR不能作为完成DSL迁移的证据 |
| Spire是完整DSL的子集 | 同日用户明确指令 | 内容组合不得依赖独立的C#效果语义 |
| base严格只使用DSL和必要的JSON | 同日用户明确指令 | base目录不得保留C#玩法、程序集或外部脚本实现 |
| 目录即后续DSL的长期目录 | 同日用户明确指令 | 按游戏领域和具体对象组织，不能沿用Compilation／Runtime的技术分层 |
| 直接切换；未迁移玩法明确报未支持，接受暂时功能回退 | 同日用户对迁移方式问题的明确选择 | 不保留自动回退旧C#规则的生产路径；不假装仍支持原范围 |
| 先有规格、设计与记录，再依任务实现 | 同日用户最新纠正 | 记录既有改动并复核准备度；后续工作要能追溯到要求和验收 |

目录细节、清单字段和首批切片是本规格下的工程设计，见plan；它们不应被表述为用户逐项指定。

## 范围与完成边界

本次交付包括最终目录规范、纯文本base包、通用加载能力的必要补充、至少一个完整DSL机制链、Host／开发工具的纯DSL接线、明确的未支持报告、迁移覆盖清单及验证记录。

第一份可运行产物限定为遗物实例生命周期、实际重洗／抽牌与TheAbacus触发的开发范围。它不是正常Ironclad开局，也不承诺首幕、完整Run、原版随机布局或全部遗物。完整游戏目标、原ENV/W分母与独立对拍要求继续保留；用户允许功能回退，不等于删除这些要求。

首批之外的牌、Power、遗物、敌人、房间和整局流程保留源身份与迁移去向，按领域后续恢复。不得把旧C#实现移到另一生产程序集后继续执行来宣称base已纯DSL。

## 术语

| 术语 | 本规格中的含义 |
| --- | --- |
| Engine | 通用类型、状态、规则编译／链接、唯一执行器、事件、选择、随机和观察能力 |
| 完整DSL | 能表达游戏模型、规则与流程的统一语言；编译为同一IR |
| Spire子集 | 完整DSL之上通过库、模板和作者限制形成的内容写法；相同程序不具有另一套执行语义 |
| base包 | `mod-the-spire/base-spire/` 下正式分发的DSL及静态JSON数据 |
| 宿主 | 加载、会话配置、IO和协议适配；不实现卡牌、Power、遗物或房间规则 |
| 迁移对照 | 冻结的旧源和测试依据；不属于base分发、不成为生产依赖或运行回退 |
| 未支持 | 请求能力尚未实现，明确拒绝；不构造替代内容、不返回空成功、不静默删池 |

## 要求

| ID | 要求 | 可观察的完成条件 |
| --- | --- | --- |
| DB-R01 | base包只包含DSL与必要JSON | 文件检查仅允许`.spire`和`.json`；文档、测试、C#与项目文件在包外；加载图无脚本后门 |
| DB-R02 | 用游戏领域和具体内容定位文件 | 从根入口能到power／relic目录及具名文件；一个具体内容一个主文件；共享机制有唯一归属 |
| DB-R03 | 玩法规则由DSL维护 | 类型、字段、规则、事件发出／订阅、动作守卫、效果和流程可追溯到DSL；无C#玩法switch或回调 |
| DB-R04 | JSON只存静态数据和元信息 | 可存源目录、池顺序、包身份、支持范围和公开元数据；不能存效果指令、条件、hook或待宿主解释的DSL字符串 |
| DB-R05 | 子集与完整DSL共用语义 | 首批内容能用DSL库／模板表示；越出已声明作者限制时明确拒绝；没有第二个效果解释器 |
| DB-R06 | 正式路径只加载DSL | 默认生产启动、显式范围、开发工具与公开Host不引用或调用旧C#组包器；即使本地存在旧DLL也不回退 |
| DB-R07 | 未迁移能力在产生副作用前拒绝 | 启动前拒绝未支持场景／范围；已有会话的未支持请求返回`unsupported_capability`且不改变状态、随机游标或账本中的执行事实 |
| DB-R08 | 源范围和支持范围分列 | 源目录保留原身份、来源和池顺序；旧C#声明／测试数量不算新DSL支持数量；无空声明补分母 |
| DB-R09 | 文件组合保持可维护性和确定性 | 同包跨文件引用可用；顺序有唯一声明来源；重复引用不重复声明／启动，循环、缺文件、重复符号、外来命名空间具名失败 |
| DB-R10 | 调试定位和身份可信 | 错误定位到实际DSL文件；相同源码语义／配置的身份稳定，语义变化改变身份；新产物不冒用旧构建身份 |
| DB-R11 | 首链具有真实状态行为 | 实际重洗后、下一张抽取前触发TheAbacus；每个有效实例增加6点无加成格挡；不洗牌、不持有或移除后不触发 |
| DB-R12 | 回退与测试变更可审计 | 逐组登记旧检查／入口的保留、迁移或退出生产范围原因；原对拍未执行或不支持时保持非零，不包装成全通过 |
| DB-R13 | 每次实现可追溯 | 任务注明要求、修改边界、依赖、预期结果和失败处置；实际记录命令、版本、结果、证据和剩余问题 |

## 验收场景

以下场景是实现前的验收定义，不表示已经运行通过。固定输入由执行任务登记，不通过换seed挑选成功。

| ID | 初态与操作 | 预期结果 | 覆盖 |
| --- | --- | --- | --- |
| DB-A01 | 向base包放入`.cs`、`.dll`或执行脚本，或让生产项目引用迁移对照 | 包／依赖检查失败，报告具体路径；不因文件未加载就放行 | R01、R03、R06 |
| DB-A02 | 维护者从根入口查TheAbacus与一个已迁移Power | 能定位领域索引、主定义和共享规则；Power尚未迁移时目录明确记录源身份，不能伪造可执行定义 | R02、R08 |
| DB-A03 | 把一个同包规则拆为schema、过程和内容文件；重复引用一片段 | 实际加载／执行结果不变，只启动一次；错误仍指向片段 | R09、R10 |
| DB-A04 | 加入循环引用、缺失文件、重名声明或其他namespace片段 | 加载失败且定位相关文件；不跳过错误文件 | R09 |
| DB-A05 | 启动旧`legacy-slice`、`formal-dev`或未迁移的单人scope | CLI明确返回未支持和非零；没有会话被创建；协议内请求使用既有`unsupported_capability` | R06、R07 |
| DB-A06 | 抽牌堆空、弃牌堆非空，持有TheAbacus，执行已支持的抽牌操作 | 实际转移与洗牌完成后增加6格挡，再抽下一张；一次重洗只触发一次 | R03、R11 |
| DB-A07 | 抽牌堆非空／两堆均空／无该遗物／移除后再次重洗 | 各场景均不因TheAbacus额外加格挡；遗物不同实例不串计数或有效性 | R11 |
| DB-A08 | 用同一规则模板增加另一份只改数值的内容配置 | 只改DSL／静态元数据及必要案例即可加载执行，无C#效果种类或按ID分支变更 | R03、R05 |
| DB-A09 | JSON加入效果、条件、hook或可执行字符串字段 | 严格schema校验拒绝；未知字段不静默接受 | R04 |
| DB-A10 | 新DSL包仅迁移首链，读取源目录与公开能力目录 | 完整源分母保留；支持目录只包含实际迁移部分，旧91件C#声明不被算作91件DSL已支持 | R08、R12 |
| DB-A11 | 通过公开路径describe→catalog→start→step→observe执行首链 | 读取同一DSL产物；动作和事实由声明派生；隐藏状态不进入公开载荷 | R06、R10、R11 |
| DB-A12 | 执行旧完整对拍suite，尚无迁移适配 | 明确未支持／未执行并保持非零；新的局部迁移检查通过不能覆盖这一结论 | R12、R13 |

## 约束与未决细节

继续使用当前仓库SDK与唯一Engine执行器，不修改独立参考玩法，不恢复AI训练，不创建第二个调度器。首批复杂计算不默认豁免为C#或Lua：本次base仅DSL／JSON；未来如确有无法表达的计算需求，先记录通用语言缺口再决定处理方式。

首批开发scope不宣称原版随机布局等价；其实际随机配置必须在包和公开描述中写清。原版排序、流布局和完整自动出牌尚未迁移时，对应能力保持未支持，不能仅因共享AfterShuffle而声明自动出牌已恢复。

用户关于切换方式的决定已取得，不需要再次询问是否允许功能回退。工程细节按plan评审；发现超出这些已确认边界的新业务选择时，才记录具体问题。


## 内容模型迁移验收补充（2026-10-19用户授权）

复用R01～R13和既有完整ENV/W范围。正式catalog定义可承载完整DSL内容模块，保留同包、显式装配、根入口属性与纯文本边界；简单use配置保持兼容。具体Power自行拥有修正／反应／寿命与私有状态；施加按已登记定义执行，不由调用方kind选择行为，未知定义在创建／效果前失败。当前已有实例合并、负层、到零、临时寿命及有效监听应有区分验证，不把目录存在算支持。

同一攻击变量的定义／升级／执行／读取使用一个权威值；复杂卡牌独有规则归其模块，共用的领域操作仍只有一份。Rupture的待结算状态归其模块，并验证嵌套／重复／结束边界，不向公共CardPlayRecord添加新专属槽。

完成迁移后单独新增SelfFormingClay与其Power，保留来源及实际运行见证；在该新增前固定树身份，实际统计生产改动，目标是在新增模块／装配／来源与必要公开元数据之外不改共享流程。实际开发若暴露既有共享契约错误，必须记录首轮失败及额外修改面，按源修正并补判别；修正后在隔离的迁移基线重新接入内容，不能隐去这部分成本。再仅改新内容的一个数值，在隔离副本用显式预期确认生效。此证据证明当前场景修改面减少，不外推全游戏工时或独立正确性。
