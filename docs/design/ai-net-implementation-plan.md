# ai-the-spire / net-the-spire 接口实施计划

本文供 AI/net 实现者查询阶段依赖、技术边界和退出条件。执行范围、负责人、优先级及恢复条件只在[GitHub 任务清单](https://github.com/QingXiang22/auto-the-spire/issues/28)关联的工单维护；技术阶段表本身不构成派单，也不证明对应能力已经交付。

先读[项目规范](spec.md)，再读 [AI 规范](ai-the-spire/spec.md)及 [net 规范](net-the-spire/spec.md)。按[文档导航](../README.md)找到各问题的唯一主约定；不要将旧评审建议自动当新规范。

四模块的编码顺序、core/base-spire 前置及首批联通目标以[相关规格](spec.md)为入口；本文保留 AI/net 的详细任务和退出验证记录。

下文 A/N/L 编号保留技术要求的定位作用，不作为当前工单编号，也不表示现有实现需重做。受控随机策略与数据设施不等于学习就绪；AI 工程和实验的恢复按总任务中的触发条件安排。

## 1. 阶段与退出验证记录

| 阶段 | 进入条件 | 交付与退出验证记录 |
| --- | --- | --- |
| E0 公开样例与确定性编码 | 首阶段约定范围/精度配置确认；P-01 资产及 Python 参考检查通过 | catalog/snapshot fixtures、Manifest 持久化、校验、数组/批处理、约定检查；不依赖后端或 C# 原型、不宣称能玩 |
| E1 模拟接口端到端流程 | E0 约定通过；所选规则开发场景有行为测试结果，机制清单及公开事实有可信来源 | C# net 约定/模拟适配/stdio；Python client；N-02 覆盖表与实际投影验证记录；可见性、幂等及版本验收 |
| E2 可学习短任务 | E1 稳定、V-15 公开事实充分性审计完成；Training/Reward/Preference/Model/Executor/CapacityProfile、目标机器预算、晋升指标/置信要求与种子拆分在进入 E2 前固定 | 共享表示基线、概率评分、近期策略 PPO、评估与模型包；学习曲线和 CPU 基准，未改善则报告失败 |
| E3 整局与内容扩展 | core/mod 对目标范围有行为测试结果；覆盖表证明所需公开结构可表示，新增机制完成 V-15 | 分批固定的新 Gym、覆盖/分布清单、保留种子评估及晋升；登记重复评估/重训成本 |
| E4 真实后端与部署 | 所需公开事实、候选语义、完成信号和控制权已核对；模型通过目标机器预算 | 真实适配差分、NoSL 控制、不可变模型包、新局晋升；能力不足时停止或换明确的受限配置 |

阶段依赖：E0 → E1 → E2；E3 另依赖规则/内容覆盖，E4 另依赖真实适配。E3的规则/内容工程可在E1后独立推进，不要求先证明E2学习改善。E2是实际学习实验验收条件，模型/学习器工程可按第4节先完成。E0 的样例并非真实规则验证记录。一个阶段通过不能代替其他阶段通过。

## 2. 第一批：给编码实现者的任务

共用任务 C-01 由协议负责人维护 [规范资产](net-the-spire/contract-artifacts.md)，拆为两步：P-01 交付机器 schema、不变量、规范化/decimal 参考算法、独立正反例和 Python 检查；N-01 再交付 C# contracts，并完成两端规范字节/摘要与拒绝行为的复核。A-01 只依赖 P-01，独立编码不等 C# 原型。两步均完成才满足 C-01 和协议固定的双端要求；任一步均不依赖游戏运行。

负责范围为 `ai-the-spire/` 与该模块必要文档；不改 core、DSL、内容或其他人的改动。建议包 `ai_the_spire/encoding/`，标准库；依赖为批准版本的 [net 协议](net-the-spire/protocol.md)和[编码约定](ai-the-spire/encoder-design.md)。

| 任务 | 依赖 | 实现内容 | 完成判据 |
| --- | --- | --- | --- |
| A-01 | P-01；无后端或 C# 依赖 | 从同一规范生成/校验 Python contracts、十进制 codec、fixture 目录 | 精确键/声明/类型/不变量严格校验；战斗、待选牌、地图/选项、Power/扩展变量样例各有独立预期 |
| A-02 | A-01 | build/save/load Manifest，固定排序、索引和变换 | 同集合不同注册顺序一致；旧字典能原样恢复，错配明确报错 |
| A-03 | A-02 | 当前快照、字段、内容状态、引用、牌堆和候选校验 | 已知零/unknown/unavailable/not_applicable 区分；离散位置和超限错误完整 |
| A-04 | A-03 | tensorize/collate、字段分通道、引用映射、masks | 所有已知信息保留；无历史依赖；本地索引无跨样本误连 |
| A-05 | A-04 | 约定验收与模块 README | V-01/V-03/V-05/V-06/V-08 的样例侧与编码第 9 节通过；声明真实提供方未验证 |

A-01 需一套极小完整 fixture 目录；此时只实现 AI 端读取/校验，不提前实现 C# net 包。不新增 PublicKnowledge/history tracker、事件流、神经网络、奖励函数、搜索或直接 core 接入。资源超限报错不截断；每个输出列的 shape/dtype/掩码须可查。

当前验收入口：从根目录执行 `python ai-the-spire/tests/run_checks.py`，保存具体场景及结果；本轮文档修改未执行该入口。输出最小可检查样例与编码规模/耗时，不能将耗时报告当已满足尚未批准的预算。

## 3. 第二批：给接口实现者的任务

负责 `net-the-spire/`、客户端和必要 solution 注册；规则补缺单独提交具体请求，不在适配器内复写卡牌效果。

| 任务 | 依赖 | 实现内容 | 完成判据 |
| --- | --- | --- | --- |
| N-01 | P-01 约定资产与 Python 参考检查固定；不依赖 A-01 全部完成 | 由同一规范生成/校验 C# contracts、PublicCatalog、能力、严格 codec，完成 C-01 双端要求 | C#/Python 规范字节/摘要/值及正反例一致；拒绝非法精度/类型，不独立手写协议 |
| N-02 | N-01、所选规则开发场景的来源清单 | 当前公开源、SnapshotProjector 和逐机制覆盖表 | 不透传隐藏 DrawPile；位置/变量更新有可信来源和验证记录，V-02/V-03/V-15；格式见约定资产第5节 |
| N-03 | N-02 | 句柄/实例绑定、SessionCoordinator、请求账本 | V-04/V-05/V-07/V-09，过期不推进，重发一次执行，unknown 停止 |
| N-04 | N-03 | stdio Host、Python client 与完整公开快照记录器 | stdout 纯协议；帧上限/断开可分类；按声明能力重放；离线轨迹不依赖活跃请求账本 |
| N-05 | N-04 | 来源/覆盖/充分性表闭合与集成验收 | V-01 到 V-10 及 V-15 适用项有真实模拟验证记录；缺失公开约束阻止相应训练配置 |

core 公开事实缺口不要求 N-02 凭隐藏顺序猜测。将“哪个机制、当前应提供什么、现有哪里缺失、怎么验证”写入执行工单，并关联具体阻塞；不受影响的工作可以继续。

若修改 .NET 项目注册，执行根目录 `dotnet build AutoTheSpire.sln`；若同时改规则/DSL/注册，按 AGENTS 执行规则检查和内容加载。当前net检查入口为 `dotnet run --project net-the-spire/Net.TheSpire.Tests`，真实stdio客户端入口为 `python net-the-spire/client/test_client.py`。本轮未执行；检查数和覆盖以执行者当前结果为准。

## 4. 第三批：训练与评价流程

| 任务 | 依赖 | 实现内容 | 完成判据 |
| --- | --- | --- | --- |
| L-01 | E1、目标配置批准 | ModelConfig、共享 encoder/scorer 与内部价值头 | [概率约定](ai-the-spire/policy-contract.md)全部不变量、重排/mask 检查；不用任意实例行号 |
| L-02 | L-01 | ExecutorProfile、Collector、事实/奖励/行为分布记录 | 实际 μ 正确，终止/截断/故障分开；所有数据标识可追踪 |
| L-03 | L-02、训练配置批准 | PPO 近期 rollout、联合梯度、checkpoint 与学习恢复 | 小任务更新流程可复现、无旧数据冒充当前策略；无需恢复游戏中途状态 |
| L-04 | L-03、评估与预算批准 | 随机/规则基线、隔离种子、学习与资源评估 | V-11 到 V-14；报告成功或失败、样本与置信区间，不强行晋升 |
| L-05 | L-04 | 模型包、加载校验与新局发布 | 标识错配拒绝；一局不热更新；量化/蒸馏/导出变化按 V-16 重评，CPU 预算达标后才宣称可部署 |

上表L-01至L-05描述真实训练与评价流程；其工程部分按[相关规格](spec.md)拆为L-00和L-01a至L-05a：配置/依赖、共享低成本模型、实际μ采样、PPO学习器、评估及不可变模型包，可在M1后依赖满足时连续实现。D-01至D-04负责独立数据设施，P-02负责测量；不要求完整整局先完成。

TrainingProfile必需目标、偏好和预算不齐时，完成工程与配置模板，并用有明确测试定义的有限小任务验证梯度、mask、终止及恢复；不能替维护者决定STS奖励，也不能据测试宣称STS学习有效。实际STS实验待L-00b决策字段固定后启动；网络规模是否满足部署预算亦待实际测量。常规框架/数值适配选择由执行者记录依赖版本和理由；第一批确定性编码仍不需要训练框架。

## 5. 后续与变更

E3 新增内容或字段要同时更新目录、Manifest、样例、训练分布和模型标识，不只扩大 embedding。E4 逐项核对真实可见性、候选、动作完成信号及资源，没有真实验证记录就保持“模拟后端已验证”。无需一次承诺任意 mod 支持。

交付通过 PR 和 CI 确认，说明实际改动、受影响场景、检查结果和限制。失败提供最小复现；接口变化在同一 PR 更新规格。流程见 [开发约定](../../CONTRIBUTING.md)。

## 6. 待维护者决定的事项

本节定义相应阶段需要明确的输入。已落实的版本、编码和来源约定不重新询问；尚未解决的决定及具体来源缺口在对应 Issue 维护，真实控制范围另行指定时再处理。

| 事项 | 最迟时间 | 阻塞范围 |
| --- | --- | --- |
| 协议/编码版本、Python 标准库布局与浮点容差 | A-01 开始前 | E0；文档草案已经可评审 |
| 模拟开发场景和当前公开事实来源 | E1 前建来源清单，N-02/N-05 补运行结果 | 相应 E1 配置，不阻塞 E0 |
| 目标机器、CPU 延迟/内存/参数预算 | 真实 E2 实验及部署声明前；工程原型维度显式配置并测量 | 真实实验配置、最终网络规模及部署声明；不阻塞小型原型工程 |
| 奖励向量、偏好/权重、时间范围与分布 | 进入 E2 前 | 策略学习，不阻塞公共数据设施 |
| 晋升指标、置信要求和资源阈值 | 进入 E2 前 | 模型发布；不看结果后再临时改验收条件 |
| 真实控制能力和公开字段覆盖 | E4 前 | 真实后端，不阻塞模拟开发 |

以上区分评审决定与编码选择；完成本计划的编写不表示这些选择已批准或任何模块已经实现。
