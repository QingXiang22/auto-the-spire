## 1. 初始实验与学习信号

不把整局胜率预测作为启动条件。先在明确覆盖的战斗/待选牌开发场景上验证“策略能利用反馈改善”，再增加长时程场景。这仍是强化学习；公开状态预测、奖励预测或对比学习仅为可选辅助任务，不能替代动作目标。

2026-10-03准备度：当前D/P交付是采样/存储/审计设施，Runner仍用均匀策略，数据场景仅两个簇且final_eval为空，不是可直接用于模型晋升的训练/评估集。按[相关规格](../spec.md)接通内容Gym、可替换策略和实际数据；模型工程不等待全部内容/整局迁移。

推荐首个可学习基线采用[合法动作屏蔽](https://arxiv.org/abs/2006.14171)与近期策略数据的 [PPO](https://arxiv.org/abs/1707.06347)，理由是先以一套可变候选策略和状态价值头检验端到端流程，控制初始工程复杂度。这是本项目的设计判断，并非论文证明它适合尖塔。初版不实现 SAC 双 Q、搜索或无限旧经验重放；后续比较异策略方法时另建方案及数据要求。

首个奖励候选为战斗终止的 win/loss 指标，默认不加入伤害、金币或生命变化的密集项；它只是待批准的实验方案。事实照常记录。若这个信号过稀，先调初始局面分布和任务时长，或测试单独版本化的辅助目标，不悄悄更改目标。样本量与胜率验收条件依据基线方差决定，不承诺少量数据足够。

## 2. TrainingProfile 与 RewardProfile

实际STS实验的TrainingProfile必须有标识及以下配置，未填写必需项则拒绝启动该实验，不让小模型猜权重和目标。工程验证可使用独立标明的合成小任务Profile；测试奖励不继承为STS目标：

| 配置 | 规则 |
| --- | --- |
| environment_identity、gym_id、Manifest | 完全绑定 net 目录、规则、后端配置、场景及编码字典 |
| scenario_distribution | 明确初始局面来源、范围与采样权重；自建场景仅用于指定实验，不冒充原版开局 |
| reward_profile | 分量 ID、单位、计算规则、时间范围、终止语义、是否能由公开事实计算 |
| preference_profile | 单一策略的目标取舍；首个实现建议固定权重，权重必须由维护者明确填写 |
| discount/timebase | 决策步计数或其他时间单位明确；选牌暂停也可能是一决策，不能和游戏回合混用 |
| algorithm_config | PPO 超参数、采样轮次、批量、种子、更新条件、停止条件与模型结构 |
| split_manifest | 训练/调参/最终种子与场景来源；生成过程、隔离和版本记录 |
| executor_profile | 训练采样与评估部署的行为配置，探索后实际分布需可记录 |
| capacity_profile | worker 数、轨迹/磁盘/内存上限、checkpoint 周期和数据保留规则 |

RewardProfile 可以返回向量 r_t。固定偏好的首版候选计算 u_t=Σ w_k r_t,k；权重、分量尺度和归一化都随配置保存。向量 critic 可预测各分量 V_k，策略用同一偏好组合优势；也可先实现标量 critic，但仍保留原始奖励向量。约束/优先级/偏好条件化是后续替代方案，不把固定加权视为所有需求的解答。

原始事实不是奖励，辅助预测 loss 也不是奖励。奖励改版可对已观察事实重算，但不能给未选动作生成反事实标签；重新利用旧轨迹还须满足算法的行为分布要求。禁止“每个候选的选择概率”等同于 Q 的监督标签。

现有原始EpisodeRecord及审计对奖励字段的拒绝保留为事实层边界。学习工程新增版本化派生训练样本/奖励产物，以原始episode/transition摘要及Reward/Preference/TrainingProfile关联；不直接修改旧事实记录，也不把训练标签加入net观察。数据格式需记录π/μ和实际model_id，不能继续把全部策略标为均匀基线；仍须校验被使用数据的算法适用性。

## 3. 轨迹与数据边界

一条 EpisodeRecord 的头部包含：episode_id、net identity、gym/Manifest、后端及场景来源、采样器种子、model/executor/training profile 标识、开始/结束原因。游戏 seed 可作受控评估元数据，不能作为模型特征；真实后端若玩家不可知，不由隐藏接口提取 seed。

每条 transition 记录：step_index、session/observation_id、完整公开 snapshot 或其可验证内容引用、候选概率 π、实际行为分布 μ/选择与 log μ(a)、request_id、原始公开结果事实、next snapshot、reward_profile ID/分量、termination/truncation 标记。请求结果不明不是完整 transition；先记挂起记录，确认后补齐，不猜下一状态或奖励。未选候选没有真实收益标签。

首版直接持久化完整公开快照；若去重，则按[约定资产第6节](../net-the-spire/contract-artifacts.md#6-暂不放宽的边界)以规范字节摘要和产物根内相对路径引用，episode 保留期间必须可读取并校验。不能用进程级 RequestLedger 指针代替快照。存储实现未验证前禁用引用模式；容量超限停止采样，不丢失仍被数据集引用的内容。

通过 episode_id/step_index/request_id 去重；append-only 记录，修改/奖励重算保存派生版本。训练过程重读这些轨迹属于数据使用，模型在线输入仍只是一份当前快照。目录、样例和模型包可进入版本管理；运行轨迹和 checkpoint 放入配置指定的产物目录，避免将大量二进制写入源码仓库。

共享规则的轨迹不一定可混用：目录/Manifest 不同、观察能力不同、任务分布不同均需显式分组。不同 model_id 可以留作分析或经适用方法训练，首个 PPO 实现仅用当前采样策略的 rollout，不把任意过去数据重新当作新策略数据。

## 4. 终止、截断与故障

| 结束类型 | 数据与训练处理 |
| --- | --- |
| 已确认游戏胜负或任务真终止 | termination=true，终止结果与分量完整；不从不存在的未来状态 bootstrap |
| 固定采样窗口结束，但有有效下一快照 | truncation=true；是否 bootstrap 由任务/折扣语义决定并固定配置 |
| 用户停止、进程丢失、结算异常、结果未知 | infrastructure/interrupted 分类；不能伪装失败奖励或自动应用普通 bootstrap，首版排除不完整转移 |

战斗开发场景结束只对该任务构成终止，不给它赋予整局通关标签。技术故障单独报告率和原因，不能通过排除困难局面来美化胜率；评估需列出尝试局数、有效局数和中断数。

## 5. 训练、恢复与发布

Collector 在单局锁定 rollout 策略版本，取得完整观察后采样，执行一个候选并记录转移。Learner 收集本轮指定策略数据后进行配置轮次的更新；新一轮同步权重，候选 scorer 与 encoder 可以联合反传。训练时并行的是独立模拟会话；不在同一局并发执行两个动作。

首个PPO训练执行配置直接从masked π采样，使μ=π；温度变换、混入均匀探索和argmax可作为执行/评估配置，但这些记录不进入首版PPO更新。学习器校验采样策略版本与配置，用同一策略定义计算新旧log-prob比率，不能只把比率计算中的旧策略 log-prob 换成任意 logμ，就当作该实现支持异策略数据。若以后训练变换后的分布，需把变换纳入被优化的策略定义并另验收。

首版采用同步采样轮次：一轮各worker使用同一固定策略，达到本轮有界采样条件后汇总、更新，再开下一轮。旧版本未结束局不能悄悄计入下一轮新策略数据；按配置完成该局或在有有效next snapshot时明确截断/关闭，再以新策略开新局。一局不热更新，不为采满数据无限等待异常会话。

Checkpoint 保存权重、优化器、配置、字典、训练 RNG 状态、数据游标和运行来源摘要。首版恢复的是学习进度，不要求恢复正在执行的游戏中途状态；丢失的局明确记录并新开，不把训练恢复偷偷变成 NoSL 部署回退。

Evaluator 用固定的执行配置和保留场景/种子比较随机合法基线、可选明确规则基线和候选模型。对同种子配对报告任务指标、方差/置信区间及资源成本；任务分布变更视为新实验。最终报告集不用于反复选参；训练样本数量、环境决策数、耗时、模型参数及所有失败都记录。

配对单位预先固定为 `(scenario_profile, initial_seed, replicate)`，记录环境 RNG 与执行器 RNG 的不同种子；同一单位运行各策略并计算结果差值，按初始场景/种子的簇报告不确定性。不同策略消费不同随机数不会自动使“按同一初始条件匹配”的比较失效；但同种子不保证正相关或方差下降，必须报告差值的实测方差。配对差值口径参考 [NIST 配对观测分析](https://www.itl.nist.gov/div898/handbook/prc/section3/prc311.htm)。本文的种子配对是实验设计推断，不声称该资料证明尖塔随机流对齐。

同一初始场景/种子的多个 replicate 属于同一个场景簇，不能当作新增独立场景样本；不确定性方法和有效场景样本数在实验前固定。中断的配对不补造结果，单独列出缺失对及原因。

只有后端声明并验证 seed_action_replay=public_trace 时才要求固定动作序列重放；这和跨策略公共随机数是不同能力。首版不重写原版随机流来追求公共随机数，否则会破坏 STS 种子保真。无法控制初始种子的真实后端单独报告任务分布下的非配对结果与中断，不能混入模拟配对置信区间。

模型晋升验收条件需包含目标指标、基础设施故障、动作合法性、观察投影验证和实际机器预算；阈值由维护者在实验前声明。规则基线不进入模型的效果标签。真实部署所需字段有 unavailable 时，只有为该能力配置单独验证的模型才能继续。发布为完整不可变 ModelBundle；真实经验先隔离核对，再按适用训练方法纳入后续版本。

## 6. 实验顺序与失败定位

E0：公开样例编码；E1：模拟接口与随机合法执行端到端流程；E2：短任务和低成本模型/PPO；E3：整局及罕见组合；E4：真实语义核对后部署。这些阶段分别验证结构、环境、学习、长时程和迁移，不互相代替。

工程顺序见[相关规格](../spec.md)：M1之后先交付可验证公开轨迹、有界采样/数据审计和分项性能测量，再实现L-00/L-01a至L-05a的共享低成本模型、采样器、PPO更新、评估及模型包。用有限且可判定的小任务验证训练工程，单独标注测试目标；不需要等待整局迁移，也不把工程通过计为E2学习改善。目标/偏好/预算未知时列出缺字段，并继续独立规则和数据任务。

E2 前先完成 V-15 的公开事实覆盖与区分审计。E2 无改善时复核该验证记录，再检查候选引用、mask、有效梯度、奖励终止语义、训练/评估分布，随后比较表示容量与探索。用公开输入分离单张牌、目标、资源和已知位置的可区分场景；不得借隐藏状态作部署输入。辅助状态预测只预测后续公开信息，随机结果使用适合的分布目标或不做确定标签，不教模型还原不可知 RNG。

实验预算耗尽仍未显示改善，记录失败和适用范围，不晋升模型。资源超标先测瓶颈，再比较维度、共享投影、量化或局部注意力；不得用截断候选或丢公开信息来满足延迟。

## 7. 历史暂缓试验：公开后果预训练

2026-10-04的[D4任务包](../public-transition-learning-v1.md)补充当前架构决定及固定任务：复用本模型编码器/候选表示，增加仅训练用的公开number/boolean后果预测头；先预训练再作共同终局目标下的scratch/pretrained策略对照，不在本轮联合预测与PPO损失。训练头不进入策略部署包，所有更新仍刷新模型标识。D1默认奖励Profile保留，D4-C单独terminal-only目标；不得把纯自监督表示称为获胜策略。新mod本轮按独立固定Gym从头建立字典/训练，不承诺跨内容零样本迁移；预测目标范围和数据验收条件见任务包。

## 8. 环境优先验收条件（2026-10-04）

用户最新决定先完成[ENV完整单人环境与源规则差异测试](../environment-completion-and-differential-v1.md)，D3/D4正式实验暂缓；第7节仅保留原架构决定供未来评审。完整环境尚未完整实现/未验收不跑新增训练头或学习实验。既有AI只做工程回归与完整公开约定必要兼容；环境标识/分布变化后重新固定数据/目标/预算，不自动沿用旧实验seed或奖励。开发场景能验证训练代码，不抵完整游戏策略可靠性验收。
