# 游戏运行态模型

本文件约定 `core-the-spire` 的运行期数据归属。`base-spire` 与其他 mod 使用同一套规则注册、状态访问和观察接口；原版内容只是其中一个规则包。账号解锁等元进度不属于本模型。

## 1. 分层与生命周期

| 层 | 生命周期 | 内容 |
| --- | --- | --- |
| 规则定义 | 会话启动前组合，整局固定 | 卡牌、敌人、Power、地图生成器、全局配置、效果 DSL、hook 和扩展项声明。 |
| 整局状态 | 一局开始时创建，终局结束 | 角色长期资源、生成后的地图与路线进度、房间栈、整局变量、待处理选择。 |
| 战斗状态 | 每次进入战斗时创建，离开时销毁 | 玩家与怪物实体、战斗牌堆、能量、格挡、Power、敌人行动记忆、战斗变量、结算队列。 |
| 会话随机流 | 跟随整局或独立战斗会话 | 命名随机流及推进位置；从开局重放时用种子和动作序列重建。 |
| 外部观察 | 每次请求时投影 | 可见状态、合法动作、敌人意图与预测伤害；不参与规则结算。 |

这是逻辑上的归属，无须立刻拆成一一对应的 C# 类。现有 `RunState` 承载整局状态，`GameState` 实际只承载一次战斗；调整类名时也应保留这些语义。玩家长期资源、地图、怪物可以作为三个理解入口，但怪物实例属于战斗，并非与整局玩家和地图同级的生命周期。

## 2. 权威数据归属

| 归属 | 必须保存的事实 | 派生或定义数据 |
| --- | --- | --- |
| 整局玩家 | 角色 ID、当前/最大生命、金币、稳定卡牌实例组成的局外牌组、遗物、药水槽及容量、跨房间修饰、玩家扩展变量。 | 卡牌描述、可用动作。 |
| 整局地图 | 已生成的有向图、节点 ID/层数/类型/后继、当前位置、已访问节点、房间揭示结果、房间栈。 | 地图生成规则、从当前位置推导的可达节点。 |
| 整局共享 | 当前幕与阶段、遭遇/事件池进度、概率累积器、奖励和选择、整局扩展变量。 | UI 文案。 |
| 战斗玩家 | 实体生命、格挡、Power 及触发记忆、能量、有序的抽牌/手牌/弃牌/消耗/出牌区、战斗临时修改、战斗扩展变量。 | 局外牌组和金币。 |
| 战斗怪物 | 每个实例的 ID、生命、格挡、Power、已选下一行动、行动位置和必要的历史记忆、实体扩展变量。 | 显示用的意图伤害。 |
| 战斗调度器 | 回合/阵营阶段、当前行动者、待结算效果与触发队列、待回答选择及恢复上下文、战斗共享扩展变量。 | 仅用于日志的完整事件历史。 |

如果规则依赖历史，应保存可在结算时直接读取的最小摘要。例如，`cardExhaustedThisTurn()` 使用本回合最近一次玩家卡牌消耗的回合号；事件日志仍供观察和排错，不参与逐次扫描。

Power 至少有层数，并可能需要施加者、跳过首次触发等实例信息，不能只存 ID 列表。战斗牌区保存卡牌实例而非内容 ID 列表。地图生成器属于规则定义，生成后的图和进度属于整局状态。

打牌恢复上下文由嵌套 `CardPlayFrame` 保存卡牌身份、目标、X 值、结果去向和自动/手动来源；现有效果栈保存每次执行及完成放置的后续阶段。父帧在自动打牌或选牌暂停期间保留，子帧完成后恢复父上下文。批次自动打出的牌先进入出牌堆，再逐张创建帧；被预留但尚未开始的牌不能被普通抽牌取走。帧和队列都属于战斗调度器，不属于局外卡组。

## 3. 跨作用域规则

1. 非战斗时整局玩家生命是权威值。进入战斗时复制给战斗玩家实体；战斗期间该实体生命是权威值；战斗完成时通过明确的提交写回整局。战斗进行中不能分别修改两份生命并假定它们自动同步。`CompleteCombat` 负责提交，`RunObservation` 在战斗中读取战斗实体的权威生命。
2. 进入战斗时，局外牌组产生保留实例身份的战斗牌堆。抽牌、弃牌、消耗和临时生成牌默认只影响本场战斗。永久升级、移除、变形或获得卡牌须走整局写入路径；当前尚未统一这些回写规则。
3. 药水、金币、遗物和路线进度归整局；战斗可通过受控命令改变它们。格挡、能量、战斗 Power、怪物实例和战斗变量随战斗结束销毁，除非具体规则声明整局效果。
4. 敌人已选行动是战斗权威值。意图种类与显示伤害从行动和当前修正投影；实际结算仍执行行动定义。隐藏牌序、未揭示地图信息和未来随机值不得泄露到训练观察。
5. “全局变量”必须注明作用域。整局共享变量属于一局，不是进程级单例；战斗共享变量属于一场战斗。实体或卡牌实例变量须另行明确所有者与销毁时点。

## 4. mod 变量的首个实现

`RunState` 与 `GameState` 分别持有独立的整数存储域，以 mod ID、作用域和变量名识别声明。同名变量可以同时存在于整局和战斗作用域。整局事件处理器与整局 hook 可以读写整局域；战斗扩展与战斗 hook 可以读写战斗域，并在有整局所有者时显式访问整局域。独立战斗没有整局域，访问会抛错。新开一局或一场战斗都会按已编译的默认值初始化各自存储域；变量不进入训练观察。

扩展代码只能通过 core 给它的上下文访问自己 mod 命名空间内的变量。规则包用 `state` DSL 声明变量的整数类型、默认值和整局/战斗作用域，编译后注册到固定的 `GameDefinition`；重复声明、无效类型与作用域在加载时失败。`GetInt`/`SetInt` 与 `GetRunInt`/`SetRunInt` 只接受当前作用域已声明的变量，未声明或跨作用域访问报错。未来还需加入可见性、版本/序列化规则及其他确有需要的类型；效果 DSL 对变量的引用和写入也尚未实现。

## 5. 随机数与复现

随机流由会话服务持有。相同规则集版本、种子、外部动作和随机调用顺序，从开局重放应得到相同结果；无需把每次抽数写入运行态。仅保存种子和中途运行态不能直接恢复各流的推进位置。中途快照或分叉需要保存等价的流进度，或从开局重放。

## 6. 实现状态与下一道验收

| 约定 | 当前对应 | 后续缺口 |
| --- | --- | --- |
| 整局玩家与地图 | `RunState` 保存资源、牌组、地图和房间栈；战斗中整局观察读取战斗权威生命。 | 显式分出玩家/世界子对象。 |
| 战斗参与者与调度 | `GameState`、`PlayerCombatState`、`EnemyCombatState`、`EntityState`。 | 实体/卡牌实例级 mod 状态。 |
| 扩展变量生命周期 | `state` DSL 编译为整局/战斗整数声明；`ScopedIntState` 按默认值初始化，扩展上下文校验已声明变量。 | 可见性、保存格式、其他类型及效果 DSL 的变量操作。 |
| 外部观察 | `RunObservation`、`CombatObservation`；意图伤害从规则计算。 | 对照真实游戏校准展示和隐藏信息。 |

`ModVariablesKeepRunAndCombatLifetimesSeparate` 验证了一个跨事件与战斗的 mod 闭环：事件写整局变量，战斗读取并更新它；独立战斗和新开整局不会继承已有变量，同名变量在不同 mod 命名空间隔离。
