# 文档维护

文档规则以 [CONTRIBUTING](../CONTRIBUTING.md)为准，入口为 [docs/README](README.md)。用户本轮简化文档及清理临时材料的要求，替代旧的每包交接、records 留档和证据恢复约定。

- 只为当前读者维护用法、接口、行为规格及重要设计决定。[任务入口](roadmap.md)连接 GitHub 总任务；状态、优先级、依赖及认领只在 Issue 维护，变更经过与结果放 PR／CI。
- 修改现有权威页面，避免重复规范。新增页须说明具体读者任务；沿用教程／操作／参考／解释分类。
- 删除过时页面时迁移仍有效的行为要求，修复当前引用；历史原文通过 Git 查询。不要新建备份、流水账、审阅目录或压缩证据包。
- 不向正式文档添加本地运行产物链接。示例可使用 `.artifacts/<任务>/` 作为可删除输出目录。
- 命令、参数、字段和示例以当前代码为依据。执行 `python tools/doc-check/check_docs.py` 和 `git diff --check`。

中文表达保持直接、准确；仅在重要行为或接口变化时更新相关规格，无需为普通代码改动额外生成文档。
