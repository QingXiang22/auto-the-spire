# mod-the-spire 开发约定

遵循根 [AGENTS.md](../AGENTS.md)、[开发流程](../CONTRIBUTING.md)和[术语规范](../docs/meta/glossary.md)。本文件补充内容开发边界。

## 规则归属

- 活动 base 包只包含 `.spire` 和必要静态 `.json`，通过通用 Engine 加载执行。操作入口见[base 开发手册](../docs/areas/base/README.md)，组织方式见[base 架构](../docs/understand/base-architecture.md)。旧 C# 编译与玩法代码只作为迁移参考，不作为当前修改入口或生产回退。
- 游戏状态由 Engine 保存；规则包定义和构建代码不保存每局可变状态，不另写玩法调度器或隐藏的 RunState。
- 解析、加载、行为测试、独立参考比较和公开接口运行分别确认。未支持内容明确失败，不能注册空效果或静默省略。

## 复用与扩展

- 开工先查[领域操作参考](../docs/areas/base/reference/operations.md)，复用完整的获得、升级、移动、伤害和房间操作。新建实例、改字段或领取某类奖励的局部操作，不能替代其余生命周期。
- 简单内容组合现有模板和操作；独有规则与私有状态保留在所属 DSL 模块。共享状态、时序和事件调用按领域统一维护，避免复制一套规则或汇集所有玩法的万能工具方法。
- 新共享机制在已有规格写清输入、前置条件、状态归属、事件及随机顺序、公开结果、失败方式和能区分错误行为的测试。组合已有能力的内容引用同一规格，不逐卡建立重复规格或测试。
- 按[监听编写指南](../docs/areas/base/how-to/write-effect-listeners.md)处理通知、修正、持有者、有效实例及销毁；依赖不满足时给出最小源代码案例并协调。
- 新增内容通过所属领域的定义、索引和来源配置接入。Host、net 和 Engine 保持通用，不添加逐卡、逐怪物或逐事件的游戏效果分支。
- 内容来源范围、资格、候选顺序与行为定义分别核对。自动加载不代表已进入原版内容池；源池选到未实现内容时明确失败，不能减少候选范围或用空事件代替。
- 地图保存原始节点类型，实际进入的房间类型单独记录。房间访问生命周期、随机房型选择和具体事件效果分别归属相关领域；公开候选来自同一状态流程。

## 验证与交付

按根约定选择受影响检查，通过工单和 PR 说明实际测试结果、源码依据和未验证范围。正常游戏流程与人工构造的开发场景分别说明；完整环境的完成条件见[环境要求](../docs/specs/environment.md)。
